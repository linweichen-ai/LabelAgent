# Round799：外部视觉专家 API 协议与合成图连通验收

## 结论

当前用户配置的 `openai/gpt-6-astra` API 已完成两层实时验收：纯文字最小请求返回 HTTP 200，耗时 5.63 秒；随后使用项目正式视觉请求封装发送一张程序生成的 640×512 合成图，严格 JSON 返回通过，耗时 3.342 秒。两次均未发送工厂图像、MCAP、标签、路径或人工真值。

## 发现并修复的问题

本地配置页原先把界面供应商别名 `openai` 直接保存到 `LABELAGENT_EXPERT_PROVIDER`，但运行器接受的协议名是 `openai_chat` 或 `openai_responses`。因此密钥和网关本身可用，工作台接入仍可能在网络请求前被协议校验拒绝。

本轮把 OpenAI、Qwen 兼容接口和自定义 OpenAI 兼容接口统一保存为当前已验证的 `openai_chat` 运行协议，同时继续分别保存到各自独立的凭证环境变量。用户级环境中的旧别名也已改为 `openai_chat`，新进程将自动读取正确值。

- 合成图大小：10,335 字节；
- 视觉请求状态：通过；
- 视觉请求延迟：3,341.862 ms；
- 工厂数据上传：否；
- `candidate_only=true`、`human_truth=false`、`approved_for_training=false`；
- 定向测试：15 项通过，另有 3 个子测试通过。

这证明当前 API 的文字、图像、认证和结构化输出链路可用，不代表真实工厂数据上的准确率提高。正式 5090 工作台仍保持外部专家关闭，不会自动上传图像；下一步只能在已获准的开发数据上，以影子模式比较本地、全外部和混合路由，且不得使用 test24。
