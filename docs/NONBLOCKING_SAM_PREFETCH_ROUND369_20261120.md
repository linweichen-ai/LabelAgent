# LabelAgent 第369轮：慢速 SAM3 预热不再拖住页面

## 本轮结论

第368轮让 VLM 和 SAM3 同时工作后，正常情况已经更快；但还存在一个故障边界：如果 VLM 已经识别完类别，而并行的 SAM3 预热因服务繁忙异常变慢，接口会继续等待 SAM3，页面看起来仍像“卡住”。

本轮增加一个明确的非阻塞门限：VLM 完成后，最多再给并行 SAM3 **100 毫秒**收尾。正常完成时继续复用预热结果；超过门限时立即返回已完成的 VLM 发现，并标记 SAM3 仍在后台预热。正式起稿随后可以复用后台结果或由原有请求安全接续，不把一次推测性优化变成新的阻塞点。

## 行为变化

| 场景 | 改动前 | 改动后 |
|---|---|---|
| SAM3 正常先完成 | 复用预热结果 | 保持不变 |
| VLM 已完成、SAM3 异常慢 | 继续等待 SAM3 | 最多再等 100 ms，返回 `registry_warming` |
| VLM 返回 busy | 返回 202，但并行任务可能仍在收尾 | 仍立即返回 202，不等待 SAM3 |
| 人工真值 / 训练集 | 不写入 | 不写入 |

## 验证

新增两条并发时序测试：

1. 人为让 SAM3 阻塞、VLM 立即完成，接口必须在 0.75 秒的严格上限内返回，且清楚报告后台仍在预热；
2. 人为让 VLM 立即返回 `Local VLM is busy`，同时让 SAM3 阻塞，接口仍必须在 0.75 秒内返回 202，不得等待另一条模型链路。

两条测试均确认人工真值、机器候选和训练批准没有写入。全量回归结果为 Python 1187 项通过、190 个子测试通过，Node 156 项通过。

本轮没有为了制造故障而停止正式 SAM3/VLM 服务，避免影响工作台；故障路径使用隔离模拟验证。它改善的是异常情况下的响应性和可恢复性，不宣称正常模型推理本身又缩短了多少。

结构化证据见 `docs/evidence/workbench-stability-20261117/nonblocking-sam-prefetch-round369.json`。
