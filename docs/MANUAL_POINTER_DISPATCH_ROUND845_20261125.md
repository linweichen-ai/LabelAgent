# Round845：手动标注画布单一指针调度与浏览器实测

## 本轮解决的问题

开发版画布此前同时存在基础指针处理、自由线捕获监听和椭圆捕获监听。
这些监听器会按工具状态竞争同一组鼠标事件，且部分监听器调用
`stopImmediatePropagation`。在快速切换工具、拖动或取消操作时，这种结构容易造成
“点击没反应”“拖动被另一工具抢走”或残留拖动状态。

浏览器实测还发现一个独立的初始化顺序错误：手动工具栏首次刷新时会读取
`modelHealthState`，但该变量当时仍处于 JavaScript 暂时性死区，页面脚本会在初始化
中断。静态字符串测试没有覆盖这一浏览器运行时错误。

## 改动

1. 将画布的 `pointerdown / pointermove / pointerup / pointercancel` 收敛到一套统一
   调度器；自由线、椭圆、节点编辑、SAM 框选、矩形和普通多边形不再各自注册竞争
   监听器。
2. 将模型健康状态提前初始化，保证工具栏首次渲染不会读取尚未声明的变量。
3. 新增合成空白图浏览器验收工具
   `tools/browser_manual_pointer_acceptance.py`，真实执行节点拖动、撤销、自由线和椭圆，
   同时监控写请求、控制台错误和页面错误。
4. 新增初始化顺序和单一指针监听的回归检查。

## 安全边界与当前限制

- 验收只使用程序生成的 640×480 空白图，没有读取或外发工厂图片。
- 没有写人工真值、候选、训练批准或 `test24`；没有启动训练或推理。
- 本轮尚未部署到正式工作台，正式工作台仍保持原版本。
- 多部件或带孔洞轮廓仍不允许直接拖动节点，继续使用“补区域 / 橡皮擦”，避免只改
  主轮廓而破坏部件和孔洞结构。
- 34 张困难集人工复核仍为 0/34，本轮只降低后续人工修边的交互风险，不把合成浏览器
  验收冒充分割精度提升或后训练完成。

## 回滚

本轮只涉及前端事件调度、浏览器验收工具、测试和文档。未部署前可直接回退本轮提交；
不会影响正式工作台状态、模型权重或人工数据。
