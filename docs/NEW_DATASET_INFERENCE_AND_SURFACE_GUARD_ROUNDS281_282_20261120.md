# 新数据端到端推理与地面/斜坡互改保护（Round 281–282）

日期：2026-11-20

## 本轮目标

在不切换正式工作台、不写入人工真值和训练集的前提下，用真实新数据
`Capture_20261103/capture.mcap` 验收完整链路：

`新数据加载 → SAM3 → VLM 可见类别复查 → Agent 精修 → 候选叠加显示`。

同时验证八个类别的逐类覆盖反馈、页面错误、请求错误以及候选/人工真值隔离。

## Round 281：链路跑通，但发现整面语义误改

在一次性隔离端口 `127.0.0.1:18791` 加载真实 MCAP：

- 数据身份：`capture.mcap`；
- 当前相机：`/capture/camera_0/image`；
- 152 帧、4 路图像；
- 8/8 类启用；
- 运行前候选、人工真值、参考帧均为 0。

浏览器自动验收通过了数据加载、模型请求、候选显示、后台 Agent 与类别审计。首批候选
约 0.953 秒可见，后台检查约 2.125 秒完成，没有 HTTP、页面或失败请求，也没有人工
真值写请求。但结果为 `person=1, slope=2`：其中一块小 `slope` 正确覆盖集装箱前的
黄色坡板，另一块巨大 `slope` 错误覆盖了整片仓库地面。

读取模型审计轨迹后定位到原因：SAM 原始结果其实是 `floor=1, slope=1, person=1`；
无人工参考的 Agent 把大面积 `floor` 整体改成了 `slope`。模型理由把候选叠加色误当成
物体颜色，声称“黄色坡面”，即使提示已说明叠加色不是物体颜色，仍然发生了整面互改。

这说明 Round 281 证明了平台链路可运行，但不能把视觉结果判为合格。

## Round 282：限制无参考的 floor/slope 整面互改

在 `source/agent/edit_agent.py` 增加可审计保护：

- 没有人工参考时，Agent 不允许把整块 `floor` 自动改成 `slope`，也不允许反向整块互改；
- 原 SAM 候选保持不变，冲突进入人工复核队列；
- 有人工参考时仍允许该语义纠正，不影响参考帧驱动的正式复核；
- 局部边界修正和独立的 floor/slope 候选仍然可用。

新增两项单元测试分别覆盖“无参考时拒绝”和“有参考时保留能力”，并与既有人物、宿主、
其他机器人和实例转地面的保护测试一起通过。

重新使用一个全新的隔离工作区和端口 `127.0.0.1:18792` 运行同一真实帧后：

- 首个 HTTP 推理响应：1.032 秒；
- 候选叠加可见：1.047 秒；
- 后台 Agent 与高风险审计完成：1.750 秒；
- 总浏览器验收：3.453 秒；
- 最终候选：`floor=1, slope=1, person=1`；
- 蓝色 floor 保留仓库平地，橙色 slope 只覆盖中央黄色坡板；
- 8/8 类均有独立状态；
- 0 页面错误、0 HTTP 错误、0 失败请求、0 人工真值写请求；
- `candidate_only=true`、`human_truth=false`、`approved_for_training=false`。
