# 第二百二十八轮：数据/相机切换后的逐类别覆盖作用域修复

日期：2026-11-19

状态：已实现、已完整测试、已部署、已在正式浏览器验收。

## 1. 这轮解决的用户问题

用户需要在新数据集上明确知道：自己选择的每一个类别是否真正进入了推理，当前帧是已经生成掩码、VLM 看见但 SAM 漏分、画面未见，还是尚未形成有效掩码。这个反馈只有在图像、相机、参考帧、类别选择和候选结果属于同一个数据作用域时才可信。

继续检查正式工作台后确认存在一个真实串台窗口：服务器在重新加载文件时已经返回新文件的 `labels / auto_labels / reference_only_labels`，但浏览器的 `loadVideo` 只替换图像、真值、候选和运行记录，没有重载类别；相机切换的紧凑接口则没有返回该相机的自动推理类别与参考帧类别。结果是图像已经切到新文件或新相机，类别勾选与“参考帧已有类别”标记仍可能暂时沿用上一作用域。

这不是模型本身漏检，但会使操作者误以为某个类别已经被当前数据检查，属于必须先修的工作台可信度问题。

## 2. 修复内容

### 2.1 统一类别状态应用

前端新增单一入口 `applyInferenceLabelState(data)`：

- 只接收服务器明确返回的类别数组；
- 自动推理类别必须属于当前总类别；
- 参考帧类别必须属于当前总类别；
- 同时刷新人工类别下拉框、推理类别复选框、类别输入框和逐类别覆盖总览；
- 若旧接口没有返回类别数组，拒绝用不完整数据覆盖当前状态。

### 2.2 文件加载强制刷新类别

`loadVideo(data)` 在恢复帧、读取候选和绘制覆盖状态之前先应用当前文件的类别状态。因此加载另一数据文件后，图像与类别列表会在同一加载事务中切换，不再保留上一文件的勾选。

### 2.3 相机切换返回完整类别作用域

后端的紧凑相机切换回执现在额外返回：

- `labels`：当前数据集允许的全部类别；
- `auto_labels`：当前相机/参考帧实际选择的推理类别；
- `reference_only_labels`：当前相机参考帧已有轮廓的类别。

完整相机切换回执也同步返回这三项。前端进入某个图像窗口的标注模式时先读取并应用它们，再显示当前相机候选。

### 2.4 用户看到的逐类别状态

工作台继续按当前帧显示五种互斥状态：

| 状态 | 含义 | 是否可当真值 |
| --- | --- | --- |
| 已生成 N 个 | 当前帧有通过分割质量门槛的机器候选 | 否，仍需人工确认 |
| VLM 看见，SAM 漏分 | 视觉复查认为可见，但没有合格掩码 | 否，进入补标/复核 |
| 本帧未见 | VLM 给出明确 absent 证据 | 否，只是机器判断 |
| 尚无有效掩码 | 已选但当前没有可展示的有效候选 | 否 |
| 未选 | 本轮没有要求该类别进入检查 | 否 |

黄色提示仍只表示需要补标或复核，不会自动写入人工真值。

## 6. 边界

- 本轮修复的是类别作用域和覆盖反馈可信度，不代表所有8类都已在每帧成功分割；
- “尚无有效掩码”不等于“画面没有该类”，只有带 absent 证据才显示“本帧未见”；
- 正式浏览器验收没有调用 SAM、VLM、Agent 或真值写接口；
- 启动器仅做不含数据图像的主VLM就绪预热；
- 没有新增候选、人工真值、训练批准、SAM3微调、VLM后训练或OSS写入；
- 合成类别只存在于浏览器内存并已恢复，没有写入服务器。
