# 人工确认区域的上下文范围对照

57次真实本地Qwen3-VL-2B NF4请求已完成。保留更大场景后，两个已确认托盘的上下文判断由人员改为托盘，上下文单项正确类别14/19→16/19；但共享的单独轮廓图仍不确定，原两视图一致确认仍11/19。未通过预先固定的严格一致确认增益条件，没有启用重分类或修改工作台。

## 输入与单一改动

使用用户已批准的18处第0帧区域（13托盘、5人员），以及第12帧A1托盘可见部分类别确认，共19处类别观察。它们来自2张已使用图像，不是19个独立物理实例、独立场景或独立像素真值。A1仍只确认类别，不增加物理实例数。

原方案复用之前局部分类的提示词、词表`pallet/person/uncertain`及裁图方法：轮廓外10%留白，生成灰背景上的选中像素、原始裁图和洋红色轮廓图。新方案保持第一张灰背景选中像素逐字节相同，只将后两张场景图扩大为以目标为中心的方形范围：边长至少160像素，或目标框最长边的1.5倍，超出源图时裁到源图边界；不缩放、不补造像素，原部件与孔洞保持。

每处实际请求单独选中像素、原三图上下文、新三图上下文各一次，共57次；单图结果在两种一致判定中复用，不重复调用。两种三图上下文的先后按区域交替，区域顺序在调用前固定。角色、已有类别、人工答案、区域ID、三维标签和轮廓坐标不作为文本发送给模型；标签或ID改动不会改变这19处的五张模型输入图字节。

模型设置固定为2B NF4、温度0、每图预算256、最多192输出token。服务逐请求证明真实CUDA、模型配置摘要、实际输入图片数及视觉token数。两组三图请求的第一张图字节、实际编码token数、提示、schema和解码设置全部一致；改变的是后两张图的裁图范围及对应实际编码。

## A1与当前限制

A1已由用户确认是托盘可见部分，模型的单独像素图为不确定，原上下文和扩大上下文均误判为人员。人工确认保持，不使用模型答案覆盖它。该处原始紧裁图只有33×17像素，扩大上下文为160×160像素；单图实际编码72token，两组三图分别为[72,72,72]和[72,64,64]。这些是服务回读的实际编码量，不能把更大像素范围称为更高的模型视觉编码预算。

共享单图只在7/14托盘与5/5人员上给出正确类别。若保持它作为一致确认的必要条件，即使另一视图假设全部正确，这19处最多也只能一致正确12处；当前实际11处。这是基于已知参考与固定单图答案的条件上界，不是模型新增效果，也不导出任何参考挑选的候选。继续单纯扩大另一幅场景图的可改进空间有限。
