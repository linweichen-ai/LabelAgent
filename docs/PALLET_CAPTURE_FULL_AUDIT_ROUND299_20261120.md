# Round 299：新实采栈板候选全量审计与图像引导复核

日期：2026-11-20  
范围：`Capture_20261103` 四相机已有机器候选，仅只读复核  
结论边界：候选优化证据，不是人工真值，不批准训练，不自动迁移正式标注

## 为什么做

用户指出栈板遮罩存在凹凸、木纹碎洞和锯齿。Round 298 已证明当前正式第 110 帧的 v5 清理结果
能正确叠加，但单帧不能证明新实采数据整体安全。本轮因此覆盖新实采全部已有 pallet 候选，并
专门检查三类风险：大面积栈板、发生孔洞变化的栈板、修改比例最高的远处小栈板。

## 复核工具先修正

原对照图工具会读取原图，但调用清理函数时没有把原图像素传给图像引导分支；因此此前画出的
“优化后”不一定与全量审计实际计算相同。本轮修正为：

1. 对照图与全量审计使用完全相同的 `image_rgb` 图像引导路径；
2. 每一行重新计算的 changed pixels 必须与全量审计逐项一致，否则立即失败；
3. 增加“仅选择发生孔洞填充的候选”；
4. `--per-topic 0` 在报告中明确写为 `full_collection`，不再误写成分层抽样。

定向测试 16/16 通过。随后以 Windows UTF-8 模式执行正式 `tests/` 全套回归，1,078项测试与
186项子测试全部通过。三组对照图全部满足 `audit_replay_match=true`。

补充说明：直接对仓库根目录执行pytest会额外收集SAM3附带的定性演示脚本，该脚本依赖未安装的
matplotlib；这不属于LabelAgent正式测试范围。正式测试第一次未启用UTF-8时另有15项仅因GBK
读取UTF-8中文JSON失败；启用项目要求的UTF-8模式后，同一套正式测试全部通过，没有修改系统
Python或安装额外依赖。

## 44 个风险样本的图像复核

本机生成三张只读三联图，每行依次为原图、当前候选、v5 提案：

- 12 个全部大候选：最大修改 0.8073%，未见明显跨实例粘连；
- 16 个发生孔洞变化的候选：未见明显真实大孔被抹除，结构孔继续保留；
- 16 个修改比例最高候选：最大达到候选面积的 2.5%，多为远处、狭长、低分辨率局部候选。

三张图哈希分别为：

- 大候选：`34b3392dfdaecbf285a14730956aa490f2413e3a17c3f1eb94252482724d70ee`
- 孔洞变化：`cfccdc302fe3c96243a6b25cf26a4d5668d9c8d8162c421ec60d110755e9cf41`
- 最高修改：`be4cb7c6bfcdb92468f54d35da844d56a11254f44917fdb02957717700e1c98c`

视觉结果支持“v5 没有明显破坏已覆盖区域”，但也暴露出另一个更重要的问题：若 SAM 初始候选
只覆盖了远处栈板的一条薄边或一小块，轮廓平滑只能让这块更平整，不能补回漏掉的整只栈板。
因此这些远处局部候选继续显示为需复核，不能因外观变平整而自动晋级。

## 本轮决定

v5 几何清理继续只用于机器候选阶段；不改写人工真值，不自动批准训练，也不因本轮全量门禁
通过而宣称栈板总体识别准确率提升。下一步优先优化远处小栈板的初始候选完整性，包括单实例
ROI 放大、多提示点和相邻帧一致性；几何平滑不再继续放宽。
