# 第二百二十九轮：逐类别覆盖依据与安全补标入口

日期：2026-11-19

状态：已实现、已完整测试、已部署、已在正式浏览器验收。

## 1. 这轮解决的问题

Round228 已保证数据文件、相机和类别选择属于同一个作用域，但逐类别覆盖总览仍只是不可点击的彩色文字。操作者能看到 `slope：VLM 看见，SAM 漏分` 或 `ego：本帧未见`，却看不到这个结论的来源、置信度和理由，也不能从漏分类别直接进入补标。

更重要的是，旧界面把“没有有效掩码”和“明确判断画面未见”放得太近，容易产生错误理解：SAM 没有候选并不等于画面没有该类别；只有当前帧存在明确的 VLM `absent` 证据时，才可以显示“本帧未见”，而且它仍然只是机器判断，不是人工真值。

正式 UI v144 的反向浏览器实测确认：`slope` 和 `ego` 都是普通 `span`，详情区域不存在，补标按钮为0；点击后工作模式、类别和点提示均不变化。模型请求和页面错误均为0，证明问题是界面能力缺失，而不是模型故障。

## 2. 实现内容

### 2.1 三种“没有掩码”状态明确分开

新增统一证据解释函数 `candidateCoverageEvidence(...)`。当前帧没有合格掩码时，工作台按可追溯证据区分：

| 界面状态 | 必须具备的依据 | 用户应如何理解 |
| --- | --- | --- |
| VLM 看见，SAM 漏分 | 当前帧有 `present` 或 `uncertain` 逐类证据 | 可能漏分，需人工确认或补标 |
| 本帧未见 | 当前帧有明确 `absent` 逐类证据 | 只是机器判断，仍可人工检查 |
| 尚未评估 / 无有效掩码 | 没有掩码，也没有可追溯的 present/uncertain/absent 证据 | 不能据此推断画面没有该类 |

已有机器候选继续显示“已生成 N 个”，未勾选的类别继续显示“未选”。所有状态都不等同于人工真值。

### 2.2 每个类别都可以点开看依据

原来的静态文字改为可键盘聚焦的按钮。点击后展开当前帧详情，包括：

- 证据类型；
- VLM 置信度（若有）；
- VLM 给出的理由（若有）；
- SAM 是否留下合格候选；
- 下一步应人工复核、补标还是先选择该类别。

详情只使用当前帧已经存在的运行记录，不会因为“展开查看”再次调用 VLM 或 SAM。

### 2.3 从漏分类别安全进入人工补标

对已选但没有合格掩码的类别，详情提供：

- `补标这个类别`：VLM 看见但 SAM 漏分；
- `仍要人工检查`：VLM 判断 absent，但操作者仍希望检查；
- `人工检查并补标`：尚无可追溯结论。

点击后只做三件事：切到人工模式、选中对应类别、打开 SAM 点提示模式。它不会立即运行 SAM；只有操作者随后在原图目标内部点击，才会提交点提示请求。进入补标前后还会核对数据文件、相机和帧没有变化，避免把旧类别动作带到新画面。

机器候选继续留在候选层，人工草稿与人工真值仍是独立层；本入口不会自动保存真值，也不会自动批准训练数据。

| 检查项 | 修复前 UI 144 | 修复后 UI 145 |
| --- | --- | --- |
| 类别状态 | 不可点击的 `span` | 可点击、可聚焦的类别按钮 |

修复后的状态提示为：“尚未提交：请在 slope 目标内部点一下，点击后才会运行 SAM”。这验证了入口本身不会占用模型，也不会产生隐式分割。
