## 通俗结论

工作台真正提交推理前已有服务端门禁，不会把旧数据集结果直接写进新数据集；但顶部“运行前检查”以前使用的是后台最多每 15 秒更新一次的摘要。刚切换数据集就点击开始时，弹窗可能短暂把上一批数据的参考帧和描述显示成当前数据已经就绪。这不会绕过最终门禁，却会让操作者误以为新数据已经准备好，影响演示和信任感。

现在弹窗同时绑定四项：当前数据路径、相机 topic、当前帧号和本次处理数量。摘要与当前数据作用域不一致时，不再显示旧参考帧，确认按钮禁用；弹窗打开后这四项任一变化，旧检查立即失效并自动关闭。当前真实作用域没有变化时，正常流程仍可通过。

## 修改内容

### 1. 当前工作区作用域校验

运行前检查从主工作台读取当前数据路径和相机，并与轻量状态摘要中的 `path/topic` 精确比较。只有摘要确属当前数据集和当前相机，才读取其参考帧及描述状态。

如果摘要仍属于旧数据：

- 数据项显示“数据集状态正在同步，请稍候重试”；
- 不展示旧参考帧；
- 不展示旧描述；
- 确认按钮保持禁用。

### 2. 弹窗打开时冻结操作范围

打开弹窗时冻结：

- 数据路径；
- 相机 topic；
- 当前帧号；
- 本次处理帧数。

点击“确认开始”或“生成描述并继续”前再次比较。若任一项变化，本次不启动并要求重新点击开始。

### 3. 切换期间自动失效

工作台发布数据/帧状态变化、工作区恢复完成、帧号变化或处理数量变化时，已打开的旧弹窗立即关闭。这样不会出现弹窗内容还是旧帧、底层页面已经切到新帧的混合状态。

### 4. 浏览器缓存版本更新

工作台 UI 版本从 141 升为 142，`guide.js` 资源版本从 113 升为 114，确保已有浏览器不会继续使用旧缓存。
