# Round516：离线人工复核草稿恢复

## 目标

Round515 的81项离线人工签字复核台只在页面内存中保存进度，刷新或关闭页面会丢失尚未完成的人工输入。本轮增加纯离线的“导出草稿 / 导入草稿”，同时保持正式签字和训练授权的原有门禁不变。

## 已实现

- 任意进度均可导出草稿；草稿只携带81项五个身份/哈希绑定字段，以及 `decision`、`reviewer`、`reviewed_at`、`note` 四个人工字段。
- 草稿绑定冻结的 review manifest SHA-256 和空白签字模板 SHA-256；候选集合、帧号或任一源图/规范几何/聚焦图哈希漂移都会整包拒绝。
- 导入要求81项完整覆盖。未知、重复、缺失身份，未知或缺失 JSON 字段，重复 JSON 键，非法决定、错误字段类型、超长人工字段及训练授权字段注入均失败关闭。
- 导入期间禁用页面编辑与导出；只有全量校验成功才按候选身份一次性恢复四个人工字段，失败草稿不会部分覆盖当前进度。
- 草稿导入不会补写人工决定，也不会把人工 `pass` 当成训练授权。正式导出仍要求81项全部具有合法决定、非空复核人和带时区 ISO 时间。
- 不使用 `localStorage` 或 `sessionStorage`，不联网，不加载外部脚本；草稿只通过用户主动下载和选择的本地 JSON 流转。

2. Python 静态门禁，确认草稿入口、重复键检测、导入锁定、正式导出门禁及无浏览器存储/网络调用。
3. 用冻结真实输入重建81项私有复核包并重新统计页面内容与哈希。

- 复核台生成器13项、签字导入门禁24项，合计37项 Python 测试全部通过，采用 warning-as-error。
- Node 直接执行生成页面 JavaScript：39种身份、哈希、字段、权限及长度攻击全部拒绝；同时验证部分草稿往返、乱序恢复、导航、导入期间锁定、失败不改内存和正式导出门禁。
- 冻结真实输入生成81项私有 Round516 复核包：证据图81、待定81、人工签字0。

- 静态检查：外部脚本0、网络调用0、`localStorage` 0、`sessionStorage` 0、草稿导入/导出入口各1。

## 使用方式

1. 人工复核若暂时不能完成，点击“导出草稿”。
2. 下次重新打开同一冻结复核包，点击“导入草稿”；只有两份输入哈希和81项绑定全部一致时才会恢复。
3. 继续完成剩余项目。81项全部完成后，“导出完整 JSON”才会启用。
4. 完整结果仍必须交给 Round513–514 的签字导入门禁；即使全部人工通过，也不会自动进入训练。

## 当前边界

本轮真实执行了生成页面的 JavaScript 逻辑，但没有绕过 `file://` 自动化安全策略做桌面浏览器视觉点击验收。没有替人工填写81项，没有读取 test24，没有训练、部署、上传私有图像或发布候选ID；训练授权和自动批准仍为否。
