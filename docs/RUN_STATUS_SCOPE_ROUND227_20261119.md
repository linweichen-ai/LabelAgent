## 通俗结论

上一轮解决了“运行前检查”引用旧数据的问题。本轮继续检查“任务状态与上次结果”时发现：状态请求发出后，如果当前页或另一个标签页切换了数据，旧请求仍可能晚一点返回。修复前，页面会短暂把旧任务显示成当前数据的“查看上次结果”；随后结果接口被服务端正确拒绝，但前端又把这次安全拒绝误说成“推理状态连接失败”。数据不会被覆盖，但操作体验混乱，而且容易让演示者误以为服务断了。

现在服务端每次状态回执都会明确附带它当前选中的数据文件和相机；浏览器只接受与当前页面完全一致的状态。发现跨窗口切换时，不再读取旧结果、不再伪报连接失败，而是禁用开始按钮并提示重新载入需要操作的数据。恢复到一致作用域后，按钮和正常轮询会自动恢复。

## 修改内容

### 1. 状态接口始终返回当前数据身份

`/api/run/status` 现在无论任务正在运行、空闲还是已有历史结果，都会返回：

- `selected_file`：服务端当前选中的数据文件；
- `selected_topic`：服务端当前选中的相机 topic。

这两个字段表示状态回执属于哪一个工作区，不依赖历史任务自身是否带文件字段。

### 2. 浏览器冻结请求发出时的作用域

状态请求发出时记录页面的数据文件和相机；回执到达后同时检查：

1. 请求期间页面是否切换了数据或相机；
2. 服务端回执的 `selected_file/selected_topic` 是否仍与当前页面一致。

任一不一致就丢弃该回执，不渲染旧任务，也不触发旧结果恢复。

### 3. 区分作用域变化与网络故障

跨窗口切换不再增加“状态读取失败”计数。页面明确显示：

`数据已在其他窗口切换 · 请重新载入`

开始按钮暂时禁用，进度区说明当前页面不会沿用其他窗口的任务状态。状态轮询在不一致期间以 1 秒间隔确认恢复；一旦重新载入当前数据且两端一致，提示自动清除。

### 4. 缓存版本更新

- UI 版本：142 → 143；
- `app.js`：v180 → v181。
