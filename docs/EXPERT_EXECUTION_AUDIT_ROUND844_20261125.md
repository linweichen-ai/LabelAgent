# Round844：外部专家执行包装器接入统一审计

## 解决的问题

Round843 已能把影子路由与执行事实合并成统一回执，但原有
`chat_external_expert_or_local` 只返回“外部成功”或“本地回退”，没有直接
给出是否真正产生网络请求、外部耗时、缓存命中和请求摘要。调用方仍可能
错误地把缓存复用记成一次新上传，或无法区分“并发槽繁忙”和“已发请求后
失败”。

## 本轮改动

- 外部调用成功：记录尝试、真实网络发送、图片外发、耗时和安全元数据；
- 精确缓存命中：记录外部结果复用，但新网络调用和新图片外发均为 0；
- 并发排队超时、熔断或失败缓存：记录本地回退和原因，不虚报网络发送；
- 已发请求后超时、HTTP 错误或无效输出：保留真实发送事实，并记录回退；
- 所有路径继续标记 `sam_result_reused=true`，不会重做已经成功的 SAM3；
- 元数据只含请求 SHA-256、重试次数、模型/用量和缓存状态，不含密钥、
  提示词、图片或原始模型回答。

这些字段可直接传入 Round843 的 `finalize_expert_route_receipt`，从困难分数
到最终路线形成一条完整、机器可验的记录。

## 验证

- 成功、缓存、并发回退、无效输出、503 熔断和缺少凭据等 5 个重点路径
  通过；
- 专家及路由相关测试 199/199 通过；
- 完整 `pytest tests`：2060 项通过、1 项跳过、294 个子测试通过；
- 本轮未执行新的外部 API 请求；未发送工厂数据；未使用 `test24`。
