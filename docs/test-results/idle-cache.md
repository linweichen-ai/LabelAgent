# 单卡闲置显存缓存释放

多图复查后，分配器会保留较大的历史缓存；切回单图时仍占显卡可见余量。本次观察到全卡只剩数百 MiB。新增 local-8gb 配置下的请求完成清理：真实生成函数返回、临时变量退出后，在同一个推理锁内检查 reserved 与 allocated；未使用缓存至少 512 MiB 才调用 empty_cache。活跃模型和张量保留，不终止其他 GPU 程序。共享服务器探测等其他配置默认不清理。

缓存释放机制参见 [PyTorch 官方说明](https://docs.pytorch.org/docs/2.15/generated/torch.cuda.memory.empty_cache.html)。它让未占用的缓存可供其他应用使用；不代表增加 PyTorch 本身的可分配上限，也不保证提速。响应与 health 返回本请求清理的真实前后 allocated/reserved 数值。清理异常单独记录，成功的模型输出保留。

60 次分类试验结束后，先用较短的四图请求进行旧进程 1 次、新进程 2 次真实比较。三份解码文本相同，但新请求的闲置缓存未达到 512 MiB，两次都未执行清理，原定至少一次回收检查失败。全卡余量增加来自进程重新加载，不能算该功能收益。这组未触发结果完整保留。

没有降低阈值。随后逐字节重建历史 Agent 第 76 帧实际使用的四张图、原提示、schema 及 768 输出上限，再执行 2 次新复查。两次均实际触发回收，解码文本与历史原文逐字相同。通过管理器正常切换时额外执行的 1 次合成灰图 SAM3 请求仅作模型轮换，不作标注质量结果。模型配置、NF4、默认 256 和真实编码均核验。

新进程两次实际释放缓存分别为 1274.0、1272.0 MiB；清理后 reserved 为 2142.0、2142.0 MiB，allocated 为 2072.8、2072.8 MiB。两次清理的活跃分配量前后相同，证明未卸载活跃模型。新服务已实际加载此代码，不只是磁盘候选。[完整脱敏结果](idle_cache_results.json)

全卡空闲量和耗时是少量顺序快照，包含进程重新加载、约束预热和其他应用负载，不能据此宣称一般速度提升或彻底解决界面卡顿。本轮共 65 次新 VLM（60 分类＋3 短请求显存对照＋2 真实 Agent 复查输入）、1 次合成 SAM3；258 项完整回归通过，原始数据与标注保护另行校验。
