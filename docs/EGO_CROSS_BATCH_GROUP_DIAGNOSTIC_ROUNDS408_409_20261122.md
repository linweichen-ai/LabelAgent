# Round408–409：ego 跨批次提示诊断与共享编码优化（2026-11-22）

## 结论

本轮用批次 B（20261104）的 003、004 两张 640×512 图像，重新检查了 Round385
在 0920 四相机序列上形成的 camera0 归一化正负点模板。003 含近距离人物遮挡，004
不含人物遮挡，二者都能看到画面底部的叉车自身结构。

固定正负模板在 003 上两组均返回候选，在 004 上两组均被 SAM 的负点冲突门禁拒绝。
这说明模板能跨帧，但不能直接跨批次/跨可见结构复制；004 的座椅与底部车体连通，固定负点
落入了同一可提示区域。拒绝是安全行为，没有错误候选进入工作台。

当前更稳健的正式补救仍是已上线的“18 个底部单点扫描 + 严格几何门禁”：本轮重新只读
运行后，003、004 均返回一个 `wide_bottom_chassis` 候选，助手目视确认候选位于宿主叉车
结构，003 没有吞入近距离人物。该目视结果不是人工真值，不能批准训练或自动部署。

## 共享编码改造

`tools/diagnose_ego_guided_points.py` 已改为一次请求全部提示组：

- 支持新 `/segment_point_groups_batch` 协议，一张图只编码一次；
- 严格校验组数、顺序、原始点和单次编码证明；
- 仅当新接口明确返回 HTTP 404 时回退旧逐组调用；
- 400 负点冲突按组隔离；503、超时和响应畸形不会被隐藏；
- 报告新增 `request_diagnostics`、`client_batch_elapsed_seconds` 和
  `elapsed_seconds_shared_batch`，避免把共享耗时误算为每组独立耗时。

真实运行中，003 和 004 都证明 `image_encoded_once=true`、
`prompt_group_count=2`。客户端批量请求耗时分别为 0.360 秒和 0.313 秒，服务内部总耗时
分别为 0.106 秒和 0.097 秒。003 的两组轮廓与旧逐组运行完全一致；004 的候选数量和
失败语义完全一致，只是新接口返回了更干净的组级错误文字。

## 安全边界

- 所有运行均为本地只读影子诊断；
- `candidate_only=true`、`human_truth=false`、`approved_for_training=false`；
- 工作台 `state.json`、`file_sessions.json`、`last_run.json`、
  `last_run_summary.json` 四个哈希未变化；
- 正式工作台仍为 HTTP 200、`idle`；正式 point-SAM 为
  `labelagent.remote-sam3.v3-point-groups`，模型已加载、无在途请求；
- 含厂内人员的图像与叠加图仅保存在本地未跟踪 artifacts，不上传公开仓库。
