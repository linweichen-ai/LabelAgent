# 第二百三十五轮：SAM 点选与区域编辑的旧窗口结果隔离

日期：2026-11-19

状态：已部署并完成全量回归、正式浏览器反向验收和状态哈希读回

版本：UI 150、`app.js?v=188`

## 通俗结论

上一轮已经挡住旧窗口保存人工真值、驳回候选和锁定参考帧，但还有两种不会立即写服务器、却会直接改变当前画面的交互结果：SAM 点选分割和手工区域编辑。如果同一个文件被重新载入，旧请求回来时文件路径、相机名和帧号可能仍完全相同，仅靠这些字段无法认出它属于旧会话。

现在每次载入数据都有独立代次。点选分割和区域编辑在开始前、计算结束后、浏览器应用结果前都必须再次核对文件、相机、帧和载入代次。只要期间重新载入过文件，即使文件名和相机没有变化，旧结果也会被服务器以 HTTP 409 拒绝，或在页面侧安全丢弃，不会突然贴回当前原图。

## 本轮实现

### 1. 服务端统一核对完整数据作用域

新增统一数据作用域校验，要求请求同时携带：

1. 当前数据文件路径；
2. 当前图像相机；
3. 当前文件载入代次。

`/api/segment_points` 和 `/api/edit_region` 都在读取帧图像前检查一次，在计算完成、准备返回结果前再检查一次。旧代次请求在读取图像或调用 SAM 前直接返回409；请求计算期间发生同文件重载时，完成结果也会返回409。

点提示请求的合并键同时加入文件路径、相机和载入代次，旧会话与新会话不再共享同一次 SAM 请求。

### 2. 浏览器对返回结果做第三层核对

页面提交点选或区域编辑时冻结文件、相机、帧、载入代次和编辑模式。结果回来后同时比较：

- 页面当前作用域是否仍与提交时一致；
- 服务端回执中的路径、相机、帧和代次是否与提交值一致；
- 区域编辑的原轮廓在等待期间是否被修改。

任何一项变化都只提示旧结果已安全丢弃，不修改当前轮廓。

### 3. 候选、人工真值与训练边界不变

本轮只保护交互结果应用，不自动保存为人工真值，不批准训练，也不改变候选与真值隔离规则。正式验收只发送故意过期的反向请求，没有调用生产图像上的 SAM/VLM/Agent。
