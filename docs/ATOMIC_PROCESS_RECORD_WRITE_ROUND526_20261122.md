# Round526：进程记录原子写入与所有权回滚

## 问题

启动脚本原先直接用 `Set-Content` 写 `.repro/processes.json`。若进程在写入中途退出、磁盘瞬时失败或多次启动发生竞争，可能留下半截 JSON；失败回滚也可能误删另一启动动作刚写入的记录。

## 修复

新增独立原子写入器 `tools/write_process_record_atomic.ps1`：

- 只允许写入名为 `.repro/processes.json` 的目标；
- 写入前校验 v2 schema、启动唯一编号、进程身份、PID 和根目录字段；
- 先在同一目录写唯一临时文件；
- 逐字节读回并再次解析身份；
- 新记录使用同文件系统移动安装，已有记录使用文件系统原子替换；
- 正常结束或异常时均清理临时文件和替换备份。

每次启动现在生成 `startup_id`。失败回滚只有在权威记录的 `startup_id` 仍等于本次启动时才删除记录；如果另一启动动作已经安装了不同记录，则保留它，不再无条件删除。

## 实现中发现的问题

第一次测试暴露 Windows/.NET 的 `File.Replace` 不能通过 PowerShell 直接传空备份路径。实现随后改为同目录唯一备份路径，原子替换完成后清理。该失败没有进入正式提交，也没有影响正在运行的工作台。
