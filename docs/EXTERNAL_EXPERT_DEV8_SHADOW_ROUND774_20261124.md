# Round774：外部视觉专家 dev8 影子对比

## 结论先行

外部模型 `openai/gpt-6-astra` 已在 8 张冻结的 640×512 困难开发图上完成真实盲测，8/8 请求成功，未使用 test24，也未上传 MCAP、标签、答案或本地路径。结果只作为机器候选，不写人工真值、不进入训练集、不部署。

本轮最有价值的发现是斜坡：外部专家判断 4 张图含坡，与已有的独立助理目视候选 8/8 一致；本地 8B 机器教师只标出其中 2 张，漏掉了两张画面边缘仅露出一小部分黄色坡板的图。这个结果说明外部专家适合复核“局部露出、边缘出现、遮挡明显”的困难斜坡，但样本仍小，且助理目视候选不是人工真值，不能把 8/8 写成正式准确率。

## 测试边界

- 数据：同一冻结 dev8，共 8 张图，文件哈希与清单逐张一致。
- 外发：仅 8 张 640×512 图像和类别定义；模型没有看到本地 8B 的答案。
- 禁止项：test24 使用数为 0；未上传原始 MCAP、1920 图、标签文件和路径。
- 状态：`candidate_only=true`、`human_truth=false`、`approved_for_training=false`。

## 具体增益与问题

1. **困难斜坡召回更好。** 两个分歧帧的坡只在右下角露出一小块，本地 8B 判为无坡，外部专家和独立目视候选均判为有坡。这与项目“斜坡按几何判断、不能依赖颜色”的目标一致，但还需加入不同颜色、不同材质的坡验证。
2. **托盘、人员、地面和本体较稳定。** 四类与本地 8B 在本轮完全一致，说明外部专家没有为了找坡明显破坏这些基础类别。
3. **车辆与其他机器人仍有标签边界歧义。** 外部专家能描述画面中的叉车、低矮移动平台和独立机器人，但对它们究竟属于 `车辆` 还是 `other_robot` 与本地 8B 有 4 次分歧。下一轮需要加入少量项目专属正反例，而不是继续堆通用文字定义。
4. **新类别发现过于积极。** 模型提出木箱、货架、笔记本、椅子、集装箱等 14 个候选；这证明“发现未登记物体”链路可工作，但其中大量是场景物体，不应自动扩充标签体系。必须增加“跨帧重复、下游价值、人工确认”三道门槛。
5. **延迟仍不适合普通帧。** 21.07 秒中位延迟明显慢于本地模型，因此只适合作为低置信度、冲突、多轮不收敛和复杂遮挡帧的专家通道。

## 下一步规划

### 第一优先级：让专家只处理真正困难帧

增加路由评分：局部边缘坡、类别冲突、低置信度、SAM3 多轮不收敛、`车辆/other_robot` 冲突才调用外部专家；普通帧继续使用本地 Qwen8B。外部失败时回退本地模型，且不重复已经成功的 SAM3 分割。

### 第二优先级：建立小而可靠的人工复核集

从 dev 数据中新选 24–40 张，不使用 test24，覆盖：不同颜色坡、坡在画面边缘、强遮挡、普通地面困难负例、叉车/机器人冲突、托盘孔洞和粘连。人工只确认类别是否存在和关键轮廓，不把机器候选直接当真值。该集合用于决定是否部署专家路由和是否继续后训练。

### 第三优先级：两条模型优化线并行

- **VLM 后训练：** 把人工确认的车辆/机器人冲突、坡道正负例和新类别否决例整理为短 JSON 指令数据，继续做小规模 LoRA；门槛同时检查漏检、误检、延迟和跨序列稳定性。
- **SAM3 分割优化：** 优先做 ROI 裁剪、多提示复用、点云/3D 框生成正负提示点、候选去重和实例拆分；等有足够人工像素真值后再做真正的 SAM3 微调。现阶段不能把机器轮廓自训练称为人工监督微调。

### 第四优先级：形成闭环但保持安全门槛

新类别先进入“候选池”，VLM 给出名称和证据，Agent 做跨帧聚合与去重，人工确认后才进入标签注册表；已确认标签再用于后训练。test24 永久只评测，所有候选默认不部署、不写真值。

## 当前部署决定

本轮外部专家不设为默认模型、不自动进入训练，仅建议下一步以“困难帧影子专家”方式接入。斜坡表现值得继续扩大验证；车辆/机器人类别边界和新类别提议仍需收紧。
