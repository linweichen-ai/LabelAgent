# Round837：19帧专家候选的哈希冻结与外发门禁

## 做了什么

Round835已经证明语义选择级联只需额外运行3次本地Qwen，但报告当时只给出“19帧专家候选”的数量，没有逐帧冻结身份。本轮把完整级联队列写入评估输出：每一帧包含样本ID、源图SHA-256、实际复核JPEG SHA-256和路由来源，不包含本地绝对路径。

最终队列共19帧：17帧来自基线困难路由，2帧来自容器口/门口专项二次复查。所有19帧均固定为`external_upload_authorized=false`和`candidate_only=true`；队列级`external_authorization_granted=false`，因此生成队列不会触发API调用。

## 为什么需要这一步

数量门禁只能限制“最多调用几次”，不能证明实际发送的是哪几张图。哈希队列使后续授权可以精确限定为某一组开发帧，也能在发送前再次验证图片没有被替换。若用户没有明确授权，或任何哈希不匹配，外部执行必须停止。

## 当前结果

- 34帧源集合；
- 本地专项二次复查3帧；
- 外部专家候选19帧；
- 绝对路径字段0；
- 已授权外发0帧；
- 真实图片外发0帧；
- test24使用0帧；
- 定向测试14/14通过。
- 完整项目回归2,036项通过、1项跳过、294个子测试通过。

这一步只提升可控性和可追溯性，不证明19帧都应调用外部模型，更不证明模型质量。11个机器争议仍需独立人工裁决；在此之前队列不能用于计算人工准确率、训练或正式部署。
