# Round 279：极细长栈板复核覆盖与延迟门禁

日期：2026-11-20  
状态：真实只读对照已完成；两项候选加速均未通过完整上线门槛，生产推理保持不变。

## 1. 为什么做这一轮

Round 278 将极细长 `pallet` 候选送入类别盲审，能够拦截货叉、地面缝、胶带、阴影和模糊碎片，但新增 VLM 调用也可能影响单帧等待时间。本轮先量化实际覆盖，再分别检验“两项并行”和“缩短单项输出预算”，不以速度牺牲误检拦截。

所有对照均只读取当前 CVAT Task3 原图和机器候选。没有修改候选、人工真值、参考帧、训练批准、模型权重或工作台状态。

## 2. 覆盖范围

CVAT Task3 共 1,143 个 `pallet` 候选：

- 旧门槛命中 22 个；
- 新门槛命中 31 个；
- 新增 9 个极细长候选，分布在 8/150 帧；
- 单帧最多新增 2 个；
- 受影响帧为 72、92、94、118、131、132、133、147。

逐帧当前审核目标数为：1、2、3、2、1、2、2、1。只有第 94 帧能直接使用既有“三项一批”路径，其余七帧会保留 1～2 个顺序审核目标。

在 `Capture_20261103` 的 4,423 个 `pallet` 候选上，旧门槛和新门槛都命中 7 个，没有新增极细长审核目标。因此 Round 278 不会给该新数据集增加 VLM 延迟。

## 3. 两项并行真实对照

对照工具对完全相同的盲审提示和隔离图像分别执行顺序请求与本地 VLM 原生 batch-2。两种路径使用相邻、但都不会截断输出的 token 上限，以避开精确请求缓存；回执同时要求两边均为真实未缓存推理。

| 帧 | 候选 | 顺序耗时 | batch-2 耗时 | 路由一致 | 结论 |
| ---: | --- | ---: | ---: | --- | --- |
| 92 | 10、14 | 17.412 s | 15.910 s | 2/2 | 快 8.63%，语义一致 |
| 118 | 5、9 | 20.228 s | 15.250 s | 1/2 | 快 24.61%，但候选 5 被 batch 错误保留 |

第 118 帧候选 5 的顺序结果是 `human_review_required`，batch-2 却以 0.98 置信度保留 `pallet`。这会削弱 Round 278 的误检拦截，因此 batch-2 判定为**未通过**，不进入生产。

## 4. 单项短预算真实对照

第 132 帧两个候选分别使用现行 768 token 上限和 384 token 上限顺序推理。四次请求均未命中缓存，均正常 `stop`，协议有效，语义核心和人工复核路由 2/2 一致。

| 路径 | 总耗时 |
| --- | ---: |
| 768 token | 14.846 s |
| 384 token | 14.674 s |

只减少 0.172 秒，即 1.16%。模型在 384 token 之前本来就已经主动结束，缩短上限没有形成有意义的计算节省。因此该方案虽然安全，但收益不足，不改变生产默认值。

## 5. 决策

本轮不部署新的生产代码：

1. batch-2 有真实路由回退，安全门槛失败；
2. 384 token 单项预算语义一致，但提速不足；
3. 当前最稳妥的方案仍是保留顺序盲审和既有 batch-3 保守门槛；
4. 自动合并继续关闭，机器候选继续保持 `human_truth=false`、`approved_for_training=false`。

下一步性能优化不再围绕生成上限，而应减少重复图像编码或把同帧隔离图像预处理复用到顺序请求中；任何改动仍需同时通过路由一致、未缓存实测和新数据覆盖门槛。
