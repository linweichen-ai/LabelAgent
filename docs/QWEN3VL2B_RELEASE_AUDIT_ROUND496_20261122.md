Round375 的 Qwen3-VL-2B LoRA 确实是一份完整、可回读的离线候选，不是只留下了汇总数字：

- 适配器文件为 34,922,600 字节，SHA-256 为
  `ad81bd3929ffb915b07986e783fe2116defe51c45d3ff562d86e5d164f59ad4f`；

- 受检查的结构化配置中没有非空凭证字段。

## 这解决了什么

此前代码仓库保存了训练结论和摘要，但模型文件仍只在本地离线证据目录，缺少一个统一、失败
关闭的发布清单。新增 `tools/audit_qwen3vl_candidate_release.py` 后，任何未来的受控发布都必须先
同时验证：训练完成、权重未漂移、train/dev 未漂移、test24 未回流、机器教师未冒充人工真值、
候选未冒充生产部署，以及受检查 JSON 中没有凭证字段。

机器可读清单：
`artifacts/round496-qwen3vl2b-release-audit-20261122/manifest.json`

现场张量回读：
`artifacts/round496-qwen3vl2b-release-audit-20261122/tensor-audit-fresh.json`

## 当前仍未做的事

本轮没有把权重上传到 GitHub/CNB。原因不是权重无效，而是公开/共享训练权重属于单独的分发
决策；当前清单明确记录 `weights_published=false`、`distribution_approved=false`。代码与哈希
可以同步，模型文件仍保留在受控本地位置，避免在未确定仓库可见性和数据/权重分发范围时扩大
传播。

本轮也没有改变正式 8B VLM、工作台配置、人工真值、训练批准或 GPU 服务。候选仍属于
`offline_machine_teacher_lora`，不是人工准确率结论。
