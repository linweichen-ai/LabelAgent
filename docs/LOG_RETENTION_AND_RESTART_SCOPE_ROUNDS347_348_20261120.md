# Round347–348：日志控量与服务重启后的旧页面保护

日期：2026-11-20
状态：代码、自动化、隔离浏览器与正式工作台部署均已完成

## 1. 本轮解决的问题

本轮先处理两个会直接影响工作台“是否顺畅”的基础问题。

第一，正式工作台日志中长期记录每一次成功的状态轮询和图像请求。页面本身没有故障，但这些正常
访问会不断写盘，`remote_workbench.log` 已增长到约 32.8 MiB。在 D 盘只剩几十至数百 MiB 时，
这种无意义增长可能挤占状态保存空间，最终表现为页面卡顿、保存失败或服务无法重启。

第二，工作台服务重启后，活动文件路径和相机可能完全不变，但“本次载入代次”会从头开始。旧页面
过去只能比较路径和相机，因此看不出自己已经过期；真正写入时虽会被服务器拒绝，却会让用户先遇到
一次 409 错误，体验上像是按钮突然失效。

## 2. Round347：日志不再无限增长

### 2.1 日常访问日志降噪

服务端现在不再记录成功的页面轮询、图片读取等常规 2xx 访问，只保留警告和错误。这样不改变业务
流程，也不影响故障定位，但能阻止工作台空闲时仍持续消耗磁盘。

### 2.2 可恢复的日志轮转

正式工作台启动前会检查日志大小：

1. 日志超过 8 MiB 才轮转；
2. 原日志先压缩为 gzip；
3. 压缩后重新读取并核对完整字节和 SHA-256；
4. 只有核验一致后才移除原日志；
5. 最多保留两代压缩日志，便于回溯近期故障。

首次正式执行后，约 32.8 MiB 的原日志压缩为约 0.9 MiB。随后连续发送 100 轮状态读取和摘要读取，
日志由 170 字节保持为 170 字节，新增 0 字节。警告和错误仍会正常记录。

### 2.3 低磁盘时的临时目录

管理器发现 D 盘低于 256 MiB 后，将运行时临时目录固定到：

`C:\Users\seer\AppData\Local\LabelAgent\runtime-temp\workbench-8765`

这避免服务启动和一次性处理继续挤压 D 盘；同时仍保留 2 GiB 的长批处理空间门禁，磁盘不足时不会
为了追求速度而冒险执行长任务。

## 3. Round348：同文件重新载入也能识别旧页面

### 3.1 服务端返回完整作用域

`/api/run/status` 现在同时返回：

- 当前数据文件；
- 当前相机话题；
- 当前文件载入代次 `selected_file_activation_generation`。

### 3.2 页面主动暂停

页面轮询任务状态时会同时核对上述三项。只要另一个窗口重新载入了文件，或服务重启导致载入代次
改变，即便路径和相机完全相同，旧页面也会：

1. 立即暂停推理入口；
2. 按钮显示“数据已切换 · 请点右上‘切换数据’同步”；
3. 只弹出一次“本页已安全暂停”提示；
4. 不沿用新会话的任务结果；
5. 不自动刷新，避免覆盖尚未保存的人工编辑。

用户点右上“切换数据”重新同步后即可继续。
