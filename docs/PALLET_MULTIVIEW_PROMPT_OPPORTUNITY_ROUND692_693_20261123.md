# 密集栈板同帧多视角提示机会复核（Round 692–695）

日期：2026-11-23

## 结论

本轮验证“同一时刻换到其他相机，能否为主相机失败的密集栈板提供额外 LiDAR 提示点”。结果为明确负结果：第五批 8 个失败实例中，非主相机提示机会为 0/8。

所有目标都位于 camera1 视场；camera0、camera2、camera3 对这些目标的专属可见 LiDAR 点均为 0。在本批稀疏 LiDAR 和当前双网格可见性门槛下，没有形成跨视角提示机会。因此本批不下载其他相机图像、不调用 SAM，也不尝试跨相机传播掩码。

该结果仅排除这批目标在当前门槛下的跨视角路线，避免继续浪费下载、GPU 推理和人工复核时间；它不代表多视角方法在其他位置或更密点云下永远无效。

## 方法

新增 `tools/evaluate_pallet_multiview_prompt_opportunities.py`，只做离线提示机会路由：

1. 只处理深度拆分后 `handled_candidate=false` 的实例；
2. 同一中心帧 PCD 只读取一次，四路相机共享同一个有限、非零 XYZ 数组；
3. `project_visible` 返回该共享数组的原始位置，因此不同相机的整数索引可以对应同一个过滤后物理点；
4. 使用人工 3D 框划分实例，落入多个 3D 框的歧义点全部排除；
5. 每路相机同时运行 `(4 px, 0.10 m)` 和 `(8 px, 0.15 m)` 两组可见性参数；
6. 只有非主相机在两组参数下都至少有 3 个专属点，且两组共享的相同索引至少 3 个，才记为 `label_conditioned_cross_view_prompt_opportunity`；
7. 机会只代表“值得按需读取该相机图像并尝试点提示”，不是分割支持、通过、真值或训练许可。

输入绑定重叠报告、两个中心帧标签/PCD 和 5 个标定文件，共 10 个文件；中心帧文件在解析前后各计算一次 SHA-256，任何运行中漂移都会立即失败，运行结束后再逐项回读。两个中心 PCD 各读取一次，8 个目标复用同一共享点轴。
