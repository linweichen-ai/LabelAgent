# LabelAgent 模型资产与运行原理

## 1. 模型分工

SAM3 负责根据文字、点、框和已有轮廓画出像素边界；Qwen3-VL 负责理解类别、场景关系、遗漏和冲突；Agent 负责把修改限制为可校验、可回滚的局部操作。三者共同产生的仍是机器候选，只有人工确认后才能成为真值。

## 2. 运行数据流

```text
图片 / MCAP
  ↓ 绑定数据集、相机和 frame_id
参考帧、项目标签注册表
  ↓
SAM3 产生候选掩膜
  ↓
Qwen3-VL 复查类别、遗漏、冲突和新类别建议
  ↓
Agent 校验并执行允许的局部操作
  ↓
候选叠加回原图，保存输入身份、操作、耗时与失败原因
  ↓
人工接受 / 修改 / 驳回
  ↓ 独立训练授权
可用训练数据
```

## 3. 当前模型状态

| 模型 | 当前用途 | 部署状态 |
|---|---|---|
| SAM3 | 候选分割与交互标注 | 正式路径 |
| Qwen3-VL-8B-Instruct | 普通帧语义复查 | 正式本地 VLM |
| 外部专家 VLM | 低置信度和冲突困难帧 | 默认关闭、受控调用 |
| Qwen3-VL-2B-Instruct | 轻量对照和后训练底座 | 非正式模型 |
| Round375 LoRA | 机器教师数据上的后训练候选 | 已保存、未部署 |

模型加载成功只说明服务可运行，不说明分割质量或泛化已经达标。新模型必须在冻结评测集上同时通过类别、误检、漏检、边界、延迟和稳定性门禁。

## 4. 服务器优先部署

推荐让网页后端、SAM3 和 Qwen3-VL 都运行在 Linux GPU 服务器，Windows 只建立 SSH 回环通道并打开浏览器：

```text
Windows 浏览器 127.0.0.1:18765
        ↓ SSH 回环
Linux LabelAgent 网页后端
        ├─ Linux SAM3
        └─ Linux Qwen3-VL
```

通道断开、模型忙、权重未加载或健康检查失败时，工作台应阻止新任务并保留已有状态，而不是生成空结果。

## 5. 模型资产分支

普通 `release`、`linux` 和 `labelagent` 代码分支都不携带大模型。获授权的维护者从 CNB `model-assets` 分支取得 Git LFS 资产；该分支包含 SAM3、Qwen3-VL-8B、Qwen3-VL-2B、Round375 LoRA、许可证和 `MODEL_MANIFEST.json`。

下载后必须逐文件核对大小和 SHA-256。哈希通过仅代表文件完整，不代表 LoRA 已获准部署。模型资产不得复制到不具备相同访问控制和许可证条件的平台。

## 6. 不进入模型资产的内容

- 工厂图片、原始 MCAP 和 OSS 数据；
- 人工真值、`test24` 和私有审核记录；
- API 密钥、SSH 私钥、账号密码和运行时令牌；
- `work/state.json`、缓存、日志和浏览器会话；
- 未完成独立验收的临时检查点。

这些内容必须按各自的数据与凭证制度管理，不能因为代码和模型已经上传就视为已经备份。
