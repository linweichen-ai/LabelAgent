# 人工确认区域：本地2B与服务器8B同输入对照

本轮新增97次真实推理：本地2B旧功能面板20次、服务器8B共77次；另复用此前2B的57份实际响应。8B在原上下文单项的正确类别为18/19，高于2B的14/19，但原两视图一致确认从11/19降到10/19，损失一处先前已正确确认的托盘。旧功能面板也未全部通过，因此工作台继续使用本地2B，候选及原标注保持。

## 固定输入和比较要求

人工确认区域为两张已使用图像上的19处类别观察（14处托盘类别、5处人员类别），包括A1托盘可见部分。这不是19个独立物理实例、独立场景或独立像素真值。两种模型使用同一57个请求体，包含单独选中像素、原三图上下文、扩大场景三图上下文；19处全部保留，人工答案与角色没有发送模型。

另保留原完整10例功能面板：2处人员、5处助手目视托盘、2处空白、1处疑似反光，每例两个视图。该面板的角色没有升级为独立人工真值，原最低3/5托盘一致确认、空白及疑似反光每个视图均不确定等要求全部保持。旧2B的20份原响应缺少逐请求模型配置和实际视觉编码记录，所以补测原20个请求；20/20类别复现，原响应仍保留。上一轮已有完整元数据的57份2B响应直接复用，没有重跑。

本地20次补测先启动；比较标准在首个8B推理请求之前固定：原紧裁图一致确认严格超过11/19、原11处正确确认不丢失、5处人员保持、任一区域不新增相反类别错误、原10例功能面板全部通过，以及全部请求有效、输入及视觉编码匹配。扩大场景的结果仅作预先指定的次级对照，不能替换主方案。

两种模型均为NF4、每图预算256、温度0、最多192输出token，相同提示、schema及服务源代码。57个请求体摘要完全一致，旧20项提示/图片/schema/解码指纹完全一致；全部77对实际视觉token数量及网格一致。模型配置摘要逐响应核验，154个被评估响应ID各不相同，其中97个为本轮新响应、57个为既有响应复用。

## 运行、回读及局限

双4090本轮通过密码认证重新连接；使用已有8B权重，四个官方分片重新逐字节校验SHA256。仅在空闲的第二张卡启动本轮临时服务，限时900秒、分配器上限35%、预留至少4096MiB，每次请求继续检查余量。模型进程按PID出生时间和完整命令核对后结束，确认显卡占用及新建SSH转发已释放，未停止其他任务。

逐份回读154个响应的类别、真实CUDA后端、物理模型配置、NF4和实际图片编码，并重建两组输入绑定；计数与全部原条件重算一致。工作台状态摘要、原指标和输入记录保持。峰值CUDA已分配量在本次请求中分别约2.31GiB与7.07GiB，属于所测请求的服务记录，不是全卡总显存或通用容量要求。

2B运行在本地笔记本显卡，8B运行在4090，运行环境也不同；虽固定输入、解码和服务代码，仍不能证明变化完全由参数规模导致。这两张图和旧面板均已用于探索，结果不作为独立验收。没有新SAM3调用、候选编辑、权重训练或原三维指标改写，临时服务也没有变成工作台长期部署。

后续需要改善单独轮廓图缺少周围结构、细薄可见部分与邻近人员对应不稳的问题；继续保留原负对照和逐区域非退步要求，不通过降低一致确认标准或只增加模型规模来包装提升。
