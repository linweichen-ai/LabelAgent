# 第二百三十六轮：清空候选与类别配置的旧窗口隔离

日期：2026-11-19

状态：已部署并完成全量回归、正式浏览器反向验收、备份与双远端同步

版本：UI 151、`app.js?v=189`、`inspection.js?v=108`

## 通俗结论

上一轮已经挡住旧窗口返回的 SAM 点选和区域编辑结果，但继续检查后发现两个更直接的入口仍可能被旧标签页误用：一是修改“项目类别 / 自动推理类别”，二是清空某一帧已经保存的机器候选。旧页面即使画面看起来没变，也可能属于同一文件被重新载入之前的会话，或者它看到的类别、候选已经被另一窗口更新。

现在这两类操作都不能只凭“文件名、相机和帧号”执行。类别修改必须同时证明文件载入代次和当前类别状态哈希没有变化；清空候选必须同时证明文件载入代次、候选文件哈希和 Agent 过程记录哈希都与页面看到的一致。任何一项已经变化，服务端都返回 HTTP 409，不修改当前数据。

## 本轮风险审计

### 1. 找到并修复的真实风险

- `/api/labels` 原先没有绑定当前数据文件、相机、载入代次和类别版本；旧窗口可能覆盖新窗口刚改好的类别。
- `/api/auto_labels` 同样缺少数据与类别版本绑定；旧窗口可能覆盖新的自动推理类别选择。
- `/api/auto_result/<frame>` 原先只按相机和帧号清空结果；旧窗口可能删除另一窗口刚生成或更新的候选。

### 2. 审计后保持不变的链路

- 参考场景描述生成已经在开始时冻结视频身份、配置、标签、人工真值和签名，并在落盘前再次检查，因此没有为它重复增加一套无意义的门禁。
- 专项复核决定已经绑定复核包清单、来源帧哈希、斜坡几何哈希和助手建议哈希，并且不会自动写真值或训练集，因此本轮不改动其协议。

## 本轮实现

### 1. 类别修改改为“当前数据 + 当前版本”原子写入

服务端为项目类别、自动推理类别和参考帧类别生成统一 `label_state_sha256`。页面保存类别前冻结：

1. 当前数据文件路径；
2. 当前图像相机；
3. 当前文件载入代次；
4. 当前类别状态哈希。

服务端写入前逐项核对，写入后回传新的类别状态与哈希。浏览器只有在返回作用域仍与提交时完全一致时才应用新状态；等待期间重新载入文件或切换工作区，旧回执不会覆盖新页面。

### 2. 清空机器候选改为内容强绑定

每帧检查结果现在提供 `clear_auto_result_binding`，包含：

- 数据路径、相机、帧号和文件载入代次；
- 当前候选产物的 SHA-256；
- 当前 Agent 运行记录的 SHA-256。

页面提交清空操作时冻结这组绑定。服务端删除前重新计算两个哈希；候选或过程记录只要被另一窗口改变，就以 HTTP 409 拒绝。成功后页面不再自行假设“已经删空”，而是读取服务端最新紧凑状态再更新画面。

### 3. 兼容与边界

自动推理类别接口继续保留旧的 `labels` 返回字段，同时新增语义明确的 `project_labels`、`auto_labels` 和 `reference_only_labels`，避免旧调用方突然失效。所有新保护只约束写操作，不增加图像推理等待，也不自动保存人工真值或批准训练。
