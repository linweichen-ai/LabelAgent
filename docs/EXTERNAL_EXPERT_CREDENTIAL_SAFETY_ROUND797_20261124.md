# Round 797：外部专家凭据传输与错误脱敏加固

## 事件与影响范围

为了验证外部专家可以从 Linux 服务器调用，本轮尝试通过加密 SSH 标准输入临时传递 Windows 用户环境变量中的 API Key。PowerShell 管道附带了回车字符，远端 Python 在构造 HTTP 认证头时拒绝该值。底层异常默认把无效认证头表示写入执行日志，造成凭据内容出现在本次受控执行日志中。

该 Key 必须按已经暴露处理并在网关后台撤销、重新生成。新 Key 不得粘贴到对话、命令参数、仓库或文档，应继续通过本机安全配置入口写入用户环境变量。

只读核对确认：

- Linux 服务器没有生成专家密钥文件；
- 密钥没有写入仓库、正式工作台状态或运行配置；
- 正式工作台保持 `idle`；
- `state.json` SHA-256 仍为 `7043442106bffcde99b0fd8a9ce7cc7f459cb94ab9f77a323291778b57d7fb51`；
- 没有上传工厂图片、MCAP、标签或 `test24` 内容；
- 失败发生在 HTTP 请求发送前。

## 代码加固

外部专家凭据现在在生成任意 provider 请求前统一验证：

- 空值拒绝；
- 首尾空白拒绝；
- 回车、换行、制表符、DEL 和其他控制字符拒绝；
- 错误消息不包含凭据值；
- 合成图 smoke 即使使用注入的测试调用器，也先执行同一凭据验证；
- 验证失败时网络调用次数必须为 0。

该规则同时覆盖 OpenAI Chat、OpenAI Responses、Anthropic Messages 和 Gemini Generate Content 四种外部协议。

## 验证

- `tests/test_expert_vlm_smoke.py`：5/5 通过；
- `tests/test_agent.py`：298 项测试与 87 项子测试通过；
- 项目正式 `tests/` 回归：1906 项通过、1 项跳过、286 个子测试通过；
- 新增回归明确检查：畸形凭据不触发网络，异常文本不包含测试密钥。

完整回归出现两条既有 Windows 子进程输出编码警告，来自原子进程记录测试读取非 UTF-8 子进程文本；没有测试失败，也不涉及本轮凭据值。该警告保持如实记录，不作为凭据安全门的通过依据。

## 后续恢复门槛

1. 在外部 API 网关撤销旧 Key 并生成新 Key；
2. 使用本机安全配置窗口保存新 Key，不在对话中发送；
3. 先在 Windows 用合成图复测；
4. 再使用无换行的安全传输方式做 Linux 临时合成图复测；
5. 两端均通过后，才允许准备默认关闭的服务器影子路由；
6. 真实工厂图片仍需开发集外发授权与严格三臂评测门禁。

在第 1 步完成前，不再使用原 Key 发起任何外部请求。
