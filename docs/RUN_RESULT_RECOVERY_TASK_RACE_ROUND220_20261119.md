# 查看旧结果与新任务并发隔离：Round 220

## 一句话结论

点击“查看上次结果”后，如果结果读取期间另一标签页已经启动更新任务，工作台现在会优先保持新任务状态和用户当前页面；旧候选继续留在原帧，不再抢帧、切换工作模式、修改候选计数或把旧任务误标为已处理。

## 问题来源

Round 219 已解决“任务完成回执覆盖用户后来切换的新数据作用域”。继续审计手动“查看上次结果”流程时发现，它在发出结果读取请求后没有冻结：

- 请求恢复的任务号；
- 当前数据文件和相机；
- 用户导航代次；
- 人工/自动工作模式；
- 读取期间是否出现了更新任务。

因此，多标签页同时操作时，旧结果读取可能与新任务状态交叉。

## 修复前正式浏览器复现

生产 v175 使用全新 Edge 上下文，结果读取由浏览器提供延迟合成回执，不调用模型、不写真值：

1. 正式 SFL camera 1 第 74 帧处于人工模式；
2. 点击恢复旧任务 `round220-old`；
3. 暂停旧结果响应；
4. 模拟另一标签页启动 `round220-new`，页面状态变为 running；
5. 放行旧任务结果，旧结果指向第 10 帧。

修复前结果：

| 检查项 | 修复前 |
|---|---|
| 页面显示的新任务 | `round220-new / running` |
| 当前帧 | **74 被旧结果改成 10** |
| 当前工作模式 | **人工被切成自动** |
| 旧任务是否标记已处理 | **是** |
| 旧任务是否延后 | 否 |
| 提示 | “已恢复 1 帧结果，请继续人工复核” |
| 模型请求 / 真值写请求 | 0 / 0 |
| 页面异常 / 控制台错误 | 0 / 0 |

页面顶部同时显示“新任务正在运行”和“旧任务第 10 帧结果”，操作语义互相冲突。

## 修复方式

### 1. 恢复请求冻结完整上下文

结果读取开始时记录任务号、数据路径、相机、导航代次和工作模式。回执必须同时满足任务号、原文件和原相机精确匹配。

### 2. 更新任务优先

读取期间只要出现不同任务，且其状态为 running、stopping 或已有更新结果，旧恢复立即延后：

- 不打开旧候选帧；
- 不改变人工/自动模式；
- 不改候选计数；
- 不把旧任务标记为已处理；
- 明确提示旧候选仍保留在原帧。

### 3. 用户最后一次操作优先

即使没有新任务，只要读取期间用户切换数据、相机、帧或工作模式，旧回执也不再更新当前页面。候选计数更新移动到候选帧真正打开之后，避免尚未成功恢复就提前污染当前显示。
