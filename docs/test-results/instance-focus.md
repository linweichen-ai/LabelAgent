# 候选局部图像的类别诊断

此前完整场景复核没有发现两个注入的类别错误，单独收紧操作 schema 也没有恢复它们。本轮测试候选局部图像能否提供更明确的类别证据，不直接改工作台候选。

## 输入与冻结要求

第 76、151 帧均按实际掩膜面积选最大候选，不使用类别或分数选择。选中的是前景人员。保留原像素，在掩膜框周围增加 10% 留白，分别提供灰背景上的选中像素、未着色原始裁图和无类别文字的洋红色轮廓。类别或 ID 改动不改变这些图片字节；孔洞、多个部分及图像边缘保留。

控制面板继续使用之前全部五个目视托盘、两个空白和一个疑似反光样例，24 份既有 JPEG 逐字节复用。两个人员加八个对照共十项，各执行单图和三图上下文请求，总计 20 次真实 2B NF4 请求。每图预算 256、温度 0、输出最多 192 token，分类为 `pallet/person/uncertain`，一致的两视图才形成类别提议。角色、当前类别和对照身份不发送给模型。

采用新的分类任务提示和词表，并增加两个人员样例，因此不是相对旧提示或词表的单因素对照。所有样例仍来自同一采集，助手目视功能样例不作为独立人工真值。

要求在调用前固定：

- 十项全部有效返回；两个人员的两视图均一致判断为人员。
- 五个托盘的任一视图均不得误判成人员，至少三个托盘两视图一致判断为托盘。
- 两个空白和疑似误检的每一视图均须不确定；误判成人员同样失败，不能只检查是否被判为托盘。
- 图片字节、计划、原标注及工作台状态保持不变。

未完成或全部不确定均不能通过。该诊断不会自动执行重分类；后续还需要实际工具执行、修改后复查和独立的参考指标检查，不能把类别提议直接解释为完整 Agent 或像素质量。

203 项完整回归通过，新增裁图像素及孔洞保持、类别无关选取、角色不泄露、空白误判、非空有效性及缓存与执行保护检查。

## 20 次真实局部请求

两个人员的单图、上下文均判断为人员；五个托盘两视图一致接受 2 个、其余 3 个不确定，未达到至少 3 个的要求。一个托盘和疑似反光在上下文视图被叫作人员。灰图单图为不确定、上下文误报托盘；白图两视图均误报托盘。因此总体门槛未通过，没有启用通用重分类。[脱敏分类汇总](instance_focus_diagnosis.json)

这是局部人物识别与完整场景候选对应之间的差异证据，不能据此声称所有类别识别可靠。提示、词表及两项样例均已变化，没有把相对旧实验的变化归因于某个单独因素。

## 隔离的实际执行检查

新增 `run_focused_class_recovery.py`：每项重新调用真实 SAM3 生成候选，参考规范复用之前真实 VLM 的缓存。局部类别提议也复用本轮真实响应；只有当前重新生成的灰背景像素、原始裁图、无类别轮廓三份 JPEG 字节全部相同，且两种视图类别一致时才匹配。当前类别已一致或结果不确定时不产生重分类。

已知类别翻转只改变实验候选的标签，不改变图片字节。匹配到相反类别提议时，由生产 Agent 的原工具执行器应用重分类，并返回 continue；下一轮调用新的完整场景 VLM 复查，保留原有无进展、循环和收敛检查。缓存不匹配则交回原复查，不强制 done。

两帧分别运行原候选和类别翻转，共四项、每项最多三轮。全部结果写在新的隔离目录；即使受控错误恢复成功，来源面板的总体失败仍然保留，不允许据此安装通用滤波器。缓存提议、重新分割和新的复查请求分别计数，不能将缓存读取计作新推理。实际执行结果见下节。
