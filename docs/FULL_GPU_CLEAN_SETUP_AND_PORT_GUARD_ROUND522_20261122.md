# Round522：完整 GPU 干净安装与启动端口门禁

## 目标

在不复用主工作区虚拟环境的 GitHub 干净克隆中，验证完整 CUDA 依赖能否安装，并修复 Windows 上端口占用被误判为可用、进而可能串到旧服务的问题。

## 干净安装实测

以 `6c49a116c515841221f711f45e3dd3742ebc3e6e` 为干净克隆起点，直接运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\setup_windows.ps1
```

实测结果：

- 完整安装成功，总耗时 1009.04 秒（约 16 分 49 秒）；
- CUDA 12.8 PyTorch 下载约 2.9 GB，下载阶段约 849 秒，实测吞吐约 3.0 MB/s；
- 完整虚拟环境占用约 5.08 GiB；
- Python 3.12.14、PyTorch 2.10.0+cu128；
- CUDA 可用，实测设备为 NVIDIA GeForce RTX 5060 Laptop GPU；
- 安装没有下载或伪造 `sam3.pt`，权重缺失时启动按设计失败关闭。

安装脚本现在会在新建完整 CUDA 环境前提示下载量和最终占用；可用空间不足 8 GiB 时在大文件下载前停止。只想快速核对公开浏览器门禁时，仍可使用 Round521 的轻量入口，不需要安装 PyTorch。

## 端口误判修复

旧版探测在 Windows 绑定探针上设置 `SO_REUSEADDR`，可能把已监听的 `127.0.0.1:8765` 错报为可用。现已移除该选项，并把端口要求纳入启动前的强制自检：

- 工作台启动要求 8765 可用；
- 启动本地 SAM3 时同时要求 8766 可用、CUDA 可用且权重存在；
- 任何一项不满足时，先退出，随后不创建 Web 或 SAM3 子进程；
- 普通诊断模式仍可把端口占用作为信息展示，不影响只读检查。

真实占用场景复核：8765 已有独立实例监听时，新启动命令在 3.87 秒内失败并明确报告 `port:8765` 与缺失权重；没有生成进程记录，也没有产生新的受管 Python 服务。已有实例未被停止或修改。
