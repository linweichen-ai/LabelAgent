# 旧结果图片加载与新任务并发回滚：Round 221

## 一句话结论

当旧候选图片已经开始加载、此时另一标签页才启动新任务时，工作台现在会把页面完整恢复到点击“查看上次结果”前的帧、工作模式和候选计数；旧结果不会留下一半完成的页面切换。

## 与 Round 220 的区别

Round 220 处理的是“旧结果摘要还在网络读取时，新任务出现”，可以在打开候选前直接停止。仍有一个更窄窗口：

1. 旧结果摘要已经返回并通过核对；
2. 工作台开始切到旧候选帧并加载图片；
3. 图片加载尚未完成时，另一标签页启动新任务；
4. 工作台在图片加载结束后才发现任务已经变化。

旧任务虽不会再被标记为已处理，但页面可能已被切到旧帧和自动模式。

## 修复前正式 v176 复现

在正式 SFL camera 1 第 74 帧、人工模式点击恢复旧任务 `round221-old`；浏览器只延迟第 10 帧图片读取。图片请求发出后，模拟另一标签页启动 `round221-new / running`，再放行旧图片。

结果：

| 检查项 | v176 结果 |
|---|---|
| 是否识别新任务 | 是 |
| 旧任务是否延后 | 是 |
| 旧任务是否误标已处理 | 否 |
| 页面帧 | **仍停在旧第 10 帧** |
| 工作模式 | **仍为自动模式** |
| 新任务状态 | running |
| 模型请求 / 真值写请求 | 0 / 0 |

说明 Round 220 已保证任务状态安全，但页面导航回滚尚未闭合。

## 修复方式

恢复旧结果前额外记录当前帧。若候选图片打开后才发现更新任务：

1. 只在数据文件和相机仍为原作用域时尝试回到原帧；
2. 复用“最后一次导航生效”机制，若回滚期间用户又做了新导航，则用户操作优先；
3. 原帧恢复成功后，再恢复原人工/自动模式；
4. 旧任务保持延后，不标记已处理。

## v177 验收发现并继续修正

v177 已能恢复第 74 帧和人工模式，但正式浏览器验收发现：加载第 10 帧时按需读取到的候选数 `0` 留在浏览器缓存里，操作前该键不存在。它不是旧回执给出的候选数，也不影响真值，但仍不满足“完整恢复操作前状态”。

因此没有放宽验收，而是在 v178 中记录目标帧候选计数原本是否存在及原值。旧导航被取消或回滚时：

- 原来有值则恢复原值；
- 原来没有该键则删除临时读取值；
- 刷新候选总览。
