# Round822：困难集后训练候选包门禁

## 目的

在不启动训练、不批准训练、也不把机器候选冒充人工真值的前提下，补齐困难集人工复核与后续目标编写之间的可追溯交接。

新增 `tools/build_mixed_hard_posttraining_proposal.py`。它只在以下条件全部满足时生成候选包：

1. 24–40帧困难复核包及文件回执哈希一致；
2. 人工复核记录完整并与该复核包绑定；
3. 复核人和带时区的复核时间存在；
4. 所有必选判断均已完成；
5. 不包含任何 `uncertain` 判断；
6. 复核包明确与 `test24` 无交集。

## 输出边界

输出只是目标编写提案，不是可直接训练的 JSONL：

- `candidate_only=true`；
- `human_truth=false`；
- `approved_for_training=false`；
- `training_authorized=false`；
- `training_dataset_materialized=false`；
- `model_training_started=false`；
- `test24_used=false`；
- `production_deployed=false`。

每一行只保留图像哈希、场景组别和人工声明的语义判断；真正的模型训练目标仍需后续编写、独立复核和单独授权。

## 当前结论

门禁代码已具备，但当前真实34帧复核仍未完成，因此不能生成真实后训练候选包，更不能启动训练。该结果是安全能力补齐，不是后训练效果提升证明。

## 验证

- 新增门禁、复核工作区和既有发布门禁的定向测试：18项通过；
- 使用当前34帧空白复核模板实命令预演：退出码2、输出文件不存在、训练0次；
- 当前独立工作树完整测试：1904项通过、1项跳过；唯一失败是启动互斥测试要求工作树内存在 `.venv`，而本轮使用另一只已验证项目虚拟环境执行测试，失败发生在环境前置检查，不涉及本轮代码路径。
