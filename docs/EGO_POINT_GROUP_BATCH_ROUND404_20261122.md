# Round404：正负提示组共享一次图像编码

## 为什么做

Round402 的 ego 影子评测对同一帧发送 3 次 SAM 点提示。每次请求都使用 1 个组件正点和同一组 3 个地面负点，得到的高质量候选在 15/24 帧上平均 IoU 为 0.922，但逐请求会重复编码同一张图。已有 `/segment_points_batch` 只支持互相独立的单个正点，不能表达这些正负点组合，因此不能直接替换。

## 本轮改变

- 新增 `segment_prompt_groups`：一张图只执行一次 `set_image`，随后独立计算最多 64 组提示；每组仍遵循原有 1～32 个正负点契约。
- 新增本地与远端 `/segment_point_groups_batch` 路径，并让工作流把它路由到专用点提示 SAM 服务。
- 在任何模型工作前验证全部输入；无效坐标、无正点、非法标签或超量输入整批拒绝。
- 某一合法组没有产生轮廓时只记录该组错误，不丢弃同批其它成功结果。
- 没有改变原 `/segment_points` 和 `/segment_points_batch`，所以旧页面和正式调用保持兼容。

## 验证结果

- 新旧语义等价单元测试通过：同一组提示的轮廓、孔洞、分数和警告与逐次 `segment` 完全一致。
- 两组提示时，旧路径编码 2 次，新路径编码 1 次；推广到 Round402 的 3 个组件即从 3 次降为 1 次。这里只证明编码次数下降，不把它冒充真实 GPU 端到端耗时结论。
- 定向测试：11 项通过，另有 4 个输入子用例通过。
- 全量 Python：1275 项通过，另有 223 个子测试通过。
- 网页 Node：167 项通过。
- `git diff --check` 通过。
- 正式 SAM 健康，`model_loaded=true`、`in_flight=0`。正式状态、候选、真值和最近运行文件的 SHA-256 与本轮前一致。
