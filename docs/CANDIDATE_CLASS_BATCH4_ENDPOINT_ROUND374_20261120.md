# LabelAgent 第374轮：四候选批审可行性探针

## 结论

第373轮真实新数据中有4个人员候选需要类别盲审。为了判断能否把当前“3个批审 + 1个顺序审”合并为一次四候选请求，本轮在隔离工作区发送了一个只读 batch-4 影子探针。

结果为**不支持，不采用**：本地VLM批量接口在模型推理开始前返回HTTP 400，明确要求 `requests must contain two or three request objects`。因此本轮没有修改服务上限，也没有把未经验证的四候选批审接入生产。

## 安全边界

- 模型推理没有开始；
- 候选、人工真值、参考帧和训练批准均未修改；
- 正式工作台代码和状态未修改；
- 当前生产继续使用已经通过实测门禁的 batch-3，剩余1～2项继续顺序复核；
- 历史 batch-2 曾错误保留困难负样本，因此不会为了速度回退到该方案。

## 后续方向

后台耗时的主要部分仍是VLM生成，而不是本地图片编码。下一轮优先评估以下不降低语义门槛的方向：

1. 在独立服务中验证第二个VLM推理槽，保持每个候选的原盲审协议；
2. 若显存与稳定性不允许第二槽，则保留 batch-3，只继续优化缓存命中与进度反馈；
3. 任何并行方案必须在历史困难负样本上保持原 `human_review_required` 路由，不能只在本帧四个容易人员样本上通过就上线。
