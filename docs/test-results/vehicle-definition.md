# 局部类别定义对照：托盘接受增加，但空白误报，未采用

仅使用原调参队列中的五个局部对象，包含两个目视托盘功能样例、三个疑似车辆部件，再加灰白两个空白对照。角色由助手目视指定，不是独立人工真值；没有使用完整验证帧。

先冻结图片字节、类别枚举、两套提示、交替顺序和门槛，再完成 28 次本机 2B NF4 真实 CUDA 请求。每个样例分别提供单张隔离前景，以及隔离前景、原始局部上下文、描边上下文三图。温度 0、每图面积 token 预算 256、输出最多 192 token，要求两视图一致才接受或拒绝，否则不确定。

| 项目 | 中性提示 | 明确类别定义 |
| --- | ---: | ---: |
| 两个目视托盘被接受 | 0/2 | 2/2 |
| 两个目视托盘被拒绝 | 2/2 | 0/2 |

定义提示说明托盘是承载平台，部分可见仍可属于托盘；叉车或搬运车的车架、轮子、货叉和手柄属于车辆部件。其他输入相同，未提供带类别文字的示例图片。预设要求同时包括接受两个目视托盘、空白和疑似部件不接受，以及至少两个部件两视图识别为 vehicle，避免把全部回答不确定算作有效改善。

定义提示降低了本组托盘误拒，但白色空图在两视图均被判为托盘；灰图的单视图也误判托盘。疑似部件仍有人员、货物或托盘等冲突判断。完整结构化响应不证明视觉识别可靠，理由中的无依据描述也没有当作正确证据。

两组均未采用，未重分类或删除任何候选。类别枚举新增 vehicle，本轮数字不能与此前不同词表、不同裁图的容量或少样例实验直接拼接比较。没有将这组小样例结果报告为准确率，也没有训练模型权重。
