# Round382：参考帧快速类别发现配对门禁（2026-11-22）

## 结论

本轮没有把 5090 快速 VLM 替换为参考帧的权威类别发现通道。它在 24 张
640×512、跨 3 个编号目录和 4 路相机的配对样本上，中位耗时从 15.140 秒降到
10.149 秒，缩短 32.97%；但只有 17/24 帧的可见类别集合与主路一致，因此未过
“不能用漏类换速度”的上线门槛。

需要特别说明：主路只是当前生产基线，不是人工真值；本轮只能判断快速通道是否
保持现有语义，不能据此宣称任一路识别正确。

## 配对结果

| 项目 | 结果 |
|---|---:|
| 配对图像 | 24 |
| 主路中位耗时 | 15.140 秒 |
| 快路中位耗时 | 10.149 秒 |
| 中位提速 | 32.97% |
| 可见类别完全一致 | 17/24 |
| 开放集候选完全一致 | 24/24 |
| 全部类别 evidence 完全一致 | 13/24 |
| 权威替换门禁 | **拒绝** |

逐类差异中，`pallet`、`person`、`ego`、`cargo_floor` 和 `slope` 为 24/24
一致；但快速通道相对主路漏掉 3 次 `other_robot`、1 次 `floor`，并额外判为
可见 4 次 `车辆`。斜坡在这组样本上没有漂移是积极信号，但不足以抵消机器人和
地面的漏检，也不代表未曝光斜坡数据已经通过。

## 为什么不直接上线

参考帧类别发现会决定后续给 SAM 的类别范围，还会影响 `other_robot` 的语义补救。
快速通道若漏掉 `other_robot`，即使界面更快，也可能让后续补救根本不触发。因此
本轮只保留为实验候选，不修改正式 `server.py`、`workflow.py` 或模型权重。

WorkBuddy 的独立只读审阅同时确认：当前已有 SAM 多提示图像编码复用、按帧/图像/
标签/配置绑定的短时类别缓存、确定性描述以及相邻下一帧独立预取；相邻帧不会互相
继承类别结论或 mask。它建议下一步只对“VLM 可见或不确定、但 SAM 没有候选”的
类别做一次受限同帧补漏。现有页面已经提供人工触发的“补标缺失类别”点提示入口；
自动触发在没有逐类人工真值 A/B 前不能贸然上线。

## 新增的可复现门禁

新增 `tools/compare_visible_discovery_routes.py`：

- 按图像 SHA-256 严格配对主路与快路；
- 检查可见类别、逐类 evidence、开放集候选、一致性告警和开放集完整标志；
- 自动统计 present 漏检和额外检出；
- 输出 `accepted_for_bounded_authoritative_route` 或
  `rejected_for_authoritative_route`；
- 输入不完全配对、重复图像或 schema 不符时失败关闭；
- 不保存候选、不改人工真值、不改训练数据。

24 张原始回执和比较结果位于
`artifacts/round382-reference-discovery-fast-ab/`，核心结论为
`comparison24.json`。结构化轮次记录位于
`docs/evidence/workbench-stability-20261117/reference-discovery-fast-route-round382.json`。
新增和既有逻辑通过 Python 1199 项及 190 个子测试、网页 159 项完整回归。
