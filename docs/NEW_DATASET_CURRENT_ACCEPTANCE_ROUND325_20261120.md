# Round 325：最新版本真实新数据端到端复验

日期：2026-11-20

范围：`Capture_20261103` 单帧、最新工作树、隔离工作区

结论边界：机器候选与助理目视，不是人工真值，不批准训练或部署

## 1. 为什么重跑

Round 281–282 已经在当时版本上跑通过一帧
`SAM3 → VLM → Agent → 原图叠加`，并修复过整片 `floor` 被误改成 `slope` 的问题。
此后工作台又经历数据身份、类别复核、栈板轮廓、结果恢复和浏览器稳定性等多轮改动，因此
本轮验证的是：**当前最新版本是否仍能在真实新数据上完整工作**，而不是重复旧结论。

## 2. 隔离与数据保护

- 使用一次性隔离端口 `127.0.0.1:18795`；
- 只读加载现有 `Capture_20261103` MCAP，不复制约 1.5 GiB 原包；
- 复用只读媒体索引和回放缓存，避免在低磁盘余量下重新展开数据；
- 初始状态为 152 帧、4 路相机、8 个类别、0 候选、0 人工真值；
- 正式工作台始终保持 CVAT Task3，没有切换数据集；
- 正式 `state.json` 前后 SHA-256 均为
  `237844f73ff4495e575c6a3f966260b9385efbdf1edee7d0e5177518470ddfab`。

## 3. 首次运行发现的是验收工具陈旧，不是模型故障

第一次打开最新页面时，模型尚未运行，验收脚本就因仍只接受旧身份文案
“新数据集 / 已加载数据”而停止。最新界面已经把该数据明确标为：

- 类型：`新实采数据`；
- 名称：`Capture_20261103 · 常熟实采 · 四相机`。

因此更新三套浏览器验收工具，使其识别新的专用身份；针对本条端到端验收又进一步要求名称
必须包含 `Capture_20261103`，防止以后退回模糊文案时仍假通过。

工具更新后第一次真实推理完整结束：候选约 18.047 秒可见，后台复核约 45.656 秒完成，得到
`floor=1、slope=1、person=1、ego=1`。验收回执当时仍为失败，唯一原因是页面在长阶段主动
取消了两次超过 8 秒的旧 `/api/run/status` 轮询；服务端对应请求随后均正常返回 200，没有
HTTP 错误、页面错误、模型 busy 或人工真值写入。

验收工具现已把这种 `GET /api/run/status + net::ERR_ABORTED` 单独记录为“预期取消”，其他路径、
其他方法或连接重置仍属于真实失败。新增单元测试覆盖四种正反情形，避免掩盖网络故障。

## 4. 最终复验结果

使用全新隔离状态重新加载同一真实帧，最终回执 `passed=true`：

| 项目 | 结果 |
|---|---:|
| 数据 | 152 帧、4 路相机、8/8 类 |
| 首个推理响应 | 2.610 s |
| 候选在原图可见 | 2.625 s |
| VLM / Agent 后台复核完成 | 3.532 s |
| 浏览器总验收 | 4.953 s |
| 候选 | floor 1、slope 1、person 1、ego 1 |
| VLM / GPT 轨迹 | 1 条，确实参与 |
| 页面错误 / HTTP 错误 / 失败请求 | 0 / 0 / 0 |
| 人工真值写请求 | 0 |
| `candidate_only` | true |
| `human_truth` / `approved_for_training` | false / false |

第二次运行复用了相同模型请求缓存，因此 4.953 秒只能证明**热路径可快速复现**，不能替代首次
45.656 秒冷路径读数，也不能宣称模型本身被加速了十倍。

## 7. 下一步

本轮证明最新版本仍能跑通真实新数据的一帧，但不等于152帧和4路相机已完成泛化验收。
下一步应从不同相机、不同时间各抽一帧做小型跨视角集合，并重点统计：坡板与平地分离、
近远栈板边界、person/机器结构混合候选和 `other_robot` 漏分。所有结果继续保持候选状态，
只有人工确认后才进入后训练数据门禁。
