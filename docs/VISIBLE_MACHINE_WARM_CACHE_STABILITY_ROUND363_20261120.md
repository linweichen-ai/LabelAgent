# LabelAgent 第363轮：车辆补漏热缓存稳定性与等待时间复核

## 目标

第362轮收紧局部机器碎片门禁后，首次运行包含新提示词的 VLM 冷调用。第363轮不再修改算法，直接复跑相同的 Capture 16帧和独立 Task3 10帧，验证：

1. 缓存命中后是否保持逐帧结果一致；
2. 重复查看或复核同一批图像时，等待时间是否明显下降；
3. 缓存是否改变候选、人工门禁或来源边界。

## Capture 16帧结果

与第362轮逐帧对照后，16帧的恢复状态、候选类别和类别盲审路由差异数为0：

- 3帧生成候选；
- 2帧普通车辆候选保留；
- 1帧车辆/机器人意见冲突，继续要求人工复核；
- 13帧无候选；
- 0运行错误。

性能变化：

| 指标 | 首次运行 | 热缓存复跑 | 变化 |
|---|---:|---:|---:|
| 中位耗时 | 5.107秒 | 0.488秒 | 降低90.4% |
| P95耗时 | 5.856秒 | 0.648秒 | 降低88.9% |
| VLM调用 | 29次 | 29次 | 相同 |
| VLM缓存命中 | 19次 | 29次 | 全部命中 |
| 逐帧输出差异 | — | 0 | 完全一致 |

这里的“VLM调用”包括语义定位、机器完整性判断和高风险类别盲审；SAM点分割仍按需运行，因此热缓存不等于整条链路零计算。

## 独立 Task3 10帧结果

第362轮修复后的10帧再次复跑：

- 局部轮子候选仍在第一道语义门禁被拒绝；
- 0候选、0人工复核排队、0错误；
- 中位耗时0.037秒，P95耗时0.178秒；
- 参考来源仍为 `legacy_auto_preannotation`，没有被升级成人工真值；
- 正式状态和参考会话均未修改。

## 结论

现有持久化 VLM 响应缓存对重复帧有效：同一输入与同一提示合同下，结果不漂移，Capture 中位等待缩短约90%。这改善的是重复展示、回看和审核体验，不能代表新图像的首次冷推理也能达到0.5秒。

为了保证新数据集的首次体验，后续仍应继续优化：

1. 在用户停留当前帧时低优先级预取相邻帧，但切帧、启动正式推理或模型繁忙时立即取消；
2. 对候选完整性检查和类别盲审做安全的批量图像编码复用；
3. 将冷启动、热缓存和缓存失效三种耗时分别展示，避免把缓存性能误报为首次推理性能；
4. 继续保持缓存键绑定图像哈希、提示合同、模型和响应模式，禁止跨数据集模糊复用。
