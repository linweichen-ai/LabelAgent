# 密集栈板冲突组联合候选诊断（Round 704–707）

日期：2026-11-23

## 结论

本轮把 Round 700 的跨帧候选与 Round 676 的原始候选放回完整冲突组，重新统一深度拆分并穷举所有可行组合。006 组评估 8 种组合，008 组评估 120 种组合；两组都没有完整通过。

但是诊断把问题进一步缩小：006 组的最佳组合已有 7/8 个成员通过，唯一阻塞是 `obj10`；008 组的最佳组合已有 6/7 个成员通过，唯一阻塞是 `obj75`。所有成员两两分离门在各自最佳组合中都通过。也就是说，继续广泛调整整组没有意义，下一步只需要针对两个硬阻塞目标。

## 公平联合协议

最初预实现曾准备把已经深度裁剪过的旧掩码再次参与拆分，审阅发现这会造成偏乐观，真实运行前已修正。正式 Round 704–707 使用 Round 676 `instances[].mask_path` 的原始掩码，与 Round 700 的原始 temporal SAM 掩码一起重新统一执行：

1. 从冻结中心标签和标定重新投影 3D 框、重建冲突连通分量；
2. Round 700 候选先要求自身定位、全量正点覆盖和全量负点排除均通过；
3. 每个成员保留一个 Round 676 原始 incumbent；没有 temporal 候选的成员只使用 incumbent；
4. 对所有组合统一运行深度拆分，并要求每个成员 `candidate_pass=true`；
5. 要求组件内所有成员对的最终掩码交叠低于 15%；
6. 通过组合优先选择 temporal 成员最多者，再按稳定 ID 排序；本轮不存在通过组合。

工具绑定报告、中心标签、标定、全部原始 incumbent 和 temporal mask，以及自身源码，共 58 个输入；掩码和标定在解析后立即复核，结束时再次全量复核。两次报告逐字节一致，SHA-256 均为 `81e395d36bbb97a9e0e4549d7253352ef9eff8aa157976a566053ced39602fec`。
