# 第二百三十轮：新数据集首屏原子切换与自动打开相机

日期：2026-11-19

状态：已实现、已完整测试、已部署、已在正式浏览器验收。

## 1. 这轮发现的真实问题

Round229 让逐类别覆盖变得可解释、可操作，但继续检查“新数据集第一次加载”后，正式 UI v145 出现了两个可稳定复现的问题：

1. 新数据的类别先被应用，候选和逐帧计数稍后才替换。类别应用会立即重画总览，因此这个短窗口会把新类别与旧数据的候选数量拼在一起。
2. `openImportedImage()` 只自动打开 `LabelAgent.StillImage`。真实 SFL MCAP 的图像话题是 `LabelAgent.CompressedImage`，因此数据虽然已经加载，当前相机不会自动进入标注窗口。

正式浏览器只在内存中加载一个“3帧、3类、没有候选”的合成新 MCAP 回执。修复前内部 `candidateStore` 已经是空对象，但界面仍显示：

- `44 帧有结果`；
- `当前帧 16 个`；
- `floor：已生成 1 个`；
- 主图像窗口隐藏；
- 标注模式未开启；
- 打开的图像窗口为0。

这证明问题不是模型效果，也不是数据真的带有候选，而是首屏状态切换不原子且相机没有自动打开。

## 2. 修复内容

### 2.1 逐类别状态原子切换

`loadVideo(data)` 现在先一次性替换：

- 文件路径与当前相机；
- 人工真值和复核状态；
- 机器候选与 Agent 记录；
- 候选帧计数索引；
- 参考帧、配置和紧凑几何模式。

上述状态就绪后才应用新数据的类别列表，并在 `refreshTopics()` 已将帧号切到新作用域后刷新逐类别总览。这样不会再出现“新类别 + 旧候选数量”的混合画面。

`applyInferenceLabelState(data, refresh)` 新增可控刷新参数：普通相机切换仍立即刷新；整文件切换则在全部状态一致后只刷新一次。

### 2.2 图像型 MCAP 自动进入标注窗口

自动打开条件从“schema 必须是 StillImage”改为“当前话题类型是 image”。因此：

- 单张导入图片继续自动打开；
- SFL 的 `LabelAgent.CompressedImage` 自动打开；
- 其他图像编码只要被媒体层识别为 image，也走同一流程；
- 点云或非图像话题不会被误当成二维标注窗口。

新数据加载完成后，操作者无需再点“添加窗口 → 选择相机 → 进入标注”。

### 2.3 首次打开少读一次时间轴和首帧

旧的自动打开流程先创建普通预览窗口，读取一次时间轴和首帧，再把同一个窗口切换成标注窗口并重复准备。`addWindow(..., deferInitialLoad=true)` 现在先建立轻量窗口壳，直接交给标注模式完成唯一一次时间轴和首帧读取。

正式浏览器验收记录到的自动打开请求为：

- 1次紧凑相机作用域读取；
- 1次时间轴读取；
- 1次首帧读取。

没有重复读取完整候选几何。

### 2.4 文件验证期间给出明确反馈

从文件列表点击“加载”后，数据集身份栏立即显示：

- `正在验证`；
- 目标数据集名称；
- `正在读取媒体索引并检查首帧；完成前保留当前工作区`。

此时 `loadedDataPath` 仍保持原数据。只有服务端完成媒体索引、首帧兼容检查和原子保存后，正式工作区才切换；失败则清除临时提示并继续显示原数据。
