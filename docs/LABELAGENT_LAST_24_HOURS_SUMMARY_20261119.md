# LabelAgent 过去24小时工作总结（截至2026-11-19 13:10）

## 一句话概括

过去一天的重点不是单纯“再跑几次模型”，而是把一个偶尔能跑通的演示原型，逐步加固成：切数据、切帧、重试、停止、恢复结果、保存配置和导入候选时都不容易串台；模型忙时能排队；结果会回到原图；机器候选不会冒充人工真值；新数据集也能沿同一流程进入。

## 1. 工作台稳定性

完成了以下用户可感知修复：

- 推理完成后，结果重新叠加到原图，而不是只留在过程页；
- 拖动工作区高度、缩放或切帧后，轮廓会重新贴合图像；
- Local VLM 忙时不再立即失败，而是显示排队/等待并自动恢复；
- 启动前检查数据、参考帧、模型和处理数量，减少点开始后长期卡0%；
- 任务进度按 SAM、VLM、Agent 阶段显示，后台精修不再看起来像死机；
- 处理帧数和复查轮数可调，默认复查6轮；
- 结果恢复、停止、失败重试都绑定任务号，旧任务不能覆盖新任务。

## 2. 多窗口和新数据集安全

从文件载入到配置保存，逐步把关键操作绑定到“文件路径 + 相机 + 文件载入代次 + 内容版本”：

- 最后一次文件选择生效，较慢的旧文件回执不会覆盖新数据；
- 快速连续翻帧以最后一次操作为准；
- 区域编辑、SAM点选、人工真值、参考帧、类别、清除候选、文件列表移除、候选导入和模型配置都拒绝旧窗口写入；
- 切换新旧数据集后，类别、推理类别、参考帧类别和逐类覆盖状态同步更新；
- 新数据集首次载入先完整替换状态，再打开当前相机，避免短暂显示旧候选；
- 文件管理器的“删除”仍只是从列表移除，磁盘原文件保留。

这部分的价值是：工作台不再依赖“操作者不要点太快、不要开两个窗口”才能安全使用。

## 3. 自动标注结果与人工边界

- 自动结果始终保留为候选，不自动标成人工完成；
- test/train 和人工真值边界保持隔离；
- 逐类别状态可以展开查看 VLM 依据、置信度和 SAM 是否有轮廓；
- 对“VLM看见但SAM漏分”的类别提供人工点选补标入口，但不会自动保存；
- 高风险类别复查、参考帧逐轮廓检查和打开原图查漏仍要求人工确认；
- 今天新增“整帧删空保护”：SAM有候选时，Agent不能未经人工确认把整帧静默删成空白。

## 4. 模型效果与效率尝试

### 斜坡

- 坡面继续按“可通行区域”处理，可与地面联合使用；
- 候选生成不依赖橙色，使用文本提示、几何过滤、重叠裁剪、参考帧和可选 LiDAR 证据；
- 加入室内普通地面等困难负样本，防止把地面块误报成坡；
- 做过斜坡平衡 LoRA 候选和不同随机种子验收，其中有候选达到“可继续人工审阅”的门槛，但这不等于已经独立证明泛化或正式部署；
- LiDAR/SAM融合、召回补漏和几何门禁仍属于候选方案，只有通过整体误检、召回和保留集门禁后才能替换现有主路。

### 其他机器人与小目标

- 尝试参考帧点扫描、跨序列验证、候选合并和自适应扫描；
- 对不安全的快速捷径做了反向验证并拒绝上线；
- 相同点提示请求会合并，减少重复SAM计算；
- 候选掩码数量和点扫描范围设有上限，避免一次补漏拖慢整个平台。

### GPU与服务路由

- 5090 SAM只有通过真实多提示、特征复用契约后才进入正式优先路；否则回退4090；
- 4090主VLM保持权威路径；5090可选VLM未就绪时不会拖住主流程；
- 启动时做无工厂图像的轻量预热，减少第一次真实推理的等待；
- 没有启动常驻占卡的hold进程。

## 5. 存储、备份与可恢复性

- 所有部署前都有按轮次备份和回滚路径；
- 工作盘空间紧张时，没有删除唯一数据，而是先逐文件哈希，再对可恢复历史备份做NTFS透明压缩；
- 旧备份逻辑内容和树指纹不变，D盘可用空间恢复到约2.93 GiB；
- 工厂图像、候选几何和浏览器截图继续留在本地未跟踪目录，不上传公开代码仓库。

## 7. 目前仍需诚实说明的问题

- “平台稳定可跑”不等于“每个候选都正确”；第85帧的15个候选仍需人工检查；
- 斜坡 LoRA 和其他机器人点扫描有候选提升，但没有足够证据宣称跨新场景全面提升；
- 微调候选实验做过，正式模型替换和持续后训练闭环尚未通过全部门禁；
- VLM/Agent的语义判断仍可能过度删除，因此刚加入整帧回滚，下一步还要限制连续错误删除并改善参考帧对比口径；
- 两次真实运行都可用，但第116帧约71.3秒，复查轮次与VLM调用时延仍需要继续压缩；
- 5090可选VLM通道当前不是主路，不能把“有5090 GPU”直接等同于“所有VLM请求都已在5090加速”。
