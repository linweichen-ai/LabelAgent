# Round527：同一克隆启动互斥

## 问题

端口预检、事务式回滚、原子进程记录均已具备，但两个用户动作仍可能在极短时间内同时进入启动流程。它们可能同时通过早期检查，再竞争端口、子进程和记录安装，造成不必要的失败与恢复。

## 实现

启动脚本现在根据当前克隆绝对路径的 SHA-256 派生 Windows 本地命名互斥锁：

- 同一克隆同时只允许一个启动动作；
- 不同克隆使用不同锁，不互相阻塞；
- 第二个启动动作在读取旧记录、运行环境检查或创建子进程前快速失败；
- 若前一个脚本崩溃，操作系统自动释放互斥锁；废弃锁由后续启动安全接管；
- 服务完成最终读回后释放锁，再按需打开浏览器；
- 不创建需要人工清理的锁文件。

## 真实并发测试

测试使用独立 PowerShell 进程持有同一命名互斥锁：

1. 持锁期间执行启动脚本，5 秒内失败并明确报告已有启动动作；
2. 持锁进程正常退出后再次执行，能够进入原有端口/权重预检，不再报告锁冲突；
3. 两次均未创建新的工作台或模型服务，既有工作台没有停止或重启。

第一次完整回归还暴露 `PYTHONUTF8=1` 与 Windows PowerShell 本机代码页不一致，测试读取线程发生解码失败。测试随后显式使用 Windows 系统代码页并允许不可表示字符替换；在“资源警告即失败”模式下重新通过，最终完整回归通过。该问题属于验收代码，不是互斥锁业务逻辑失败。
