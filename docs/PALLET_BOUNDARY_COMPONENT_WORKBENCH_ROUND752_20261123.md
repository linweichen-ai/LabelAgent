# Round752：托盘边界所有权证据接入只读复核工作台

## 这轮解决了什么

Round751 已经生成 11 张托盘边界候选组件的六联证据图，但当时只能离线查看。本轮把现有“微孔聚焦复核”入口通用化为“组件证据复核”，让旧微孔包和新的托盘所有权包共用同一套只读、会话草稿工作台。

这里没有把任何助手判断变成人工真值，也没有自动采用候选、回流训练或部署模型。

## 实现

- 后端新增 `labelagent.component-review-pack.v2`，旧 `labelagent.ego_tail_focused_review_pack.v1` 继续兼容。
- 新格式显式声明 `display_name`、`review_kind` 与 `evidence_mode`；当前只允许受控的微孔和托盘所有权类型。
- `tools/build_pallet_boundary_component_review_pack.py` 从一个或多个 Round751 所有权清单构建复核包：逐图核对路径、SHA-256、图片格式、尺寸和安全门禁，再原样复制证据字节。
- 前端按证据类型显示名称和排名；3840×480 所有权图按 8:1 宽幅展示，不再塞进方形黑底。
- 草稿新增 `session_only=true` 绑定，同时兼容旧 `local_only=true` 草稿；清单哈希或图片哈希改变时，旧草稿自动失效。

## 回归

- 定向测试：11 项通过，另有 4 个子测试通过；
- 前端核心测试：通过；
- 全量 `tests/`：`1790 passed, 1 skipped, 286 subtests passed`；
- Windows 执行全量测试需要 `PYTHONUTF8=1`，否则旧测试中未显式指定 UTF-8 的 `Path.read_text()` 会按 GBK 读取 UTF-8 临时文件并产生环境性失败；启用 UTF-8 后全量通过。

## 证据边界与下一步

本轮证明的是“真实所有权证据能够安全、稳定、可复现地进入只读复核工作台”，不是模型准确率提升。下一步应先收集独立人工复核结论，再决定哪些边界规则值得进入候选实验；在完整精度、误检和总体 F1 门禁通过前，继续保留现有默认策略。
