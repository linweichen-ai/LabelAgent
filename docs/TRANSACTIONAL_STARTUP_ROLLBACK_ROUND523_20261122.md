# Round523：事务式启动回滚

## 问题

Round522 已经能在启动前识别端口占用，但预检与真正监听之间仍有短暂窗口。若端口在此期间被抢占，或 SAM3 / 工作台子进程提前退出、健康检查失败、最终服务读回失败，旧脚本可能留下本轮已经创建的进程或过期的 `.repro/processes.json`。

## 修复

启动阶段现统一放入失败回滚边界：

- 本地 SAM3、外部 SAM3 健康检查、工作台启动、就绪等待和最终读回属于同一个启动事务；
- 等待期间同时观察本轮工作台与本地 SAM3 子进程，任一提前退出立即停止等待；
- 任一阶段抛错时，只结束本轮记录的 PID，并删除本轮进程记录；
- 成功完成服务读回后才保留进程；浏览器打开不参与服务事务；
- 既有实例、其他仓库和其他用户进程均不扫描、不接管、不停止。
