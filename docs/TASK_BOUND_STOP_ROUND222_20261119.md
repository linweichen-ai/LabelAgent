# 第二百二十二轮：停止操作绑定任务号，防止旧标签页误停新任务

日期：2026-11-19
状态：已实现、已全量回归、已部署到正式工作台并完成浏览器验收

## 通俗结论

以前点击“停止自动标注”只表达“停止现在正在跑的任务”，却没有说明要停止哪一个任务。如果两个标签页的画面不同步，旧标签页还以为旧任务在运行，它发出的停止请求可能正好停掉另一标签页刚启动的新任务。

现在每个停止请求都必须带上操作者当前看到的任务号。服务端会再次核对：只有任务号完全一致才设置停止信号；任务已经换代时返回 HTTP 409，并明确提示“未停止当前新任务”。主工作台和参考帧一键起稿弹窗使用同一规则。

## 修复前证据

使用隔离的服务端状态构造：

- 当前真实活动任务：`new-task-round222`；
- 旧标签页请求停止：`stale-old-task-round222`；
- 请求体虽然携带旧任务号，但旧服务端完全忽略该字段；
- 返回 HTTP 200、状态被改为 `stopping`、停止信号被置位；
- 新任务号仍显示为 `new-task-round222`，说明被误停的正是新任务。

该复现只修改测试进程内存，未接触正式任务、模型、候选或人工真值。原始结果保留在本地未跟踪目录 `artifacts/round222-task-bound-stop/server-prefx-result.json`。

## 修改内容

### 1. 服务端成为最终门禁

`POST /api/run/stop` 现在要求 `expected_task_id`：

- 缺少任务号返回 HTTP 400，不设置停止信号；
- 当前有运行中或停止中的任务、但任务号不匹配时返回 HTTP 409；
- 任务号匹配时才把状态改为 `stopping`；
- 回执带回实际 `task_id`，便于页面再次核对；
- 任务已经结束时返回 `stopped=false`，不会伪装成刚刚成功停止。

### 2. 主工作台停止按钮

主按钮先冻结当前页面看到的 `latestAgentJob.task_id`，再发送停止请求。回执任务号不一致时不宣告成功；409 后立即刷新运行状态，因此页面会切到另一标签页启动的新任务，而不是继续显示旧任务。

### 3. 参考帧自动起稿弹窗

参考起稿在轮询当前运行状态时，只接受开始时间属于本轮、状态为 `running/stopping` 的任务号。点击“停止生成”时：

- 尚未确认本轮任务号则安全等待，不发送无归属的停止请求；
- 已确认后发送本轮任务号；
- 回执任务号不一致则不显示“正在安全停止”。

这避免参考帧弹窗误停主工作台或其他标签页的新任务。
