# Round535：首次状态单读候选负结果

## 假设

Round534 的正式工作台在约 1.19 秒内恢复，但启动期仍读取两次运行状态。候选方案尝试复用页面加载早期、尚未绑定数据作用域的第一次状态回执：只有当回执中的文件、相机和载入代次与稍后恢复出的最终作用域完全一致时才采用，否则继续走原有补读。

| 项目 | Round534 正式版本 | Round535 候选 |

第一次状态回执对应的是相机恢复前的旧载入代次，不能满足最终作用域门禁，因此仍必须补读。候选没有减少请求，并出现约 1 秒负向波动。

## 决策

- 候选代码、UI 172 和新增测试全部撤回；
- 正式工作台保持已验收的 UI 171，不部署该候选；
- 不通过忽略载入代次来强行合并请求，因为这会重新引入跨窗口/同文件重载的旧状态风险；
- 隔离服务已停止，正式 PID `63284` 未变化。
