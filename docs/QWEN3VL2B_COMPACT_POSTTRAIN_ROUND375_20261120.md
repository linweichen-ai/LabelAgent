# Round 375：2B VLM 短目标后训练与公平 A/B

日期：2026-11-20

## 结论

本轮完成了一次真实的 Qwen3-VL-2B LoRA 后训练。新候选把监督答案压缩为保持原有
八类 schema 的单行短 JSON，在内部 dev8 上达到 `8/8` 合法输出和 `62/64` 个类别证据
与 8B 机器教师一致。使用完全相同的短提示重测旧最佳 LoRA 后，旧模型为 `61/64`；
新候选少了一个 `other_robot` 漏检，并把回答中位长度从 `198.5` 降到 `182` token。

这仍不是人工真值准确率，也没有通过全新外部盲测。动态生成路径中新候选中位时间为
`16.608` 秒，旧最佳为 `15.712` 秒；追加同机、同提示的静态缓存公平对照后，新候选降至
`4.594` 秒，旧最佳为 `5.602` 秒，新候选快约 `18.0%`。因此当前决定仍是：保留离线质量与
效率候选，不替换正式 8B，不进入 `test24`，不改工作台生产权重。

追加的4张隔离 `other_robot` 影子检查与既有助手预审一致3张：两个负例均正确拒绝，两个正例
命中1张、漏1张。该检查再次说明候选尚不能独立承担远处小型机器人的发现；助手预审也不是人工
真值，因此这里只记录风险，不换算为正式准确率。

## 公平 A/B

三组结果都使用相同图片、相同短目标契约和相同动态生成路径：

| 候选 | 合法 JSON | 教师证据一致 | 中位输出 token | 中位生成时间 |
|---|---:|---:|---:|---:|
| 基础 2B | 7/8 | 48/56 | 255 | 13.782 秒 |
| 旧最佳 LoRA | 8/8 | 61/64 | 198.5 | 15.712 秒 |
| 本轮短目标 LoRA | 8/8 | 62/64 | 182 | 16.608 秒 |

本轮新候选的斜坡结果为 TP=2、FP=0、FN=0、TN=6；普通地面没有新增斜坡误报。
`other_robot` 从旧最佳的 TP=3、FP=1、FN=1、TN=3 改善为 TP=4、FP=1、FN=0、TN=3。
剩余错误是一个 pallet 漏检和一个 `other_robot` 误报。

## 静态缓存加速复测

为避免把模型质量提升和运行方式混为一谈，又在同一台4090、同一8帧、同一短提示、相同静态
KV缓存设置下分别复测新旧LoRA。结果如下：

| 候选 | 合法 JSON | 教师证据一致 | 中位输出 token | 中位生成时间 | 最慢帧 |
|---|---:|---:|---:|---:|---:|
| 旧最佳 LoRA + 静态缓存 | 8/8 | 61/64 | 199 | 5.602 秒 | 6.258 秒 |
| 本轮短目标 LoRA + 静态缓存 | 8/8 | 62/64 | 182 | 4.594 秒 | 5.021 秒 |

新候选相对旧最佳的中位生成时间减少 `1.009` 秒，约 `18.0%`；相对新候选自身动态路径的
`16.608` 秒减少约 `72.3%`。这证明“短回答后训练 + 静态缓存”可以同时改善本组样本的质量、
输出长度和生成速度。该数据仍只来自内部dev8，不能外推为新场景准确率或正式端到端时延。

## 服务与回滚

训练使用双 4090 的 GPU0 空闲显存，与正式 SAM 服务并存；包装器在训练和评测前检查 SAM/VLM
健康及在途请求。训练完成后训练进程已退出，GPU0 回到约 17,113 MiB 空闲；正式 SAM、8B VLM、
5090 加速通道和工作台均正常，在途请求为0。正式 `state.json` SHA-256 仍为
`9EF08118DD2BA0760CC93CF57BBEAAE4B3BED062D383DF4E6A454C389D4AB115`。
