# 第二百三十四轮：旧窗口真值与参考帧写入代次隔离

日期：2026-11-19

状态：已部署并完成全量回归、正式浏览器反向验收和状态哈希读回

版本：UI 149、`app.js?v=187`、`human-review.js?v=98`、`reference-prep.js?v=167`、`review-packet.js?v=165`

## 通俗结论

上一轮已经保证“最后一次选择的数据文件生效”，但继续审计发现一个更隐蔽的风险：如果同一个文件被重新载入，旧标签页看到的文件路径和相机名仍与新会话相同，它仍可能尝试保存人工真值、驳回候选或锁定参考帧。

现在工作台不仅核对“哪个文件、哪个相机、哪一帧”，还必须核对“这是第几次载入”。旧窗口即使文件名完全相同，只要载入代次落后，就会在服务器写入前收到 HTTP 409；旧窗口不能读取新会话几何、不能取得新复核绑定、不能提交真值/驳回，也不能锁定参考帧。

## 问题边界

Round232 的文件激活代次已经覆盖文件载入和相机切换，但以下高风险入口当时主要依赖路径、相机、帧哈希、候选哈希和数据版本：

- 单帧按需标注读取 `/api/frame_state/<frame>`；
- 参考帧目录 `/api/reference-preparation`；
- 人工复核绑定 `/api/human_review_binding`；
- 人工真值保存 `/api/truth`；
- 候选人工驳回 `/api/human_review`；
- 参考帧锁定 `/api/reference_frame`。

这些校验对“切换到另一个文件”已经足够严格，但同一路径、同一相机、同一内容重新载入时，旧窗口仍可能碰巧通过路径和内容哈希。人工真值与训练隔离属于最高风险边界，因此本轮不接受只在页面层提醒，改为服务端强制门禁。

## 本轮实现

### 1. 服务端统一校验载入代次

新增统一的请求代次校验。代次必须是整数并与当前服务器文件激活代次完全一致：

- 缺失或格式错误：HTTP 400；
- 代次落后或不一致：HTTP 409，并带 `stale_review=true`；
- 只有当前代次才继续读取帧、计算复核绑定或执行写入。

人工真值和候选驳回在最终提交时再次使用复核绑定中的 `expected_file_activation_generation`，因此即使复核弹窗打开后另一窗口重新载入同一文件，旧弹窗也不能提交。

### 2. 参考帧与按需读取同样绑定代次

单帧按需读取和参考帧目录都要求页面提供当前代次，回执也带回同一个代次。参考帧锁定同时核对：

1. 文件路径；
2. 相机；
3. 帧号；
4. 文件载入代次；
5. 真值内容哈希；
6. 当前人工复核回执。

任何一项变化都拒绝在当前工作区显示或写入。

### 3. 页面不允许“刷新获得新令牌”

参考帧准备弹窗和专项复核页原本会重新读取参考目录。如果该接口直接返回最新代次，旧标签页可能借此取得新会话代次。本轮要求它们用工作台已持有的代次发起请求；旧标签页只能得到409，不能通过刷新目录把自己升级成新窗口。

### 4. 人工复核界面公开绑定信息

人工复核弹窗新增“文件载入代次”显示。提交和驳回都使用服务器返回的绑定代次，不使用临时猜测值；页面本地作用域变化时也会中止后续读回与更新。
