# Round738：栈板边界清理的人工作用域开发门

## 结论

当前 `pallet-boundary-cleanup-v6` **未通过开发门，不自动上线**。

这是第一次把 Round737 的“看起来更平滑”候选与同一张图上的既有人工复核轮廓做固定实例匹配，
而不是只统计改了多少像素。可严格绑定的范围只有 1 帧、10 个发生变化的栈板候选；10 项 IoU
全部下降，平均 IoU 从 `0.983346` 降至 `0.974326`，下降 `0.009020`。其中 5 项触发单实例
回退门。正式工作台、人工真值、训练数据和模型权重均未修改。

这项结果只能否决当前候选，不能证明所有场景上的总体效果：复核身份仍是 `self_declared`，
数据切分为 `unassigned`，训练回流未获批准，并且只有一个同场景帧。

## 对齐和指标

1. 只使用“当前候选”与 11 个栈板复核轮廓计算 IoU 矩阵；
2. 用最大总 IoU 的匈牙利匹配一次性固定映射；
3. 清理后候选必须沿用同一映射，不能通过换一个真值实例提高分数；
4. 10 个变化候选全部匹配，固定匹配 IoU 均大于 `0.97`；
5. 同时报 IoU、Dice、Boundary-F1@1px、Boundary-F1@2px、FP/FN 像素、连通域、
   小碎片、孔洞和周长/面积；
6. 新增前景若落在人工作用域背景内会单独计数，避免把真实叉孔或开口当噪声填掉。

## 决策与下一步

1. 保留正式工作台当前结果，不把 v6 对比候选自动采用为真值或生产输出。
2. 下一版不再用“看上去更平滑”作为通过标准；优先限制无图像证据的边界简化，只保留有
   明确表面证据且不破坏结构孔的修改。
3. 为另外 5 个仍有效的人工作台栈板帧生成同源、只读候选包；完成前不宣称跨帧提升。
4. Task3 的 81 个人工来源实例仍需独立签字；实例外继续 ignore，test24 不回流训练。
5. 微调候选继续保持拒绝部署，直到同域留出和跨序列门同时不退。
