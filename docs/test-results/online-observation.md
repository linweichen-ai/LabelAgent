# 实时局部观察到原模型工具决定

在同一 2B NF4、相同候选、参考规范和操作 schema 下，先执行两次新的局部分类请求，再把实际类别观察交给原 VLM 选择工具。分类请求不含当前类别或对照身份；主模型能看到当前候选类别及两个视图的实际观察。程序既不构造 reclassify 操作，也不复用分类缓存。

两帧原候选、两项类别翻转、两策略共八项，最多三轮、顺序交错。调用前固定恢复及保护要求。原四张主模型图片和原提示前缀保留，只追加带来源说明的观察文字，操作 schema 不变。

## 第一组结果

210 项完整回归通过。完成 8 次真实主模型复查及 8 次实时局部分类；两策略均原候选保持 2/2、错类恢复 0/2、实际修改 0。四对原提示/图片前缀和 schema 核验一致。

两个错类的局部视图都识别为人员。主模型理由也明确表示候选的 pallet 类别不正确，却同时返回 done 和空 operations。因此新证据已进入模型，但没有形成可执行修正。本轮要求未通过，没有启用。

后续单独测试一次有界的一致性复核：当 done/空操作与两视图局部观察产生冲突时，让原模型重新核对。观察是可出错的辅助证据，复核可保留原决定，不得由程序强制选择修改。将单独报告新增调用、真实操作、修改后再观察及失败情况。
