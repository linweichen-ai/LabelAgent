# `other_robot` 自动紧定位与保守分流：Round 194–198

## 一句话结论

这一轮没有把不确定目标硬写成 `other_robot`，而是把结果稳定分成“自动候选、需要人工看一眼、没有候选”三类。最终的 Round 198 在四张跨序列图片上做到：两张助理预审正例都进入复核，两张助理预审负例都不产生自动候选且不打扰复核；VLM 分类耗时相对 Round 197 降低 51.62%。但这些样本没有人工真值，所以结果只能证明分流逻辑更保守、更省时，不能称为准确率。

## 这轮为什么不继续盲目训练

Round 190–193 已经证明，仅用少量助理预审样本继续训练，会出现“所有图片都回答有机器人”的退化。当前更关键的问题不是模型完全看不见，而是候选区域不够准确：

- 自车的左右货叉会被当成两个低矮机器目标；
- 普通人工叉车即使无人驾驶、停在原地，也可能被误认为无人机器人；
- 远处小目标可能和人物粘在一起，或在 SAM 候选阶段就没有形成独立轮廓；
- 全图 VLM 比较保守，紧裁剪又可能丢失“这是自车还是独立设备”的上下文。

因此本轮先修“怎么看、看哪里、看不清怎么办”，没有把训练轮数继续堆高。

## 当前流程

```text
原图
  ↓
颜色无关的参考点扫描（SAM 生成实例候选）
  ↓
几何过滤、去重、已有类别排除
  ↓
先识别画面下方左右对称的自车货叉对
  ├─ 是：直接排除，不再占用 VLM
  └─ 否：只取前 4 个高质量候选
            ↓
      原始上下文 + 紧目标图 + 独立掩码双路 VLM 判断
            ↓
      两路都支持独立机器人 → 自动候选
      一路支持、一路反对   → 人工复核
      都不支持             → 没有候选
```

这里的扫描不依赖橙色、绿色等固定颜色。颜色只用于结果可视化，不能作为类别证据。

## Round 196–197：修掉自车货叉误报，建立三态分流

新增两层保护：

1. 画面下方、左右对称、尺寸和高度相近的细长目标，先识别为自车货叉对；
2. 当基础提示与正例参考提示意见冲突时，不再静默丢弃，也不自动晋级，而是进入人工复核。

Round 197 的分流结果为：

| 样本 | 自动候选 | 人工复核候选 | 状态 |
|---|---:|---:|---|
| Capture camera0 | 0 | C02、C05、C07 | 需要复核 |
| Capture camera2 | 0 | C02、C03 | 需要复核 |
| SFL 1104/004 | 0 | 0 | 没有候选 |
| Capture camera3 | 0 | C08 | 需要复核 |

自车货叉 C04、C09 已被正确拦截，但当时是在 10 个候选完成 VLM 分类后才执行，仍浪费计算，而且 camera3 还有一个低优先级冲突候选进入复核。Round 197 结果 SHA-256：

## Round 198：把拦截提前，并把候选收紧到 4 个

最终把自车货叉对识别提前到 VLM 之前，并把每张图的分类上限从 10 个降到 4 个。

| 样本 | 自动候选 | 人工复核候选 | 助理预审覆盖 |
|---|---:|---:|---|
| Capture camera0 | 0 | C02 | 覆盖疑似正例 |
| Capture camera2 | 0 | C02、C03 | 覆盖疑似正例 |
| SFL 1104/004 | 0 | 0 | 负例无打扰 |
| Capture camera3 | 0 | 0 | 两根自车货叉在 VLM 前排除 |

最终分流统计：

- 助理预审正例：2/2 至少有一个候选进入人工复核；
- 助理预审负例：0/2 产生自动候选，0/2 产生复核候选；
- 自动晋级的 `other_robot`：0；
- 人工真值写入：0；
- 训练批准：0；
- 正式模型或工作台权重修改：0。

这些是候选覆盖和干扰情况，不是 precision、recall 或准确率。

## 额外诊断：语义提示不能替代实例扫描

还尝试用 `robot / AGV / AMR / mobile robot / industrial robot / forklift` 等文本直接请求 SAM。四张图上没有产生可用的 `other_robot` 检出，只在 camera0 找到明显的普通叉车。这表明当前 SAM 语义提示对远处、遮挡、低矮工业机器人不够可靠，不能单独承担定位；仍需要参考点扫描或更强的专用检测器。

## 安全和可复现边界

- 输入清单强制 `human_truth=false`、`candidate_only=true`、`production_deployed=false`、`approved_for_training=false`；
- 每张源图都绑定 SHA-256，重复 ID、图片变更和不安全输出路径会失败关闭；
- 离线评测只写本地结果目录，不修改正式 `state.json`；
- “需要复核”不能自动转成标签，“助理预审”不能自动转成人工真值；
- 33/33 项相关单元测试通过，Python 编译和差异检查通过；
- 收尾读回：工作台 HTTP 200，SAM 两个入口均 HTTP 200，VLM HTTP 200，SAM/VLM 进行中请求均为 0。

## 下一步门禁

1. 先让人工对这四张图和候选区域做一次窄复核，尤其确认 camera0 与 camera2 是否真的存在独立无人机器人；
2. 扩到至少 24 张跨序列正负样本，保持序列隔离，不能用同一批图训练又验收；
3. 针对“小目标与人物粘连”增加紧目标生成或专用检测器，不把人工猜测强塞给模型；
4. 对 VLM 做候选批处理和图像特征复用，继续压低 71 秒的分类开销；
5. 只有人工真值、负例干扰、正例覆盖和原开发集非退化全部通过，才允许接入工作台候选层；仍不自动标记为人工完成，也不自动进入训练集。
