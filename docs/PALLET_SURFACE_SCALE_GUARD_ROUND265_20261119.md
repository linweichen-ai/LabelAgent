# LabelAgent Round 265：栈板表面填孔的跨分辨率尺度保护

日期：2026-11-19  
范围：候选层栈板几何清理、只读跨数据审计、工作台空间恢复。没有启动模型推理、训练或后训练，没有修改人工真值和模型权重。

## 一、为什么 Round 264 之后还要继续收紧

Round 264 已解决第100帧近景木栈板的主要视觉问题：10个内部洞降为4条真实横向板缝。但把同一规则扩到更多帧做肉眼复核时，第123帧出现一项风险：中等大小的黑色塑料实例包含圆形真实开口，单看“洞的面积、跨度和长短轴比”可能把它当成表面掉点。

这说明“紧凑洞”规则只适合占画面很大的近景栈板，不能无条件用于中等和远处实例。

## 二、v3 的收紧规则

紧凑表面洞仍需同时满足：

- 洞面积不超过768像素；
- 最大跨度不超过64像素；
- 长短轴比不超过3.0；
- 整个候选覆盖画面至少30%；
- 单实例总变化不超过2.5%；
- 显著连通组件数保持不变；
- 结构洞最低保留75%。

相较于固定“候选至少10万像素”，30%相对面积门槛能随640×480、1920×1536等分辨率同步缩放，避免高分辨率新数据上门槛意外变松。

中等与远处实例仍会执行原有微孔、短纹理孔和受限轮廓简化，但新增的大跨度紧凑填孔保持关闭。

## 三、审计工具同步修复

跨数据审计工具此前有两项口径落后：

1. 仍按旧版“面积大于256或跨度大于32即结构洞”计算，会把v3允许的近景紧凑表面洞误报为结构破坏；
2. 对工作台状态文件只读取 `candidates_by_topic`，没有用当前页面最新的顶层 `candidates` 覆盖当前相机，可能拿旧快照评价新版。

现已与生产规则共享紧凑洞判定，并在审计工作台状态时用当前候选覆盖当前相机；其他相机仍读取分相机集合。新增确定性测试覆盖旧快照与当前候选冲突场景。
