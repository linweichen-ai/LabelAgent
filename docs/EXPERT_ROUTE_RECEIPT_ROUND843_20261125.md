# Round843：困难帧路由执行后统一回执

## 结论

困难帧影子路由原本已经记录触发原因、各项分数、本地模型耗时和
SAM3 复用状态，但真正执行外部专家后，外部耗时、缓存命中、回退原因
和最终路线没有统一收口。本轮新增纯数据函数
`finalize_expert_route_receipt`，把影子判断与执行事实合并成一条可追溯
回执。该函数不接收图片、提示词或模型原始回答，也不会发起网络请求。

## 回执覆盖内容

- 为什么调用或不调用外部专家，以及每项评分；
- 最终路线：本地保留、外部完成、缓存复用或外部失败后本地回退；
- 本地与外部模型耗时；
- 新外部调用次数、重试次数和请求摘要；
- 是否发生回退、回退原因、是否复用已有 SAM3 结果；
- 固定安全边界：`candidate_only=true`、`human_truth=false`、
  `approved_for_training=false`。

回执会拒绝不一致事实，例如“没有尝试却声称已上传”“缓存命中却声称
产生了新外部请求”“发生回退却没有回退原因”，以及任何试图把机器结果
标成人工真值或训练数据的输入。

## 当前 API 实时探针

2026-11-25 使用项目既有安全探针向 `openai/gpt-6-astra` 发送了一张程序
生成的 640×512 合成图。请求通过 `openai_chat` 协议完成，耗时
3,405.653 ms，使用 453 tokens，重试 0 次，返回结果摘要与历史已验证
结果一致。没有发送工厂图片、MCAP、标签、本地路径或人工真值。

这次结果证明当前 API、认证和结构化视觉输出仍可用，不证明真实工厂
数据上的质量提升。真实 19 张困难开发队列仍保持未上传状态；必须取得与
冻结队列匹配的明确授权后，才能先运行 8 张哨兵。
