# Slope（斜坡）重点类分割与闭环验收口径

## 为什么单列

斜坡属于可通行区域的一部分，但与平地、货箱地板、黄色标线、门板和普通金属板容易混淆。边缘通常贴近平地接缝，远距离时像素少，强反光、阴影和遮挡又会削弱纹理，因此只看七类平均指标会掩盖 slope 的失败。

## 当前证据边界（2026-11-11）

- LabelAgent 已把 `slope` 纳入七类体系，文本查询映射为 `ramp`，不是待新增 ontology 类。
- 当前真实验收帧来自批次 A/000、`/capture/camera_0/image`、frame 0，图像 SHA-256 为 `3775ee5f41374c9a302c458cfffa2799222e22ff17541045d6acfb8434bd682f`；画面右中部有黄色斜坡。
- SAM3 单正点 `(1100,620)` 返回 1 个候选区域、44 个外轮廓顶点、score 0.98046875。这个结果只证明服务能产生候选，当前帧没有可回读的 slope 人工像素真值，因此不能据此宣称分割质量、IoU 或可通行性正确。
- 第一条已知类 slope high-level 事件固定保存 `human_pixel_truth_available=false`、`approved_for_training=false`、`traversability_status=unknown` 和 `geometry_evidence_sufficient=false`；它不走 unknown/ontology 分支。

## 两层语义

1. `slope_visible`：图像中可见的实际坡面像素，和 `floor`、`cargo_floor`、门板、标线分开标注。
2. `slope_traversability`：`unknown / traversable / non_traversable / review_required`。它是基于视觉、LiDAR、位姿和车辆约束的派生判断，不等同于视觉类别。

VLM 可以提出 slope 候选、相似类别和理由；SAM 负责像素候选；Agent 负责 ROI、正负提示、拆分/合并和重试。没有几何证据时，VLM 不得把 `slope_visible` 直接升级为 `traversable`。

## 建议闭环

```text
VLM 发现/确认 slope 候选
  -> LiDAR 平面、法向、高差和连续性检查
  -> Agent 生成单坡面 ROI + 坡内正点 + floor/门板/障碍负点
  -> SAM 分割坡面
  -> 边界、连通性、跨类泄漏和几何一致性门禁
  -> 自动接受或人工复核
  -> slope 人工真值与可通行性判断分别版本化
```

## 必须单独报告的指标

- slope 像素 IoU、Dice；
- slope 边界 F1（至少报告多个像素容差，不能只报区域重合）；
- 与 `floor`、`cargo_floor`、门板/金属板的混淆和泄漏像素；
- 近/中/远距离、正视/侧视、遮挡、反光/阴影分层结果；
- 同一斜坡连续帧的掩码面积与边界抖动；
- slope 候选召回率、自动接受率和人工复核率；
- `traversable` 的误接受数。安全评测集中出现误接受时，不允许自动放行。

在建立第一批独立人工 slope 真值前，不设看似精确的自动接收阈值，也不允许用模型 score 代替 IoU。阈值应在开发集上确定，再在按采集序列隔离的测试集上锁定验证。

## 第一批人工真值与困难分层

先建立小而明确的 slope 专项集，正例和负例都要有：

- 近距离大坡面、远距离小坡面、侧视、部分遮挡；
- 黄色/灰色/金属/橡胶等材质，强光、阴影、反光、磨损；
- 坡面与平地接缝、坡面与货箱地板接缝、坡边缘；
- 可移动登车桥、固定坡道、窄坡、边缘有落差或障碍的坡；
- 困难负例：黄色地面标线、平放钢板、门板、托盘表面、普通 floor 和 cargo_floor。

训练/验证/测试按采集序列或实体斜坡隔离，不能把同一斜坡的相邻帧拆进不同集合。

## 仿真数据接入

仿真可系统改变坡度、宽度、高差、材质、颜色、摩擦、边缘形状、障碍物、相机姿态、距离、光照和遮挡，并天然输出 slope 像素真值与几何真值。仿真样本必须保留 `source.origin=simulation`、场景参数和随机种子；仿真提升只能作为补充，最终仍由真实工厂 slope 测试集验收。
