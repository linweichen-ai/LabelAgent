# 第二百三十三轮：旧备份透明压缩与工作盘余量恢复

日期：2026-11-19  
状态：已完成、内容指纹复核通过  
性质：本地存储稳定性治理，不改模型、数据语义或工作台代码

## 为什么立即处理

第二百三十二轮部署时，启动器提示 D 盘工作临时空间不足2 GiB。部署后实测只剩约1.47～1.52 GiB。工作台虽然仍能启动，但新数据导入、媒体索引、结果保存和回滚备份都会受到影响，因此继续做效果实验前先恢复安全余量。

## 只读容量归因

`D:\Apps\LabelAgent` 的主要逻辑占用为：

| 目录 | 逻辑大小 | 处理决定 |
|---|---:|---|
| `work` | 约23.29 GiB | 含正式数据、模型、检查点，不动 |
| `.local` | 约9.50 GiB | 含迁移工作树和回滚，继续细分 |
| `.venv` | 约4.97 GiB | 正式运行依赖，不动 |
| `source` | 约3.28 GiB | 代码和SAM资产，不动 |
| `backup` | 约1.85 GiB | 旧状态备份，适合透明压缩 |

细分后确认：

- `.local/relocated-worktrees` 约6.18 GiB，包含历史研发恢复数据和当前实验证据，本轮不删除；
- `.local/backups` 有目录联接和既有独立备份，不用简单逻辑大小判断物理占用；
- 当前实验产物约1.21 GiB，但其中一份图文说明书被其他程序占用，无法获得完整树指纹，因此本轮明确跳过整个目录；
- `backup` 下311个实际文件均可完整读取，主要是历史大体积JSON状态副本，适合NTFS透明压缩。

## 执行门禁

压缩前对 `D:\Apps\LabelAgent\backup` 按“相对路径、字节数、逐文件SHA-256”生成完整树指纹：

- 文件数：311；
- 逻辑字节：1,988,581,846；
- 树SHA-256：`07981DE390E820475EE96274D9FDFFFE0350B7B1877E73E2C70846106F904523`。

只在该指纹成功后执行NTFS透明压缩。没有删除、移动或改名任何文件；压缩是可逆的，应用仍通过原路径读取原始字节。

## 结果与读回

压缩后：

- 311个文件仍全部存在；
- 逻辑字节仍为1,988,581,846；
- 树SHA-256仍为 `07981DE390E820475EE96274D9FDFFFE0350B7B1877E73E2C70846106F904523`；

这证明释放的是可恢复的存储表示，不是项目内容。
