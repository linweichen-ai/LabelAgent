# Round839：语义专家哨兵的可执行哈希队列

## 修复的关键问题

Round838已经冻结8+11的哨兵顺序，但原始采集图哈希与复核工作区实际保存的JPEG哈希不同。外部运行器读取的是复核JPEG；如果继续把原始采集哈希放在运行字段中，发送前校验必然失败，或者可能错误绑定另一份图像。

本轮新增显式转换器：

- `original_source_image_sha256`保留原始采集图哈希，只用于溯源；
- `source_image_sha256`绑定运行器实际读取和可能上传的复核JPEG；
- 队列仍不包含绝对路径；
- 前8帧标记为`canary`，后11帧标记为`remainder`；
- 队列整体和逐帧授权仍为false。

## 运行保护

外部运行器新增`--max-new-attempts`参数。即使19帧获得整体授权，首轮也可硬限制最多产生8个新请求；失败记录在恢复时不会自动重试。缺少与队列哈希完全一致的授权文件时，加载器在读取图片和调用模型前失败关闭。

实测执行队列为19帧，其中8帧哨兵、11帧后续；首帧运行哈希与复核JPEG哈希一致。缺少授权文件时拒绝执行，API调用和真实图外发均为0。

第一次门禁检查命令误带文本补丁标记，在进入加载器前产生Python语法错误；修正命令后，缺少授权被正确拒绝。该失败没有读取或上传图片，也没有调用模型。
