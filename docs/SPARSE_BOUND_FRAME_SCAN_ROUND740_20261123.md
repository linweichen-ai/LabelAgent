# Round740：稀疏候选绑定的全范围只读扫描

## 结论

正式当前序列共有 152 帧，但只有 frame 0、76、151 三帧保存了服务端候选绑定；其余 149 帧
没有候选也没有绑定。Round739 实际已经覆盖了当前正式状态中全部可验证机器候选，共 34 个
栈板，而不是只抽查了三帧后遗漏其他已有候选。

v7 在这 34 个候选上仍为 0 次变化。因此当前只能确认安全 no-op，不能确认真实图像修复有效。
要得到真实正例，下一步必须在隔离环境为更多帧生成新的候选，再运行同一只读门禁；不能在正式
工作台上补写候选或把空帧当成负样本。

## 工具改进

`build_pallet_boundary_comparison_pack.py` 新增显式
`--skip-unbound-empty-frames`：

- 默认关闭，原有缺绑定立即失败行为保持不变；
- 只接受 frame-scoped 接口明确返回的两张空稀疏映射：`candidates={}` 且
  `candidate_review_bindings={}`；字段缺失、错类型、外来帧键或单边条目均失败；
- 如果存在任一候选但缺绑定，仍立即失败；
- 候选集合 SHA、候选指纹、作用域或前后状态不一致仍立即失败；
- 跳过帧列表同时写入 manifest 和生成回执，不能静默丢帧；
- 被跳过的空帧不读取原图，减少无效 I/O。
- 产出前逐一二次读取所有跳过帧；并发期间新增候选或绑定时立即失败关闭。
