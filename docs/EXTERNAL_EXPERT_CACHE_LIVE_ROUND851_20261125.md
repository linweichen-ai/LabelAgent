# Round 851：外部专家真实缓存与上传回执修正

## 目的

验证完全相同的图像、提示词和模型是否只产生一次真实联网调用，并核对缓存命中时的审计字段是否准确。

## 发现与修复

外部专家底层已经能够复用精确缓存，但合成图冒烟工具在缓存命中时仍固定写入 `external_upload_performed=true`，会把“本地读取缓存”误报成“再次上传”。本轮改为依据 `expert_network_dispatched` 记录：

- 真正联网：`external_upload_performed=true`，内容为生成的合成图；
- 缓存复用：`external_upload_performed=false`，内容标记为 `none_cache_reuse`。

该修复只校正测试与审计回执，不改变正式路由、缓存键、模型输出或人工真值。

## 真实联网复测

同一进程内，对同一张 320×240 合成图、同一提示词和同一 `openai/gpt-6-astra` 连续请求两次：

| 项目 | 第一次 | 第二次 |
|---|---:|---:|
| 路由 | `external_expert` | `external_expert_cache` |
| 延迟 | 7,880.064 ms | 0.364 ms |
| 联网发送 | 是 | 否 |
| 外部上传 | 是，仅合成图 | 否 |
| 缓存命中 | 否 | 是 |
| 重试 | 0 | 0 |
| 响应哈希 | `31344e20...390d` | `31344e20...390d` |

两次调用合计只有 1 次网络发送和 1 次缓存命中。真实网络请求的用量为 149 输入 Token、16 输出 Token、165 总 Token；缓存读取没有新增网络调用。接口未返回可核验费用字段，因此不虚构金额。
