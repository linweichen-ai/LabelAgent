# Round394：ego 固定验收标准与独立样本门禁（2026-11-22）

> 2026-11-22 更新：Round395 将 manifest/report 升级为 v3，新增分相机平均质量和候选可用性
> 门禁。本文保留为固定阈值与独立样本门禁的历史记录，实际验收使用 Round395 的 v3 清单。

## 结论

Round393 已绑定候选和真值来源，但清单仍可自行把阈值降到接近零、只要求一个相机一帧。这样的
“门禁通过”没有统一含义，也可能通过重复同一张图凑足样本数。

本轮将最低验收标准固定为项目文档原先建议的正式口径，并新增唯一原图哈希门禁。清单仍可使用
更严格阈值，但不能降低标准或缩小相机范围。

## 不可放宽的最低标准

| 项目 | 最低要求 |
| --- | ---: |
| 平均 ego IoU | ≥ 0.85 |
| 单样本 ego IoU | ≥ 0.75 |
| 候选误纳 person | ≤ 0.02 |
| 候选误纳 floor | ≤ 0.02 |
| 每路相机样本数 | ≥ 5 |
| 必测相机 | camera0、camera1、camera2、camera3 全部 |

任何清单若降低 IoU、放宽误纳率、减少每相机样本数或省略任一路相机，会在计算指标前直接拒绝，
不会产生容易被误读的“通过”报告。

## 防止重复样本凑数

- 复核队列必须为每个样本提供有效 `source_image_sha256`；
- 人工收据逐样本绑定原图、候选、ego、person、floor 五类哈希；
- 整个验收集的原图哈希必须唯一；
- 即使候选、真值和收据同步修改，重复原图仍会被拒绝。

由于新增了原图哈希绑定，人工收据明确升级为
`labelagent.ego_human_pixel_truth_receipt.v3`。旧 v2/v1 收据失败关闭，不做静默兼容。

结构要求。这里只验证候选包结构，没有创建人工真值，也没有运行或宣称通过正式指标门禁。
