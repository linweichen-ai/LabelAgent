# Round349：服务重启作用域彻底隔离与旧页面降频

日期：2026-11-20

## 问题补充

Round348 已能通过文件载入代次识别同文件重载，但继续审阅后发现一个极端边界：旧服务若仍处在
载入代次 0，重启后的新服务也从 0 开始，那么路径、相机和代次三项可能同时相同。服务器的大部分
写接口虽然已有三项强绑定，在这一碰撞情况下仍无法区分重启前后的页面。

## 改进

服务启动时不再把载入代次固定为 0，而是使用“启动毫秒时间 × 1024 + 进程号低位”生成正整数基值。
该数值保持在 JavaScript 安全整数范围内，之后每次加载文件仍继续加一。因此：

- 同一进程内，多次加载严格递增；
- 服务重启后，即使恢复同一文件与同一相机，也会得到新的作用域；
- 旧页面提交的点提示、类别配置、人工确认和其他强绑定操作会在服务器侧直接拒绝；
- 页面状态轮询也会主动提示重新同步。

旧页面发现不一致后，轮询从 250 毫秒一次降为 1 秒一次。提示仍会立即出现，但多个旧标签页不再
持续以每秒四次的频率读取服务状态。

## 验证边界

- 新载入代次必须大于 0；
- 新载入代次不得超过 JavaScript 最大安全整数；
- 同文件重新载入必须保持路径和相机不变，同时代次严格增加；
- 推理状态回执中的代次必须与服务器当前作用域一致；
- 浏览器提示期间不得产生人工真值写请求。

本轮不改变模型、候选或人工真值，也不放宽低磁盘门禁。
