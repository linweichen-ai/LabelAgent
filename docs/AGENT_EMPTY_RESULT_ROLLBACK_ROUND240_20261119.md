## 用户现象与真实原因

操作者反馈：“这一帧标好了，但结果没有显示在原图上；昨天是可以显示的。”

服务端过程证据表明，这次不是画布尺寸、图层刷新或结果恢复按钮失效。第78帧的 SAM 首轮实际产生13个候选，随后 GPT/Agent 在6轮复查中连续执行删除，最终把候选数从13降到0。服务器因此正确保存了一个空机器候选列表，页面也就没有轮廓可画。

这暴露出一个产品安全问题：即使 Agent 怀疑所有候选都是误检，也不应该在未经人工确认时让一整帧从“有可见候选”静默变成空白。

## 修复

Agent 在进入复查前保留一份通过几何校验与候选过滤后的 SAM 初稿。如果后续自动修改把整帧删成0个：

1. 恢复这份 SAM 初稿；
2. 将停止原因记为 `empty_result_rollback`；
3. 增加 `agent_empty_result_rollback` 人工复核原因；
4. 明确 `human_review_required`；
5. 仍然只保存为机器候选，不写成人工真值、不批准训练。

单个明显误检仍可由 Agent 删除；只有“原来非空、最后整帧变空”会触发保护。因此它不会把空画面凭空制造出候选，也不会把候选提升为真值。
