# Round519：真实浏览器门禁接入标准一键验收

## 目标

Round518 提供了独立的公开合成自检，但外部复现者仍可能漏装依赖或忘记执行。本轮把它接入既有 Windows 安装和 `verify_checkout.ps1`，使标准复现路径同时覆盖代码、网页逻辑和真实浏览器行为。

## 修改

- `tools/setup_windows.ps1` 在项目 `.venv` 中安装固定的 `tools/requirements-browser-qa.txt`，不污染系统 Python。
- `tools/verify_checkout.ps1` 将 `.venv/Scripts` 放到子进程 PATH，确保 Node 测试调用的裸 `python` 仍是项目环境。
- 网页测试集合加入 Round516–517 草稿逻辑与浏览器验收静态门禁，并在其后运行公开合成真实浏览器自检。
- 公开合成工具新增 `--ephemeral`：输出位于 `.repro/test-temp` 下由标准库创建的随机临时目录，完成后自动清理，不留下重复回执或截图。
- 私有输出边界负例改为显式在仓库根目录创建临时目录，不再依赖操作系统 `TEMP` 恰好位于仓库外。

## 发现并修复的问题

第一次标准集成运行中，171/172项网页测试通过，草稿测试失败。原因是 Node 子进程调用系统 Python，缺少 Pillow；此前单独测试时手工修改过 PATH，未覆盖标准入口。正式脚本现已统一绑定项目虚拟环境。

第一次完整 Python 回归中，1498/1499项通过，1项私有输出负例失败。标准脚本把 `TEMP` 安全隔离到 `.repro/test-temp`，使该测试的“外部路径”实际变成允许路径。测试现改为显式仓库根目录临时路径，仍在结束后自动清理，重新恢复原安全语义。

## 最终验收

直接运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\verify_checkout.ps1
```

最终结果：

- 环境和固定依赖检查通过，`pip check` 无冲突；
- Python 回归共1499项，1498项通过、1项按设计跳过；
- 网页逻辑172/172通过，其中草稿测试实际覆盖39种攻击拒绝；
- 公开合成真实浏览器自检通过，外部请求0、页面错误0；
- 页面、部分草稿、正式合成导出的冻结哈希与 Round518 完全一致；
- 临时模式运行前后残留目录数均为0；
- 训练授权、自动批准和批准训练保持false，真实人工决定写入0。
