3.2 时间戳一致性实验（阳性缺陷）

脚本：tools/audit_signoff_timestamp_parity.py（隔离分支提交 39b8579）。使用合成 81 项构建页面，从 HTML 提取内嵌 JS 的 validTime，与 Python 导入器的 _valid_timestamp 对同一组 17 个向量比对。

输入页面正式导入器影响
2026-02-30T12:00:00+08:00放行拒绝页面允许正式导出，导入整包失败。
2026-11-22T24:00:00Z放行拒绝同上。
2026-11-22T12:00:00.1234567Z放行拒绝小数秒超出导入器约束。

其余 14/17 向量一致。另做端到端复现：81 项其他字段完整，只将时间戳设为以上任一值，页面仍导出成功，正式导入器拒绝，3/3 可复现。结论：idea 的风险成立，但修复尚未完成，不能宣称“已 work”。

4. 当前核心 idea 与验证状态

核心 idea：人工复核 UI 的输入校验必须与正式导入器使用同一规范/测试向量；页面可用性检查不能比下游导入门禁更宽松。性质：对任何页面允许导出的 payload，都必须通过导入校验器（export ⇒ import accepted）。

状态：风险已在实验分支版本中验证，idea 作为工程要求成立；本次未重新核对最新主线的时间戳实现，不能断言最新主线尚未修复。历史实验存在 3 个反例，应先复核最新代码，再决定是否需要修复及补测。

推荐实现优先级：不要维护两套独立正则/日期解析。优先定义一份规范并生成共享测试向量：严格日历日期、小时 00–23、分钟/秒有效、偏移合法、最多 6 位小数秒、必须有时区。若无法让浏览器和 Python 共用运行时代码，则共享 JSON vectors，双端测试同一组 vectors。
