# 栈板像素真值与微调准备度复核（Round 718）

日期：2026-11-23

## 一句话结论

当前不是“完全没有人工复核像素”，但仍没有可直接启动正式 SAM3 微调的数据集。正式工作台内有 6 个唯一帧、48 个栈板轮廓仍与 v2 人工复核收据逐哈希匹配；它们全部是 `split=unassigned`、`training_return_allowed=false` 的工作台真值候选。006/008 两张密集栈板硬例与这些候选的图像 SHA 交集为 0，因此不能据此宣称已经具备针对硬例的人工监督。

本轮只读，没有修改正式工作台、人工真值、训练集、OSS 或模型，也没有启动 GPU 训练。

## 为什么旧口径和新口径并不冲突

文档中的 `0/96` 专指冻结的 `train72/test24` 训练门：96 张图没有完整人工签核与可用的 `human_verified` COCO。这不等于工作台从未进行过任何人工复核。

Task3 原始导入仍是另一条边界：150 帧、1550 个形状中，1469 个来源为 `auto`，81 个来源为 `manual`；这 81 个全部是栈板实例，但每个所在帧仍混有自动形状，完整全人工帧为 0，独立签核为 0/81。未标物体必须保持 `ignore`，不能把画面其他区域当成负样本。

## 006/008 困难帧覆盖

当前密集冲突硬例为：

- 006 / `1789899601982497364` / camera_1；
- 008 / `1789899778882397075` / camera_1。

两张图与 10 条工作台复核收据的 frame SHA 交集为 0，与 Task3 81 个 manual-source 实例清单的 image SHA 交集也为 0。由于 Task3 使用 JPG、Round 674 使用 PNG，文件 SHA 零交集只作辅助证据；更强的身份核对是 Task3 的 81 个 `source_timestamp_ns` 与 006/008 的 frame ID 交集同样为 0，工作台复核来源作用域也不包含这两个帧身份。现有证据是人工 3D 框、投影、LiDAR 几何、SAM 候选和助手诊断，不是人工像素真值。

006/008 已被反复用于开发诊断，因此即便后续补齐真值，也只能作为训练/开发困难集，不能再承担最终未曝光测试集角色。

## 当前训练决定

- 正式 SAM3 小样本微调：**不启动**；
- 原因：训练批准为 0、split 未分配、006/008 像素真值为 0、独立未曝光 holdout 缺失；
- 候选级技术烟测：可以隔离进行，但必须保持 `human_truth=false / approved_for_training=false / production_deployed=false`，且不能据此宣称人工监督微调有效；
- 已知风险：此前用 71 个助手通过的 Task3 候选做训练，跨序列验证退化，已经否决且未部署。

## 最小可执行下一步

1. 对 48 个当前哈希匹配候选逐帧明确分配 train-only 或保留，并单独授权训练回流；在另行完成实例穷尽性和负空间签核前，只允许 positive-instance loss，实例外及其他未标像素全部保持 ignore，禁止 full-frame semantic loss 和负采样；
2. 对 Task3 81 个 manual-source 栈板实例完成哈希绑定签核；
3. 为 006/008 各精修真实像素实例，未标区域全部设为 ignore；
4. 按完整序列/时间组划分 train/dev，继续冻结 test24；
5. 另建从未用于提示、阈值和候选筛选的外部 holdout，之后才启动 SAM3 mask decoder/LoRA 小样本实验。
