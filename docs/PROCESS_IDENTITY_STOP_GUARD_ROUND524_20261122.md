# Round524：停止操作的进程身份门禁

## 问题

旧版停止脚本只读取 `.repro/processes.json` 中的 PID。Windows 在进程退出后可能复用 PID；如果记录陈旧，仅凭 PID 停止会存在误伤后来无关进程的理论风险。

## 修复

新启动记录升级为 `labelagent.local-process-record.v2`，为每个本轮子进程保存：

- PID；
- 服务角色（SAM3 或工作台）；
- UTC 创建时间；
- Python 可执行文件绝对路径；
- 当前克隆根目录。

停止脚本会先完整验证全部存活目标，再执行任何停止动作：

- 记录必须属于当前克隆；
- PID 不得重复，角色必须属于允许集合；
- 实际 Python 路径、记录路径和当前克隆虚拟环境必须一致；
- 实际进程创建时间必须与记录一致；
- 老格式记录只在克隆根目录、Python 路径和受限创建时间窗均匹配时兼容；
- 任一身份无法读取或不匹配时，失败关闭并保留记录供检查。

## 真实负例

在确认当前克隆没有受管进程记录后，临时构造一份记录，把一个正在监听但属于其他环境的既有工作台进程伪装成本克隆受管进程。停止脚本拒绝执行并报告可执行文件不匹配；该无关进程保持存活，临时记录保持原样。测试后临时记录已删除。

该负例没有停止、重启或修改既有工作台，也没有访问模型权重或真实标注数据。
