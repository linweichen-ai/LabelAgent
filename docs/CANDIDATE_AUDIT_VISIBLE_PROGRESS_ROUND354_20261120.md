# 第 354 轮：高风险复核可见进度与系统盘稳定化

## 本轮解决的问题

自动候选已经能够先显示，但用户过去只能看到“正在复核”，无法判断后台是在批量处理、串行处理、等待人工，还是反复重试。因此一旦耗时变长，使用感受仍像“卡住”。

本轮把高风险类别复核拆成四个可见计数：

- **批量**：已经通过三目标独立批审完成的候选数；
- **串行**：没有组成三目标批次、正常单独完成的候选数；
- **需人工**：模型结论为不确定、冲突、低置信或改判其他类别的候选数；
- **实际重试**：批量协议失败后的额外单项调用，加上单项协议内部的额外调用次数。

页面阶段名称也从过窄的“疑似箱体栈板”改为“高风险类别候选”，现在能准确覆盖 person、ego、other_robot 和特殊 pallet。

## 页面显示方式

运行到该阶段时，进度区会显示类似：

> 高风险类别已复核 3/3；批量 3 · 串行 0 · 需人工 1 · 实际重试 0

这组信息只说明后台处理路径，不把机器判断包装成人工结论；“需人工”候选仍必须由人确认，系统不会自动删除候选、写入人工真值或批准训练。

测试期间，Windows 运行时临时虚拟盘持续扩张，C 盘一度降到约 134 MiB。单纯压缩无法保持安全余量，因此将下面这一份历史产物归档迁到 D 盘：

- 原路径：`C:\Users\seer\AppData\Local\LabelAgent\artifact-archive`；
- 新物理位置：`D:\Apps\LabelAgent\.local\archives\artifact-archive-c-volume-20261120`；
- 文件数：1055；
- 校验：迁移前后逐文件长度和 SHA-256 全部一致；
- 兼容：原路径保留为目录联接，现有程序和文档无需修改；
- 可逆：将目标目录移回并移除目录联接即可恢复原布局。

该操作没有移动或删除生产模型、数据集、机器候选、人工真值或备份。完成后 C 盘约 336 MiB，D 盘约 1.36 GiB；D 盘仍低于 2 GiB 告警线，管理器会继续只读提示，不自动删除下载残片。
