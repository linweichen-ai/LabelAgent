# Round792：远程工作台安全通道故障恢复验收

## 目标

验证 Windows 到 Linux 工作台的 SSH 安全通道意外退出后，可以由受管连接脚本自动恢复，同时在打开页面前重新检查网页、SAM3 和 Qwen8B。测试只操作独立端口和独立运行记录，不停止正式 `18765` 通道。

## 实现

`connect_remote_workbench.ps1` 和 `disconnect_remote_workbench.ps1` 新增可选 `RuntimeDirectory`。默认仍使用仓库 `.repro`，原有用户不需要修改命令；需要并行连接或隔离验收时，可让每条通道使用独立记录目录，避免覆盖正式隧道身份。

连接脚本继续执行以下门禁：

1. 远端网页端口必须先通过只读检查；
2. 本地通道建立后，`/api/run/status` 必须可达；
3. `/api/model_readiness` 必须同时确认总状态、SAM3 和 Qwen8B ready；
4. 旧记录对应进程不存在时，旧记录改名为 stale，再建立新通道；
5. 已登记进程存在但网页不可达时，只允许回收命令行身份匹配的受管 SSH 进程；
6. 页面可达但模型未就绪时保留通道并失败关闭，不打开无法推理的页面。

测试端口为 `18767`，独立记录目录为 `work/round792_tunnel_runtime`。

本轮没有启动模型推理、写候选、写人工真值、写训练批准或使用 test24。

## 清理说明

受管断开脚本已经删除活动记录并关闭测试隧道。独立目录中只剩一份 310 字节的 stale 故障记录：

`work/round792_tunnel_runtime/remote-workbench-tunnel.json.stale.20261124T092918Z`

自动清理该记录的命令被本机执行策略拒绝，因此本轮没有改用跨 Shell 或绕过策略的删除方式。该文件只包含测试 PID、端口和时间，不含密钥、数据或图片；保留它不影响运行，也不纳入 Git。

## 结论

独立测试证明受管 SSH 通道进程意外消失后，连接脚本会更换 PID、重新建立通道并重新验证页面、SAM3 与 Qwen8B。当前证据覆盖“进程退出”故障；网络长时间抖动、服务器重启和模型服务单独失效仍需分项验证。
