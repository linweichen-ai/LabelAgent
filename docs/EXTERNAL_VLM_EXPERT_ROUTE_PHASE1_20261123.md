# 外部视觉专家模型接入第一阶段（2026-11-23）

> 历史阶段说明：本文件记录第一阶段基线。多协议适配已在第二阶段完成，最新边界见 `EXTERNAL_VLM_EXPERT_ROUTE_PHASE2_20261123.md`。

## 目标

在不改变现有本地 Qwen8B 主路径、不发送任何真实工厂图像、也不保存 API Key 的前提下，为后续 `qwen3-vl-plus` 等外部视觉模型建立显式专家通道。该通道用于困难帧复核，不是默认替换本地模型。

## 已实现

- 新增 `chat_external_expert()`。只有 `llm_expert_enabled=true` 且 URL、模型、协议、密钥环境变量名完整时才允许调用。
- 第一阶段支持 `openai_chat` 协议，覆盖阿里百炼等 OpenAI Chat Completions 兼容服务。
- 密钥只从 `llm_expert_key_env` 指定的环境变量读取；配置接口明确拒绝 `llm_expert_key` 原始密钥字段。
- URL 禁止内嵌用户名或密码；环境变量名只接受大写字母、数字和下划线。
- 专家配置从调用前的配置副本构建，不修改正式配置；同时移除所有 `llm_fast_*` 字段，避免专家请求误走本地快速模型。
- 模型就绪接口只报告专家通道是否启用、配置是否完整及环境变量是否存在，不主动连接外部服务，也不会因为专家未就绪阻断本地 SAM/Qwen8B 工作台。
- 追踪记录只保存模型名和路由，不保存 API Key 或图像 Base64。

## 验证

定向回归覆盖：

1. 专家路由只访问配置的 `/chat/completions`；
2. 配置对象不被修改；
3. 本地快速通道不会被联系；
4. API Key 不进入追踪记录；
5. 未显式启用或缺少环境变量时在联网前失败关闭；
6. 未知协议、URL 内嵌凭据和原始密钥字段被拒绝；
7. 就绪检查不主动访问外部 API；
8. 外部专家状态不影响本地主路径 readiness。

结果：`8 passed, 278 deselected`；Python 编译和 `git diff --check` 通过。

## 当前边界

- 本轮没有配置或读取真实 API Key。
- 没有发送公开图、脱敏图或工厂图到外部服务。
- 没有运行真实外部模型，因而没有延迟、费用或分割质量对比结果。
- 当前仅支持 OpenAI Chat Completions 兼容协议；OpenAI Responses、Claude Messages 和 Gemini 原生协议仍待后续适配。
- 尚未把专家通道接入自动困难帧判断；当前必须由明确调用者主动选择。
- 未部署到正式 `D:\Apps\LabelAgent`，未修改模型权重、人工真值、训练集或 `test24`。

## 下一步门禁

1. 用户选择供应商并在本机环境变量中配置密钥，不在聊天、代码、日志或仓库中传递密钥。
2. 先使用一张公开或脱敏图片完成连通性测试，核对响应结构、超时、Token 和费用。
3. 再建立固定困难样本影子 A/B；外部模型只给出助手级复核，不写人工真值。
4. 只有在类别、协议成功率或候选修改质量有可复现实测提升后，才设计自动困难帧路由。
