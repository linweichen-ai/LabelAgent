# Round404：正负提示组共享一次图像编码

## 为什么做

Round402 的 ego 影子评测对同一帧发送 3 次 SAM 点提示。每次请求都使用 1 个组件正点和同一组 3 个地面负点，得到的高质量候选在 15/24 帧上平均 IoU 为 0.922，但逐请求会重复编码同一张图。已有 `/segment_points_batch` 只支持互相独立的单个正点，不能表达这些正负点组合，因此不能直接替换。

## 本轮改变

- 新增 `segment_prompt_groups`：一张图只执行一次 `set_image`，随后独立计算最多 64 组提示；每组仍遵循原有 1～32 个正负点契约。
- 新增本地与远端 `/segment_point_groups_batch` 路径，并让工作流把它路由到专用点提示 SAM 服务。
- 在任何模型工作前验证全部输入；无效坐标、无正点、非法标签或超量输入整批拒绝。
- 某一合法组没有产生轮廓时只记录该组错误，不丢弃同批其它成功结果。
- 没有改变原 `/segment_points` 和 `/segment_points_batch`，所以旧页面和正式调用保持兼容。

## 验证结果

- 新旧语义等价单元测试通过：同一组提示的轮廓、孔洞、分数和警告与逐次 `segment` 完全一致。
- 两组提示时，旧路径编码 2 次，新路径编码 1 次；推广到 Round402 的 3 个组件即从 3 次降为 1 次。这里只证明编码次数下降，不把它冒充真实 GPU 端到端耗时结论。
- 定向测试：11 项通过，另有 4 个输入子用例通过。
- 全量 Python：1275 项通过，另有 223 个子测试通过。
- 网页 Node：167 项通过。
- `git diff --check` 通过。
- 正式 SAM 健康，`model_loaded=true`、`in_flight=0`。正式状态、候选、真值和最近运行文件的 SHA-256 与本轮前一致。

## 隔离 4090 真实 A/B

候选服务随后部署到 4090 的临时目录和临时端口，使用与正式服务相同的权重，在 Round402 冻结的 24 帧上比较“3 次逐组请求”和“1 次三组批请求”。参考帧只用于冷启动预热，不计入测量。

| 指标 | 逐组请求 | 组批请求 |
| --- | ---: | ---: |
| 中位耗时/帧 | 0.885 秒 | **0.293 秒** |
| P95 耗时/帧 | 1.324 秒 | **0.357 秒** |
| 中位加速 | — | **3.02×** |

24/24 帧的三组结果逐字段完全一致，24/24 帧的成功/失败数量一致；每个候选响应都确认只编码一次图像。首次冷启动超过 30 秒并产生一次客户端超时，模型随后完成加载；该次不计入正式测量，说明部署验收必须把冷启动和热态推理解耦。

隔离服务、临时 tmux 进程和本地 SSH 通道已在测量后关闭，GPU0 显存从 12.8 GiB 回落到 8.3 GiB；正式 28766 服务继续健康。详细本地结果为 `artifacts/round404-point-group-real-ab-20261122/results.json`，SHA-256 为 `E35B0FD1877BC57AE5F8B83761FB904F15888856DA526279DBAAF490AB2FA72A`，不包含原始图像。

## 当前边界与决定

本轮仍是隔离候选，不是正式部署。真实 GPU 等价与速度门禁已经通过，但当前 4090 正式服务仍是 `labelagent.remote-sam3.v2-exact-response-cache`，没有重启或替换；正式工作台也还没有调用新接口。不批准训练或自动真值。

下一步是做可回滚接入：先备份远端点提示服务和本地调用代码，部署新接口但保持旧接口不变；健康检查和契约探针通过后，让参考几何候选路径使用组批接口。若新接口不可用，调用方必须显式回退到逐组请求，且不能吞掉质量错误。
