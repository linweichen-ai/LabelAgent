# Round742：栈板 ROI 尺度与去绝对颜色先验的 v8 影子候选

## 结论

v8 已经在真实新增候选上产生首批非零修改，但仍是**影子候选**，没有部署，也不能宣称质量
已经提升。16 帧中的 164 个机器栈板候选里，53 个通过“局部 ROI + 绝对像素”尺度门，最终
只有 2 个通过全部图像证据和结构保护门，分别只新增 9、31 个像素。

这两处修改没有删除原前景、没有合并实例、没有改变组件数，且两次隔离重复回放的 manifest SHA
均为 `2eeaaa793a5374c31f9913978aca4e8ac8de3cdb4ce74a17e3438209e1be5771`。
人工真值 frame 0 的 11 个固定匹配栈板全部保持不变，指标零回退，但因为真实变化没有落在
该人工真值作用域，`development_gate_passed=false`。

## 这次改了什么

旧 v7 要求单个候选至少占整幅图像 30%。在 1920×1536 的多实例工厂画面里，164 个候选没有
一个能通过。v8 没有直接降低这个整图比例，而是增加一个更保守的局部门：

- 候选面积至少 4096 像素；
- 候选框面积至少 8192 像素；
- 候选框宽至少 96 像素、高至少 24 像素；
- 仍要求局部缺口与相邻栈板表面相似；
- ROI 路径不再要求“表面必须明亮、低饱和”，因此蓝色、灰色等栈板也可评估；
- 仍保留 add-only、授权区域、零组件合并、1% 且最多 256 像素预算、结构孔 100% 保留。

这里的“去绝对颜色先验”不是不使用颜色信息，而是取消明亮木色这一绝对前提；证据仍来自缺口与
同一实例邻域的局部连续性。

## 决策

1. v8 只进入版本库作为可复现的影子实验能力，默认 `full`/v6 和 v7 行为不变；
2. 两处真实变化进入候选复核，不自动写人工真值、训练集或正式工作台；
3. 下一步需要在更多带独立真值的大栈板实例上检验 IoU 与 BF1@1px，不能用 frame 0 的 no-op
   代替有效性证据；
4. 若新增像素在真值上造成误扩张，优先增加边缘/深度证据门，而不是继续放宽尺度或颜色门。
