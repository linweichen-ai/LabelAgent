# 参考帧起稿服从当前人工导航：Round 217

## 一句话结论

参考帧起稿读取较慢时，如果操作者已经切到另一帧、相机或数据集，旧起稿现在会被安全取消，不再在新画面上激活旧帧的多边形、SAM 点提示或机器草稿；正常操作仍会准确进入目标帧。后台 Agent 精修和高风险类别复核也只允许更新原来的数据集、相机和帧。

## 修复前的问题

参考准备助手有四种入口：复用机器候选、复用历史标注、SAM 点提示起稿、手工多边形起稿。它们都会先异步读取目标帧，再打开相应编辑工具。

修复前真实浏览器复现如下：

1. 正式页面位于 SFL camera 1 第 74 帧；
2. 对空白第 0 帧开始“手工多边形起稿”，并把第 0 帧图片读取人为延迟 600 ms；
3. 读取期间，操作者明确切到第 1 帧；
4. 页面最后虽然停在第 1 帧，但旧第 0 帧起稿仍返回成功；
5. `referencePreparationIntent` 错误绑定第 0 帧，多边形工具在第 1 帧被激活，并显示“已进入多边形绘制”。

| 项目 | 修复前结果 |
|---|---|
| 页面最终帧 | 1 |
| 旧起稿目标帧 | 0 |
| 旧起稿返回 | 成功 |
| 页面起稿意图 | 第 0 帧、`manual_polygon` |
| 多边形工具 | **错误激活** |
| 人工真值写请求 | 0 |
| SAM/VLM 请求 | 0 |

这不会立即写入真值，但会把旧帧意图叠到当前帧，操作者继续编辑或保存时容易造成误操作。

## 修复方式

### 1. 四种起稿统一冻结作用域

每次起稿都记录发起时的数据集路径、相机和导航代次。只有目标帧真实打开，而且数据集、相机和帧仍全部一致，才允许进入编辑状态。任何一项变化都会返回：

> 您已切换到其他帧、相机或数据集，本次参考起稿未进入

机器候选和历史标注先暂存在局部变量中，目标帧确认打开后才写入当前浏览器草稿，避免旧异步结果提前污染页面内存。

### 2. 参考意图同时绑定数据集路径

旧参考意图只依赖相机和帧。本轮加入数据集路径，收尾引导必须同时满足：

- 当前数据集等于起稿数据集；
- 当前相机等于起稿相机；
- 当前帧等于起稿帧。

因此不同数据集恰好有相同相机名和帧号时，也不能误复用旧意图。

### 3. 后台精修与类别复核服从人工当前操作

机器候选进入页面后，Agent 精修或高风险类别复核可能仍在后台运行。回调返回时会重新核对起稿意图、数据集、相机和帧。操作者已经离开目标作用域时，后台结果只保留在候选/审核记录中，不重置当前选择、不覆盖草稿、不显示过时成功或失败提示。

### 4. 修复正常起稿的时间轴对齐

第一次部署验收抓到保护条件过严：并发切帧已正确拦截，但在普通图像窗口中打开目标帧后，旧 `clockTime` 会让控制条把帧号又改回原帧，导致正常起稿也被拒绝。

本轮没有忽略这个失败，而是把参考目标帧与时间轴先对齐，再读取图片和更新控件。资源版本由 v172 提升到 v173。最终结果是：旧并发请求被拒绝，正常起稿成功，两者同时成立。
