# Round 854：外部专家授权防重复消费账本

## 风险

Round 853 已将授权与数据、接口和模型精确绑定，但旧执行器的结果去重主要依赖指定输出目录和进程内缓存。如果操作者换一个输出目录，或删除结果文件后重跑，同一授权理论上仍可能再次发出付费请求。

## 修复

新增跨进程持久化授权账本，默认位于当前账户的 `.labelagent/external-authorization-ledger`，也可通过 `LABELAGENT_EXTERNAL_AUTH_LEDGER_DIR` 或 `--ledger-dir` 指定服务器持久目录。

执行流程现在为：

1. 用授权文件 SHA-256 建立唯一账本目录；
2. 将该授权绑定到唯一输出目录；
3. 每张图像在模型或网络调用前，按运行名称、样本 ID、源图哈希和实际上传图哈希建立原子占位；
4. 占位已存在时拒绝重复请求；
5. 结果文件被删除、输出目录被替换或两个进程同时请求时，仍然失败关闭；
6. 组合运行收据记录账本会话哈希和已占位调用数，但不记录图片、API Key 或其他凭据。

账本文件使用排他创建，Windows 与 Linux 共用相同实现。异常退出如果发生在占位之后、结果落盘之前，会保留占位并阻止自动重试；这会牺牲一次授权额度，但不会造成静默重复付费。

## 验证

- 授权、账本、组合执行和准备状态相关定向测试：38/38 通过；
- 项目全量回归：`2077 passed, 1 skipped, 294 subtests passed`；
- 同授权换输出目录：请求前拒绝；
- 删除结果后重跑：请求前拒绝；
- 两线程同时占位：仅一个成功；
- 损坏账本：失败关闭；
- 账本占位先于模型/网络调用：已验证；
- 外部 API 调用：0；
- `test24` 使用：0；
- 正式部署：否。

## 当前边界

账本防止同一机器、同一账户下的意外重复消费。若人工把授权文件复制到另一台没有共享账本的机器，仍需依靠运行规范避免重复；正式服务器部署时应把账本目录放在持久卷中。34 帧人工复核和真实图片外发授权仍未完成，因此三路效果比较保持关闭。
