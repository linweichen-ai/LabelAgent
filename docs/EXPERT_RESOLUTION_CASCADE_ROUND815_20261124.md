# Round815：外部专家动态分辨率级联

## 目的

固定使用 640×512 的外部专家较慢；固定使用 512×410 又可能损失画面边缘斜坡、遮挡目标和托盘细节。本轮新增一个离线评测方案：困难帧先看 512×410，只有结果仍不可靠时才升级到原始 640×512。

该方案不是新的线上部署。它只复用 Round814 已规划的两份外部结果，不增加图片外发，也不新增 API 调用。

## 升级条件

512×410 结果满足任一条件时升级：

1. 总体置信度低于可配置阈值，默认 0.85；
2. 任一类别为 `uncertain`；
3. 存在类别冲突或未知类别；
4. 斜坡为边缘局部、遮挡或不确定；
5. 托盘质量不确定；
6. 与本地 Qwen8B 在 slope/floor、车辆/other_robot/ego、pallet/cargo_floor 上不一致；
7. 与本地 Qwen8B 的托盘实例数不一致。

每帧都会保留升级原因，便于检查路由是否合理。外部失败时的正式回退仍由现有外部专家调用层处理；本工具本身不发请求。

## 评测口径

新增工具：`tools/evaluate_expert_resolution_cascade.py`。

在34张开发困难帧上模拟：

- 非困难路由帧：采用本地 Qwen8B；
- 17张混合路由帧：先采用512×410结果；
- 触发升级的帧：最终采用640×512结果；
- 延迟同时计入本地、低分辨率首轮及必要的高分辨率升级；
- Token 与调用次数按真实两阶段调用累计。

输出仍固定为：

- `candidate_only=true`
- `human_truth=false`
- `approved_for_training=false`
- `test24_used=false`
- `deployment_gate_passed=false`

## 同时修复的问题

真实本地 Qwen8B 结果使用 `copied_image_sha256` 绑定图片，而旧三路评测器只读取测试夹具中的 `source_image_sha256`。本轮兼容真实字段，并在两个字段同时存在但互相矛盾时拒绝评测，避免拿错图片仍得到分数。

## 当前结论

代码和离线门禁已完成，但没有把该策略称为更优结果。最终是否节省时间且不损伤斜坡召回，必须等人工复核集完成、真实图片外发获得明确授权后，使用同一批 Round814 结果计算。当前不部署。

验证结果：定向测试26项通过；在测试进程显式使用 UTF-8 并移除宿主注入但不完整的临时 Git 配置后，项目正式 `tests/` 测试集为1966项通过、1项跳过、294项子测试通过。直接从仓库根目录无约束搜集测试会误收集 SAM3 的可视化演示脚本，并因可选的 `matplotlib` 未安装而停止，故不作为正式测试命令。
