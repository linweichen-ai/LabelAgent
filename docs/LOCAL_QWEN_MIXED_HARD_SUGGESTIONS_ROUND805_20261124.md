# Round805：34张困难帧本地Qwen8B辅助建议与混合路由投影

## 目标

在不调用外部 API、不写人工真值、不使用 test24 的前提下，让服务器 Qwen8B 对 Round779/803
的34张困难开发帧独立给出机器建议，并验证这些建议能否支持“本地优先、困难帧再交给外部专家”
的路由策略。

## 实现

新增 `tools/run_local_qwen_mixed_hard_suggestions.py`：

- 同时校验34帧清单、工作区回执和每张复制图像的 SHA-256；
- 不向模型提供 cohort、旧复核说明或人工答案，避免提示泄漏；
- 每帧原子保存，支持断点续跑；
- 结果保存为单独的 `assistant-suggestions.json`，不预填人工裁决模板；
- 每行固定保留 `candidate_only=true`、`human_truth=false`、
  `approved_for_training=false`、`test24_used=false`；
- 根据语义不确定、类别冲突和未知类别生成不上传图像的专家影子路由建议。

首次试运行要求8类逐项输出理由，Qwen结果在约300字符处截断并产生无效 JSON。该失败被记录，
没有写入可用建议。随后把响应压缩为8类存在性、总体置信度、斜坡几何、托盘质量、冲突和困难
标志；同一帧复测成功后才继续整批。

## 实测结果

| 项目 | 结果 |
|---|---:|
| 样本 | 34张困难开发帧 |
| 成功 / 失败 | 34 / 0 |
| 中位延迟 | 4701.896 ms/帧 |
| P95延迟 | 5010.241 ms/帧 |
| slope判为存在 / 不确定 / 不存在 | 0 / 16 / 18 |
| 4张slope正候选 | 4张全部“不确定” |
| 3张Batch-B ramp候选 | 3张全部“不存在” |
| pallet质量“不确定” | 32/34 |
| 混合路由建议外部复查 | 17/34（50%） |
| 本地结果足够 | 17/34（50%） |
| 实际外部 API 调用 | 0 |

这里的“正候选”和“ramp候选”仍来自既有助理候选清单，不是人工真值，因此不能据此计算真实
精确率或召回率。结果只能证明：本地 Qwen8B 在这批困难帧上经常显式不确定，并且会漏报若干
已有斜坡候选，不能单独承担困难帧裁决。

同时发现总体置信度为0.90–1.00，但斜坡和托盘专项仍大量输出“不确定”。因此路由器新增
`priority_semantic_uncertainty` 硬信号：只要 slope、pallet、车辆、other_robot、cargo_floor
等重点类别显式不确定，即使标量置信度偏高，也推荐进入外部专家影子复查。该信号不重复增加
难度分，只负责避免错误的高置信度压制升级条件。

## 验证与边界

- 新工具边界测试：3 passed；
- 路由器和辅助建议定向测试：14 passed；
- 输出 SHA-256：
  `b0bff89db15a664d0e6bae1ce1a06b3a357b89c7efd3825b517e4a90051c8b1b`；
- 图像只经临时 SSH 回环通道传给自有 `factory-5090` Qwen8B；通道完成后已释放；
- 没有外部 API 上传、没有修改正式工作台状态、没有部署、没有写人工真值或训练批准。

下一步仍需人工完成34张裁决，才能在同一真值上计算“仅本地、全部外部、混合路由”三种方案
的真实质量、延迟和成本指标。
