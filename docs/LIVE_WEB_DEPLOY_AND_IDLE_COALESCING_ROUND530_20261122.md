# Round530：网页原子更新与启动轮询合并

## 目标

本轮继续解决“工作台能用，但首次打开不够丝滑”的问题，同时把正式网页更新从人工复制改为可验证、可回滚的原子流程。全程不启动真实推理、训练，不写人工真值，也不停止正式工作台进程。

## 实测发现

Round529 已消除主工作台与顶部向导对运行状态的长期重复轮询，但首次真实 Edge 验收仍发现启动阶段存在请求突发。32 秒空闲窗口内：

| 项目 | 首轮实测 | 目标上限 |
| --- | ---: | ---: |
| `/api/run/status` | 5 | 4 |
| `/api/state/summary` | 7 | 4 |
| 页面错误 | 0 | 0 |
| 外部请求 | 0 | 0 |
| 受保护写请求 | 0 | 0 |

进一步合并后，第二次隔离真实 Edge 验收为：

| 项目 | 修复后实测 | 目标上限 |
| --- | ---: | ---: |
| `/api/run/status` | 4 | 4 |
| `/api/state/summary` | 2 | 4 |
| 页面错误 | 0 | 0 |
| 控制台错误 | 0 | 0 |
| 外部请求 | 0 | 0 |
| 受保护写请求 | 0 | 0 |

摘要请求从 7 次降到 2 次，下降约 71%；这来自真实浏览器网络记录，不是只调整测试阈值。

## 实现

- 主页面首次运行状态请求暴露为可等待的共享就绪结果；
- 工作区恢复优先复用该结果，仅在数据文件、相机或载入代次不一致时补读；
- 顶部向导在工作区恢复完成前只登记“需要刷新”，不立即连续请求摘要；
- 工作区完成事件与恢复 Promise 竞争时只允许一条首次摘要读取；
- 焦点、页面恢复和候选事件仍保留 1 秒合并窗口；
- 新增只读真实浏览器空闲轮询门禁，禁止外部请求和受保护写请求；
- 新增网页原子部署脚本：只允许三个明确网页文件，部署前验证源版本与目标旧版本，未知本地差异直接拒绝，写入后逐文件读回，失败自动回滚；
- 页面版本提升到 `168`，资源版本为 `app.js 205`、`guide.js 119`。

## 验收

- 完整 Python 回归：1523 项，1522 通过，1 项按设计跳过；
- 完整网页逻辑：174/174 通过；
- 本轮新增向导启动合并测试后，定向网页逻辑：91/91 通过；
- 网页部署与空闲验收工具定向 Python：6/6 通过；
- 隔离真实 Edge 32 秒空闲验收通过：运行状态 4 次、摘要 2 次；
- 外部请求 0、受保护写入 0、HTTP 错误 0、页面错误 0、控制台错误 0；
- 正式工作台部署必须在本提交固化后使用原子脚本执行，并另行读回版本、文件摘要和正式进程 PID。

## 边界

本轮优化的是网页稳定性、启动请求合并和部署可回滚性，不等价于分割质量提升，也没有启动微调或后训练。机器候选仍必须经过人工门禁后才能成为真值。
