# Round 783：Linux服务器全托管架构

## 目标

将网页后端、SAM3和本地VLM全部部署在Linux GPU服务器，本机仅通过浏览器访问，不再依赖本地Python后端或本地模型进程。

```text
本机浏览器
    │
    └── SSH安全隧道
            │
            └── Linux工作台 127.0.0.1:18765
                    ├── SAM3 127.0.0.1:18766
                    └── Qwen8B 127.0.0.1:18878/v1
```

## 服务器选择

只读比较双4090与双5090后，选择双5090作为首个全托管节点：

- 双5090系统盘可用约911 GiB；双4090系统盘可用约171 GiB；
- 双5090现有SAM3与Qwen8B服务均由`clw`用户运行；
- 双5090的8765端口已由另一位用户的工作台占用，因此不得抢占或停止；
- 新版`clw`工作台使用空闲的127.0.0.1:18765，并通过SSH隧道提供给本机浏览器。

## 本轮代码调整

1. `start_linux.sh`新增可配置工作台端口、本地VLM和快速VLM参数；
2. 启动记录保存实际端口和模型端点，`status_linux.sh`按记录回读；
3. 网页后端可从环境变量读取VLM默认配置，但不会覆盖已经持久化的人工配置；
4. 新增Windows一键连接和断开脚本，隧道只转发单个工作台端口；
5. 默认仍只监听服务器回环地址，不把没有身份认证的Flask服务直接暴露到局域网或公网；
6. 正式工作台、人工真值、test24和模型权重均未因本轮代码修改而改变。

## 验收门槛

完成部署后必须同时验证：

- 服务器工作台、SAM3、VLM三项readiness均为true；
- 本机通过隧道读取页面和`/api/run/status`；
- 一帧授权开发数据能够完成候选生成并显示叠加结果；
- 停止隧道只影响本机连接，不停止服务器模型；
- 服务器重启脚本只管理当前`clw`发布目录登记的进程；
- 不触碰其他用户的8765进程。
