# 先写证据的 Agent 自主工具决策对照

复用两帧已绑定图片字节的真实 SAM3 候选和相同未确认功能参考；每帧分别使用自然候选与一个已知人员→托盘的错类对照，两策略交错，共 8 次新本机 2B NF4 复查。没有重新生成 SAM3、指定正确工具/类别、强制 continue，或将分类适配器当成自由决策。

唯一输入变化是追加通用序列化要求：先写原 reason，再写 status 和其余原字段。图片、原提示前缀、完整 schema、工具、ID、模型及默认 256 预算保持。原语法实际允许 reason 首字段，干预组 4/4 真实响应确实先写 reason，不能把“没有执行干预”解释为失败原因。

| 策略 | 自然候选保持 | 已知错类实际恢复并再复查 | 实际编辑 |
| --- | --- | --- | --- |
| 原始 | 2/2 | 0/2 | 0 |
| 先写证据 | 2/2 | 0/2 | 0 |

两组都返回 done，但没有修正已知错类。该实验否定“只改变结论与证据的输出顺序即可解决当前工具决策”的假设，没有提升自然帧指标，不启用新提示。生产工作流、schema、数据和工作台状态均未改动。[脱敏结果](evidence_order_results.json)

复现：`tools/evaluate_evidence_order.py` 使用独立输出目录、真实服务身份检查、四对原输入指纹、原语法指纹、实际字段顺序和逐轮工具执行记录。max-rounds=3，正常 done 仍允许。参考是未确认功能示例；受控恢复与真实自然错误修正分别计数。
