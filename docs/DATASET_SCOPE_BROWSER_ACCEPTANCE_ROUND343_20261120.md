# Round343：新数据集界面、八类覆盖与跨会话隔离验收

日期：2026-11-20  
状态：隔离浏览器验收通过；正式工作台未切换数据、未写人工真值

## 1. 本轮目标

本轮继续验证工作台是否能稳定展示最新数据，而不是只依赖静态代码检查。验收范围包括：

1. 新实采数据身份和四相机信息是否清楚；
2. 从“人工标注/真值”返回“自动标注/候选”时，处理帧数输入是否可以直接使用；
3. 八个推理类别是否全部显示，并逐类区分“已生成”和“尚未评估”；
4. 候选轮廓是否仍叠加在原图上；
5. 浏览器验收是否会误写人工真值，或被另一窗口切换数据后继续在错误数据上执行。

## 2. 正式工作台上的并发问题

第一轮在正式端口执行时，验收开始于 `Capture_20261103`，但约31秒后另一个浏览器会话载入了
`CVAT_Task3_original_annotations.mcap`。页面作用域在测试过程中发生变化，旧工具只表现为等待
输入框聚焦超时，无法直接说明是界面失败还是数据被其他窗口切换。

本轮因此加强浏览器验收工具：开始时冻结数据路径、相机和载入代次，在文件管理器检查后、
人工到自动模式切换后以及最终读回前重新核对。只要任一项改变，工具立即失败并保存
`failure.json`、失败截图、初始/当前作用域、页面错误和人工真值写请求。这样不会把跨窗口切换
误报成工作台功能故障，也不会在错误数据集上继续操作。

## 3. 隔离验收环境

为不打断正式工作台的使用，在 `127.0.0.1:8893` 启动一次性隔离工作台。隔离副本加载：

- 数据：`Capture_20261103/常熟0920_四相机与点云.mcap`；
- 相机：`/capture/camera_0/image`；
- 帧数：152；
- 数据身份：`Capture_20261103 · 常熟实采 · 四相机`；
- 类别：车辆、pallet、person、floor、slope、ego、other_robot、cargo_floor；
- 人工真值帧、候选帧和Agent运行记录在初始检查中均为0。

隔离副本缺少两张内容寻址的过程预览图时，第一轮严格验收正确记录了8个HTTP 500。补入与文件名
SHA-256一致的两张只读预览资源后重新执行；这只是补全隔离快照，不修改正式状态或业务代码。
