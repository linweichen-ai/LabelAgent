# 第二百三十一轮：过期数据加载回执隔离与多窗口作用域保护

日期：2026-11-19  
状态：已部署并完成真实工作台反向验收  
工作台版本：UI 147、`app.js?v=185`、`reference-prep.js?v=166`、`review-packet.js?v=164`

## 这一轮解决了什么

上一轮已经让新数据集首次加载时原子刷新图像、类别和候选，但快速切换文件、多个浏览器窗口同时操作时仍有一个边缘竞态：较早发出的文件加载请求可能比后一次选择更晚返回。旧页面收到这个迟到回执后，会把已经切好的当前工作区重新画成旧文件的内容。

这不是模型效果问题，而是“谁的加载结果有资格改页面”的问题。如果不处理，操作者会看到文件名、相机和逐类别覆盖短暂串台，随后还可能在错误作用域上继续操作。

## 修复前的直接证据

在正式 UI 146 上，以浏览器本地合成一个迟到回执，不改服务器数据：

- 原工作区：8/8 类、44 帧有候选、当前帧 16 个候选；
- 合成旧回执：2 类、2 帧、0 个候选，文件路径后缀为 `.stale-response`；
- 旧公开加载入口没有报错，页面路径被旧回执覆盖；
- 页面随后发出旧作用域的相机、时间轴和首帧读取；
- 浏览器异常为 0，但最终页面已经不是服务器当前数据。

这证明“接口请求成功”并不等于“回执仍属于当前工作区”。

## 已实施的三层保护

### 1. 显示前先核对服务器当前作用域

文件管理器、已有标注数据入口和专项复核包不再直接应用加载回执。它们先读取服务器当前文件和相机，只有回执的 `path + topic` 与服务器完全一致时才允许改变页面。

公开的 `window.loadVideoData` 也改为安全加载器的别名，避免其他旧模块绕过门禁。

### 2. 显示后再核对一次，并可自动恢复

第一遍核对与页面完成绘制之间仍可能发生另一个窗口切换，因此绘制后再次核对。如果这段时间作用域发生变化，页面会重新读取服务器 bootstrap，恢复真正的当前文件；恢复失败时宁可清空工作区，也不保留来源不明的混合状态。

### 3. 服务端拒绝旧文件发来的紧凑相机请求

紧凑相机切换请求现在必须携带页面当前文件路径。路径与服务器当前文件不一致时直接返回 HTTP 409，并在修改相机前停止。这样即使旧页面还没刷新，也不能把新数据集的服务端相机改回旧值。

## 修复后的真实工作台验收

在已部署 UI 147 上重复完全相同的迟到回执：

- 页面先发出且只发出一次 `/api/state/summary` 核对；
- 安全加载器明确提示“数据已在另一个窗口切换，本次过期加载结果未显示”；
- 文件路径、camera 1、8/8 类、44 帧和当前帧 16 个候选全部保持原样；
- 没有旧相机、旧时间轴或旧首帧请求；
- 主图仍可见，浏览器异常为 0。

随后对正式服务发送带错误文件路径的紧凑相机请求：

- HTTP 状态为 409；
- 返回“数据文件已在另一个窗口切换，旧相机请求已拒绝”；
- 请求前后文件和相机完全一致；
- 正式 `state.json` 与 `file_sessions.json` 哈希均未变化。

因此这轮不仅防止旧结果覆盖页面，也防止旧页面借相机请求修改服务器当前数据。
