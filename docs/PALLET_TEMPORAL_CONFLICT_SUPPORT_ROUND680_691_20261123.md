# 密集栈板几何时序支持与安全门修正（Round 680–691）

日期：2026-11-23

## 通俗结论

第五批还有 8 个密集堆叠栈板没有可靠二维边界。继续增加 SAM 提示已经在上一轮得到 0/8，因此本轮不再围绕提示词调参，而是查看同一个 3D 栈板在前后帧是否持续存在、是否在两侧都能得到独立 LiDAR 回波。

固定 11 帧窗口中：

- 7/8 个失败实例在中心帧前后都能看到同一个人工 3D `obj_id`，类别和 3D 尺寸保持一致；
- 1/8（008 / obj79）在中心帧之后仍没有达到 3 个可见回波，证据不足；
- 0/8 满足“中心帧完全没有回波、前后重新显现”的严格遮挡门；
- 因此 7 个只能标记为“人工 3D 轨迹条件下的存在性支持，优先人工复核”，不能生成或放行二维掩码；obj79 保持证据不足。

这项改进不依赖托盘颜色，也没有把邻帧掩码复制到当前帧。它解决的是“人工先看哪几个”的排序问题，不是像素分割真值或端到端自动检测。

## 先修复的安全问题

复用旧时序工具前发现两处问题：

1. 旧代码把“有效帧数”同时当作已出现帧数和总帧数，导致身份持续条件天然相等；目标在清单部分帧缺失时仍可能误过门。
2. 旧报告只记录 manifest 哈希，没有绑定实际使用的标定文件，也没有在运行后回读全部输入。

现在改为：

- 用 `target_present_frames == frame_count` 显式要求目标在冻结窗口每帧都存在；
- ignore 帧可以作为上下文，但不计入可见性通过条件；
- 绑定 manifest、`lidar2camera.yaml`、对应相机标定、全部标签和全部 PCD 的 SHA-256；
- 运行结束前逐项回读，任一输入漂移即失败关闭；
- 遮挡/无遮挡分组为空时返回 `null` 并判证据不足，不再生成非标准 `NaN`；
- 图表标题使用实际 target/occluder ID，不再硬编码 obj20/obj15。

历史 obj20 的 11 帧遮挡样本复跑两次，结论保持不变：11/11 帧目标存在，中心可见回波 0，中心前 1 帧、中心后 2 帧恢复可见，无遮挡中位数 16、遮挡中位数 0，仍通过严格遮挡门。25 个实际输入全部被哈希绑定，重复运行的数值、输入哈希和图表哈希一致。

## 新增批处理流程

新增 `tools/evaluate_pallet_temporal_conflict_support.py`：

1. 只读取深度拆分报告中 `handled_candidate=false` 的实例；
2. 从同一冲突组中选择深度严格更近、对目标投影重叠最大的遮挡实例；
3. 无更近遮挡者时显式跳过，不猜测；
4. 为每个目标生成独立冻结 manifest；
5. 调用加固后的时序评估；
6. 输出三种安全状态：
   - `occlusion_support`：只允许当前二维候选延期并送人工；
   - `label_conditioned_presence_support_only`：只增加人工复核优先级；
   - `insufficient`：保持失败，不补边界。

总报告明确记录 `conditioned_on_human_3d_labels=true` 和 `not_end_to_end_detection=true`。所有状态都保持 `human_pixel_truth=false`、`approved_for_training=false`、`production_deployed=false`。
