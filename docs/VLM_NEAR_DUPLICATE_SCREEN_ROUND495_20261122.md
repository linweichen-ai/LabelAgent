# Round495：VLM 后训练跨集合近重复图像筛查

日期：2026-11-22

## 为什么做

Round494 已经确认 train、dev、test24 之间没有相同 sample ID、相同图像 SHA、相同来源帧或
相同采集序列，但当时没有读取像素，因此不能排除“文件不同、画面非常相似”的情况。本轮只在
数据所在的 factory-4090 上读取冻结样本的图像字节，补做跨集合感知近重复筛查。

## 只读边界

- 输入仍为 Round494 冻结的 62 train、8 dev、24 test24，共 94 张图；
- 远端路径必须位于固定数据根目录下，并逐张核对清单中的 SHA-256；
- 远端只读取，不生成文件、不改 OSS、不改本地数据集；
- 图像像素不下载到本机，只返回有限的哈希和距离统计；
- 不写人工真值、不批准训练、不改变生产权重或线上工作台。

## 方法

每张图在远端计算三种互补的低成本特征：

1. 64 位 pHash，用于比较整体视觉结构；
2. 64 位 dHash，用于比较相邻亮度变化和边缘结构；
3. 32×32 灰度缩略图平均绝对差（MAD），用于补充亮度与布局差异。

仅比较不同 split 的图像对。候选近重复必须同时满足：pHash 汉明距离不大于 6、dHash 汉明
距离不大于 6、缩略图 MAD 不大于 0.08。该规则偏保守，用于发现值得人工复核的可疑对，而非
证明场景在语义上完全独立。

## 结果

- 成功读取并校验 94/94 张图；
- 完成 2,176 个跨 split 图像对比较；
- 阈值命中 0 对，状态为 `passed_heuristic_screen`；
- 最近的一对是 train 的 `005_1789899371082473367_camera_3` 与 test24 的
  `010_1789899969582349655_camera_3`：pHash 距离 8、dHash 距离 11、MAD 0.057590，
  因两个哈希距离均未达到门槛，不判为近重复。

## 过程中发现并修复的问题

首次本地调用暴露了脚本不能依赖项目包导入，改为独立 JSONL 读取；第二次暴露了 SSH 内嵌代码
引号兼容问题，改为 Base64 安全传输；第三次暴露远端旧版 Pillow 没有
`Image.Resampling`，增加兼容路径。三个问题都发生在正式结果生成前，没有远端写入，也没有
绕过图像哈希校验。

## 边界与决策

本轮结果支持“当前冻结 split 未发现明显像素近重复”，但不等于证明语义独立：相同路线、相似
背景、相同物体或时间邻近画面仍可能不触发该阈值，也没有做人工场景身份复核。因此可以把
Round494 的“近重复未验证”提升为“自动启发式筛查通过”，但仍不能把 dev8 或 test24 的结果
夸大为真实泛化，更不能自动部署候选模型。

下一步优先扩大独立人工真值集和新场景集；任何后训练候选仍必须保持 train-only 学习、dev-only
选择、test24 只做最终评测且禁止回流。
