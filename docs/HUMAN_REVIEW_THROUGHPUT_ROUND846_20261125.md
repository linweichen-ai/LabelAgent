# Round 846：专项人工复核连续操作与文件代次绑定修复

## 本轮目标

当前混合困难集尚未获得足够的人工裁决，后训练和三方案真实 F1 对比仍被人工门禁阻塞。本轮不代替人工判断、不写入训练集，而是缩短专项复核每帧的重复操作，并确认队列能够在当前安全协议下真正打开原图。

## 实际发现的问题

真实 Edge 隔离验收首先复现了两个现行故障：

1. 专项复核脚本会在主工作区恢复完成前读取队列。此时文件载入代次仍可能为 0，随后读取复核状态会得到 409；页面却已经缓存了目录，用户再次打开时不一定重新初始化。
2. 打开专项帧时，`/api/human_review_binding` 请求只提交了帧号和 topic，没有提交后端已经强制要求的 `file_activation_generation`。因此当前后端会拒绝请求，专项队列无法可靠进入目标帧。

这两个问题均由真实浏览器流程发现，不是模型效果或静态测试推断。

## 完成的改动

- 专项复核目录等待 `labelAgentWorkspaceReady` 后再初始化，避免工作区恢复与复核目录竞争。
- 打开帧时提交并回读核对当前文件载入代次，同时继续校验 MCAP、topic、帧号和原图 SHA-256。
- 复核工作台快照加入文件载入代次，便于浏览器验收和后续作用域核验。
- 原来的单一“签署专项判断”拆成：
  - `仅签署`：保存当前显式人工决定但停留当前帧；
  - `签署并下一帧`：只有服务端成功写入并完成读回后，才进入下一未完成帧。
- 新增快捷操作：`Alt+1/2/3/4` 只选择判断但不签署，`Ctrl+Enter` 显式签署并进入下一帧，`Alt+←/→` 切换待处理帧。
- 助手建议仍不预选、不自动签署；机器候选继续保持 `human_truth=false`、`approved_for_training=false`。

## 边界与下一步

本轮提高的是人工复核可用性和吞吐，不是分割精度；没有启动训练、推理或外部 API 调用，也没有新增人工真值。困难复核集仍需真实人工逐帧裁决。完成裁决后才能：

1. 冻结互斥的训练与评测清单；
2. 在同一人工真值上比较仅本地、全外部和混合三种方案；
3. 根据误检、漏检、延迟、成本和跨序列稳定性决定是否进行下一轮 VLM LoRA；
4. 只有全部部署门槛通过后再进入正式工作台。
