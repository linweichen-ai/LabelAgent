# Round842：外部专家并发防重与可配置运行保护

## 本轮发现的缺口

Round802已经具备成功结果缓存、超时、有界重试、熔断和本地回退，但只有“请求完成后的缓存”。两个完全相同的请求如果同时进入，仍可能在第一个结果尚未写入缓存时重复付费。不同困难帧也缺少一个明确的外部并发上限。

## 新增保护

1. **同请求合并**：协议、地址、模型、提示词、输出结构和所有图片哈希完全一致时，只允许一个请求拥有网络调用；同期请求等待后读取精确缓存。
2. **路由并发槽**：每个外部协议、地址和模型组合默认最多1个并发请求，可在1～8之间配置。
3. **有界排队**：并发槽或同请求等待默认5秒；超时后立即保留本地Qwen8B结果，不重做SAM3。
4. **无效返回防重**：外部API已经产生付费返回但JSON无效时，默认300秒内拒绝完全相同的重复请求。
5. **不改默认路由**：外部专家仍默认关闭，本轮没有将其接入正式标注结果。

## 工作台配置

外部专家设置面板现在可调整：请求超时、失败重试、熔断冷却、最大并发、并发排队上限、成功缓存和失败防重时间。后端对每个数值设置范围限制，`/api/model_readiness`只读返回当前并发、排队和失败防重配置，不返回API密钥。

## 验证结果

- 相同请求两个线程同时进入，实际网络调用为1次，等待方命中缓存；
- 不同请求在并发上限为1时，第二个请求超过排队上限后回退本地，`sam_result_reused=true`；
- 已付费但返回非JSON后，第二次相同请求未发生网络调用；
- 外部专家专项测试21/21通过，相关Python测试341项及87个子测试通过；
- 完整Python回归2,055项通过、1项跳过、294个子测试通过；
- 全部网页逻辑测试187/187通过。首次运行误用系统Python，因缺少Pillow导致1项环境失败；切换到项目虚拟环境后全部通过，该失败与本轮逻辑无关，但已保留记录。
